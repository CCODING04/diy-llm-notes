## 核心内容

### 1. 为什么需要 RLHF？从 SFT 到对齐

#### 1.1 SFT 的边界

SFT 教会了模型"问答格式"，但格式 ≠ 质量。SFT 后的模型仍然存在以下问题：

- **不知道何时闭嘴**：面对有害请求（"教我做炸弹"），SFT 模型可能照样回答——它只学会了格式，没学会判断"该不该回答"
- **偏好长而啰嗦的回答**：SFT 数据中的"好答案"往往是详细的，但模型学到了"长 = 好"，输出变得冗长
- **价值观未对齐**：不同文化背景下对"好回答"的定义不同，SFT 数据中的标注者偏好被模型当作"唯一的正确答案"

RLHF 的核心目标是：**让模型学会人类偏好，而不仅仅是模仿人类行为**。

```
SFT 做的事：     "看到这个格式 → 输出这种风格的回答"
RLHF 做的事：     "理解这个回答为什么好 → 朝这个方向优化"
```

> 🌐 **补充（Web Search / InstructGPT 论文 NeurIPS 2022）**：InstructGPT（1.3B 参数）在人类评估中，其输出被偏好于 175B GPT-3 的输出——尽管参数量少了 100 倍。这首次证明了"对齐"可以效果压倒"规模"。

### 2. RLHF 三阶段流程总览

```
预训练模型 π_PT
    │
    ▼
阶段 1: SFT          → 高质量对话数据 → 得到 π_SFT（会问答，但未对齐偏好）
    │
    ▼
阶段 2: 奖励模型训练  → 人类偏好对数据 → 得到 RM（学会给回答打分）
    │
    ▼
阶段 3: PPO 微调     → RM 打分 + KL 约束 → 得到 π_RLHF（对齐后模型）
```

### 3. 阶段 2 详解：奖励模型训练（Reward Modeling）

#### 3.1 为什么要训练奖励模型？

对齐问题的核心困难在于：**"好回答"没有数学公式可以精确描述**。我们不能写一个函数 `goodness(response)` 来计算分数。奖励模型（RM）的本质是用人类偏好数据训练一个**可微分的"好回答"近似器**。

#### 3.2 数据：偏好对（Preference Pairs）

奖励模型的训练数据不是"问题 + 标准答案"（那是 SFT 数据），而是"一个问题 + 两个回答 + 人类偏好"：

```
Prompt: "请解释什么是黑洞"
  Response A: "黑洞是时空中引力极强的区域，连光都无法逃脱..."
  Response B: "黑洞就是个宇宙吸尘器，啥都吸进去..."
  Human preference: A > B（A 更受偏好）
```

每个偏好对的数据成本远低于 SFT——标注者只需要**比较**两个回答，而不需要**撰写**一个高质量回答。这正是 RLHF 的核心动机之一：**评价比生成便宜**。

> 🌐 **交叉验证（InstructGPT 论文 / NeurIPS 2022）**：InstructGPT 雇佣了约 40 名标注者（通过 Upwork 和 ScaleAI），标注者间一致性达 72.6 ± 1.5%（训练标注者间）和 77.3 ± 1.3%（与保留标注者间）。数据规模：SFT ~13k 条、RM ~33k 条（每条含 4-9 个排序输出）、PPO ~31k 条。

#### 3.3 Bradley-Terry 模型：把偏好转化为概率

如何从"人更喜欢 A"这个定性判断，得到一个可优化的损失函数？答案是 Bradley-Terry 模型。

核心假设：存在一个隐式的奖励函数 r(x,y)，使得人类更喜欢 y_w 而非 y_l 的概率为：

$$
P(y_w \succ y_l \mid x) = \frac{\exp(r(x, y_w))}{\exp(r(x, y_w)) + \exp(r(x, y_l))} = \sigma(r(x, y_w) - r(x, y_l))
$$

其中 σ 是 sigmoid 函数。直观理解：**两个回答的奖励差越大，人类偏好 A 的概率就越接近 1**。

#### 3.4 奖励模型的架构与训练

**架构**：复用 SFT 后的模型，将最后的语言建模头（lm_head）替换为一个线性回归头（输出标量分数）。这是关键设计——底座复用让 RM 继承了语言理解能力，不需要从头学习什么是"好回答"。

```
π_SFT 的 backbone（冻结或微调）
       │
       ▼
   最后一层 hidden state
       │
       ▼
   线性层（d_model → 1）→ 标量奖励 r(x,y)
```

**损失函数**（负对数似然）：

$$
\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma(r(x, y_w) - r(x, y_l))\right]
$$

**数值推演**：假设一个偏好对——r(x, y_w) = 2.3，r(x, y_l) = 1.1
- 奖励差 = 2.3 - 1.1 = 1.2
- σ(1.2) = 1/(1 + e^{-1.2}) ≈ 0.769
- Loss = -log(0.769) ≈ 0.263

如果模型判断错误（r(x, y_w) < r(x, y_l)），比如奖励差 = -0.5：
- σ(-0.5) = 1/(1 + e^{0.5}) ≈ 0.378
- Loss = -log(0.378) ≈ 0.973 —— 惩罚大幅增加

### 4. 人类标注的挑战

#### 4.1 标注者人口偏差

> 🌐 **交叉验证（InstructGPT 附录 B.3 / 19 名受访者自愿匿名调查）**：标注者国籍分布为 Filipino 22%、Bangladeshi 22%、American 17%、Albanian 5%、Brazilian 5%、Canadian 5%、Colombian 5%、Indian 5%、Uruguayan 5%、Zimbabwean 5%。东南亚背景合计约 44%，美国/加拿大合计约 22%。

课程原文中提到"标注人员主要是菲律宾、孟加拉国和 17% 的美国人"——这里"主要由"的描述，经原始论文交叉验证，实际 Filipino 和 Bangladeshi 各 22%（共 44%），他们是最多的两个群体，但并非构成绝对主体。更精确的表述是：**标注团队由来自多国的小团队组成，东南亚和美国背景占比较高，但远非"代表全球用户"**。

这个偏差有实际后果——InstructGPT 模型被发现比 GPT-3 更契合东南亚宗教观念，因为标注者的文化背景影响了他们对"好回答"的判断。

#### 4.2 长度偏差

人类和 AI 标注都倾向给更长的回答打更高分。这让模型学会了一个捷径：**写长 = 高分**，而非真正提升质量。

RLHF 中的 KL 惩罚（后面模块会详述）部分缓解了这个问题——防止策略模型偏离原始 SFT 模型太远去追逐"高分长文"。

#### 4.3 过度优化（Overoptimization）

```
奖励模型分数
    │     ╭─ 实际人类偏好开始下降
    │    ╱
    │   ╱
    │  ╱  ← 但 RM 分数还在涨
    │ ╱
    └────────────────→ 训练步数
```

这揭示了 RLHF 最根本的困境：**奖励模型只是人类偏好的近似，过度优化这个近似会偏离真正的偏好**。就像学生过度刷某一套模拟题，分数越来越高但真考反而变差——"刷分" ≠ "会了"。

> 🌐 **补充（Web Search / Tulu 3 研究 2025）**：在不同研究中，PPO 和 DPO 的相对优势结论截然相反。AI2 团队早期发现 PPO > DPO，但在后续 Tulu 3 研究中发现：如果 SFT 阶段做得更好，PPO 和 DPO 的差距会消失，只有特定变体的 DPO 保持优势。这提醒我们——对齐方法的优劣高度依赖实验环境，不要将任何单篇论文的结论视为金科玉律。

**成本维度**：

RLHF 的 PPO 训练阶段需要**持续、高频**地获得奖励信号——每个 batch 的每一条生成回复都需要一个分数。如果每次打分都需要真人实时介入：

**Q2 批改**：自动驾驶的例子抓住了核心要点——多维度权衡无法压缩为单一标量。这个例子具体且有说服力：安全性、舒适性、时效性三者之间天然存在 trade-off（开快可能急刹，开慢可能迟到），一个标量分数必然掩盖这些张力。

可以进一步强化的角度：回到 LLM 场景本身——对于同一个 prompt，人类可能同时偏好"A 的回答更准确"和"B 的回答更有创意"，这两个维度不可通约。Bradley-Terry 强制给 A 和 B 一个总排序，但实际上人类内心可能是"准确度上 A > B，创意度上 B > A，不同场景要不同答案"。Bradley-Terry 把多维偏好暴力投影到了单一维度，这对"有帮助性/无害性"等本身就存在冲突的维度来说，是一个固有局限。— 得分：**8/10**

<details>
<summary>📖 Q2 参考答案</summary>

Bradley-Terry 假设的不成立场景可以归为两类：

**场景 1：多维偏好不可通约**

对于一个回答，人类可能同时关心：
- 准确性（是否说对了事实）
- 简洁性（是否啰嗦）
- 安全性（是否拒绝有害内容）
- 创意性（是否有洞察）

这些维度之间存在**固有冲突**。例如：
- Prompt："如何致富？"
  - 回答 A："努力工作、投资理财、控制开支"（准确、简洁、但缺乏创意）
  - 回答 B："《富爸爸穷爸爸》的核心观点是..."（引用了一本有争议的书，创意但可能不够准确）

不同用户对这两个回答的偏好排序可能完全相反，且不是"奖励差"能调节的——因为**不同用户对"好"的定义本身就不一样**。

**场景 2：循环偏好（非传递性）**

Bradley-Terry 隐含假设偏好是可传递的：如果 A > B 且 B > C，则 A > C。但实际偏好可能是：

- 回答 A 更准确但更啰嗦
- 回答 B 长度适中但有一些小错
- 回答 C 很简短且完全正确但不够友好

人类可能的循环偏好：A > B（准确性优先），B > C（长度优于简短），C > A（友好度优于啰嗦）——形成循环。Bradley-Terry 无法建模这种情况。

**深层含义**：Bradley-Terry 的"单一标量奖励"假设本质上是把对齐简化为"存在一个正确的人类偏好排序"，但实际上人类偏好是**多元、情境依赖、有时内在矛盾**的。

</details>

**Q3 批改**：你的"两条途径"框架很好——分别从"人"和"数据"两个角度切入，思路清晰。

策略 1（各地区标注者占比均衡）是一个直接有效的方法，但有一个隐藏难点：**人口占比均衡 ≠ 偏好影响力均衡**。假设你给东南亚、欧洲、非洲各 1/3 的标注配额，但全球用户 60% 在亚洲——那么"等比例标注"反而会让模型偏向欧美/非洲用户的偏好，对亚洲用户来说反而"没对齐"。因此需要进一步区分：是按"全球用户分布"配比还是按"等权代表"配比——这两种策略对最终结果的影响完全不同。

可以补充的一条具体策略：**标注后分层校准**——不要求标注者本身"无偏差"，而是在标注完成后，按标注者的人口属性（国籍、语言、年龄）对偏好数据进行**分层分析**，识别并修正系统性偏差（如某国标注者系统性地给短回答打低分），然后再训练 RM。— 得分：**7/10**

<summary>📖 Q3 参考答案</summary>

**策略 1：地理/文化配额采样 + 人口加权**

不追求"等比例"，而是按照**目标用户地理分布**配比标注者（如亚洲 60%、欧洲 15%、非洲 10% 等）。同时，对偏好数据进行人口加权——少数但关键的文化群体的偏好数据可以被上采样，防止被主流群体"淹没"。

**策略 2：分层标注 + 偏差检测**

每个 prompt 由来自**至少 3 个不同文化区域**的标注者独立标注。如果标注者间的偏好分歧超过阈值（如某题上东南亚标注者一致偏好 A，而欧洲标注者一致偏好 B），标记为"文化敏感题"。对于这类题，不做全局偏好排序（禁止 Bradley-Terry 把一种文化偏好当成"正确答案"），而是保留**多文化版本的 RM**——不同地区直接使用不同的奖励模型。

**策略 3：人工标注 + AI 校准两阶段**

第一阶段：由跨文化标注团队产出偏好数据。第二阶段：用 LLM 对每条偏好进行**文化偏差元标注**——例如"这个比较中，A 被偏好是否依赖于'尊称长辈'的东南亚文化假设？"——标记出文化依赖的偏好对，将其从全局 RM 训练集中移除或放入特定文化子集。

**策略 4：用户可选择的多样性**

接受"统一 RM 无法完美对齐所有人"这一现实。技术上提供**用户级适应性**：允许用户标记自己的偏好（如"我更看重准确性 vs 简洁性"），系统层面用 LoRA 或 prompt 工程做轻量个性化对齐，而非依赖一个全局 RM。

</details>

**综合评价**：三个回答的框架感很强——Q1 区分成本/效率、Q3 区分"人/数据"两个途径——这种"先搭框架再展开"的答题方式值得保持。Q2 的自动驾驶跨领域举例很有创造力。需要注意的是：Q1 遗漏了"RM 提供可微分梯度"这个关键的技术维度——成本和效率之外，**梯度**是 RL 能运作的数学前提。Q3 的"均衡标注者占比"策略需要在"等比例 vs 人口加权"上做更细致的权衡分析。
