## 核心内容

### 1. 机器学习的四种学习范式

在进入大模型训练流程之前，需要先理清四种基础学习范式的本质差异——它们的区别不在于"用什么模型"，而在于**数据长什么样**和**优化信号从哪来**。

```
监督学习：     输入 x → 输出 y（有标准答案）
无监督学习：   输入 x → ??? （没有答案，自己找结构）
自监督学习：   输入 x → 从 x 自己生成伪标签（无监督的子集）
强化学习：     输入 状态 s → 输出 动作 a → 环境给奖励 r（延迟、稀疏的信号）
```

#### 1.1 监督学习（Supervised Learning）

**是什么**：给定输入-输出配对 $(x_i, y_i)$，学习映射 $f: x \mapsto y$。

**核心特征**：
- **有"标准答案"**：每个样本的输出 $y$ 由人工或可靠系统标注
- **损失可计算**：预测值 $\hat{y}$ 与真值 $y$ 的误差（交叉熵、MSE）作为直接优化信号
- **目标明确**：最小化训练集预测误差 + 防止过拟合

**直觉**："老师把答案写在卷子上"，模型通过对比自己的答案和标准答案不断纠正错误。

**典型任务**：图像分类（猫/狗/车）、房价预测（连续值回归）。

#### 1.2 无监督学习（Unsupervised Learning）

**是什么**：只给输入 $x$，不给输出 $y$，让模型自己找规律、找相似、找低维表示。

**核心特征**：
- **没有标签**，目标是从数据本身挖掘隐藏结构
- 常见任务：聚类（Clustering）、降维、密度估计

**直觉**："不给答案、只给卷子"，让机器自己把题目分堆、找规律。

**与监督学习的关键对比**：

| | 监督学习 | 无监督学习 |
|---|---|---|
| 输入 | $(x_i, y_i)$ | 只有 $x_i$ |
| 优化信号 | 预测值 vs 真实标签的误差 | 数据内部结构（簇内距离、重构误差等） |
| 成本 | 需昂贵人工标注 | 数据拿来就能用 |

**自监督学习（Self-supervised Learning）** 是无监督学习的一个子集——它从原始数据中**自动生成伪标签**，然后按有监督方式训练。例如：
- LLM 预训练：用"上文"预测"下一个词"（标签来自文本自身）
- BERT 的 Masked Language Modeling：随机遮盖部分词，让模型预测被遮盖的词
- 对比学习（Contrastive Learning）：同一图片的不同裁剪是"正样本对"

> 💡 **补充（Web Search / ICML 2025）**：ICML 2025 上有工作从 Rademacher 复杂度的角度，定量分析了 next-token prediction 预训练的泛化能力——泛化误差受 token 序列数 $N$、序列最大长度 $m$ 和 Transformer 参数量 $\Theta$ 三个因素共同控制。这意味着**增加序列长度和序列数量都能提升泛化**，为"更大数据 + 更长上下文"的实践方向提供了理论支撑。

#### 1.3 强化学习（Reinforcement Learning）

**是什么**：智能体在环境中通过**试错**学习——执行动作 → 观察新状态 → 获得奖励 → 调整策略。

**核心特征**：
- **延迟奖励**：不是每一步都有反馈，可能只在最终才有奖励（赢了/输了）
- **稀疏信号**：奖励信号远比监督学习的逐样本 loss 稀疏
- **序列决策**：当前动作影响未来状态和未来奖励

**直觉**："老师只期末给总评，学生全程自己摸索哪一步对哪一步错。"

与监督学习的本质区别：监督学习是"告诉你每道题的正确答案"；强化学习是"只告诉你最后考了多少分，你自己琢磨哪些步骤导致了加分/扣分"。

> 强化学习将在第 14 章详细介绍。本章第 4-5 模块重点讲解 RL 在 LLM 对齐中的应用（RLHF/PPO/DPO）。

### 2. 大模型预训练（Pre-training）

#### 2.1 预训练范式的起源

预训练的概念最早在计算机视觉领域产生实质影响——在 ImageNet 上预训练的模型，只需少量标注数据微调就能在下游任务上表现优异。

**GPT-1（2018）** 首次将"无监督预训练 → 有监督微调"路线系统化应用于 NLP：
- 先在 5GB 的 BooksCorpus 上做大规模无监督预训练（自回归语言模型目标）
- 再在少量标注数据上微调具体任务
- 显著超越当时只能从头训练的模型

**核心价值**：预训练让模型在海量无标注数据上"自学"通用知识，得到一个强大的底座，然后用少量标注数据微调解决具体任务——这是**迁移学习的极端放大版**。

#### 2.2 Next-Token Prediction：预训练的唯一目标

大模型（decoder-only 架构）的预训练范式极其简洁：**不断预测下一个词**。

对于输入序列 $[x_1, x_2, \dots, x_{t-1}]$，目标（标签）是序列中的下一个词 $x_t$。模型学习的是条件概率分布：

$$P(x_t \mid x_1, x_2, \dots, x_{t-1})$$

**具体构造示例**："自然语言处理是人工智能的一个重要分支"

| 输入序列 | 预测标签 |
|---------|---------|
| `["自然", "语言", "处理"]` | `"是"` |
| `["语言", "处理", "是"]` | `"人工智能"` |
| `["处理", "是", "人工智能"]` | `"的一个"` |
| `["是", "人工智能", "的一个"]` | `"重要分支"` |

每个位置的 loss 是交叉熵 $-\log P(x_t \mid x_{<t})$，整个序列的 loss 是所有位置的平均值。

**关键理解**：预训练完成后，模型是一个**续写模型**——你给一段文本，它续写下去。它还没有"问答"能力，没有"遵循指令"的概念，有的只是"给定上文，预测下文最可能是什么"。

#### 2.3 预训练数据规模

| 模型规模 | 典型训练数据量 | 示例 |
|---------|--------------|------|
| ~8B 参数 | ~36T tokens | Qwen3-8B |
| 更大模型 | 50-200T tokens | 前沿模型 |

数据来源：公开网页抓取、书籍、论文、代码、多语种语料，经过去重和数据清洗后用于训练。

> 🌐 **补充（Web Search / LinkedIn 2025）**：Microsoft 在 2025 年 6 月提出了 **Reinforcement Pre-Training（RPT）**，将预训练从纯粹的 next-token prediction 扩展为"激励模型的 next-token 推理能力"。RPT 通过强化学习信号提升模型在关键 token 位置（如推理步骤的核心转折点）的预测质量，而非对所有 token 一视同仁。这代表预训练范式本身也在进化——从"预测所有 token"到"重点预测关键 token"。

预训练完成后，模型蕴含了海量先验知识，但它**不能很好地遵循指令**。要实现产品化，需要后续的 SFT 和 RLHF 阶段——这是接下来模块 2-5 的内容。

### 3. GPT-3：大模型时代的里程碑

#### 3.1 为什么 GPT-3 是里程碑

GPT-3（OpenAI，2020 年 7 月）用 **1750 亿参数 + 自回归语言模型 + 纯提示（prompt）** 第一次证明：

> **"只要够大，模型就能在没有任何梯度更新的情况下，看懂任务并给出像模像样的答案。"**

核心数据：
- 参数量：175B（GPT-2 的 1.5B → **参数 ×100**）
- 训练数据：约 570GB 文本
- 训练目标：只有"给定上文，预测下一个 token"

| 任务 | 指标 | GPT-3 成绩 |
|------|------|-----------|
| 英文阅读理解（RACE） | 准确率 | 86.8%，超越人类平均 73% |
| 翻译（WMT'14 法→英） | BLEU | 43.9，接近当时最佳有监督系统 |
| 数学加法（2-5 位数） | 准确率 | 随示例数从 0% 提升到 80% |
| 代码补全（HumanEval） | 通过率 | 37%（Codex 微调后→72%） |

#### 3.2 In-Context Learning（上下文学习）的涌现

GPT-3 最惊人的发现是 **In-Context Learning（ICL）**——在 prompt 中给出几个示例（few-shot），模型就能"看懂"任务格式并在新输入上执行，**无需任何参数更新**。

使用 GPT-3 的方式：
```
Translate English to French:
sea otter → loutre de mer
cheese → fromage
bread →
```

模型本质上是"续写"，但因为训练数据中包含了大量翻译、问答等格式的文本，它学会了"看到这种格式就切到对应模式"。

#### 3.3 GPT-3 的局限

- **幻觉严重**：会一本正经地编造新闻、假引用
- **偏见大**：性别、种族、宗教刻板印象随提示直接输出
- **不能遵循指令**：需要把任务包装成"续写"格式才能使用
- **缺乏产品化价值**：能跑通 demo，但无法作为可靠产品部署

从 GPT-3 到 ChatGPT 之间的关键一步就是 **SFT + RLHF**——这正是本章后续模块的核心内容。

> 🌐 **补充（Web Search / EMNLP 2024）**：一篇 EMNLP 2024 的综述对 ICL 的解释和分析做了全面梳理，从**机制可解释性**（Transformer 的注意力头如何实现 ICL）和**实证分析**（哪些因素影响 ICL 效果）两个角度总结了进展。核心发现之一是：ICL 可以理解为 Transformer 在注意力层中隐性执行**梯度下降**——few-shot 示例相当于在激活空间中产生了一个临时的"任务向量"。

### 📝 批改结果

**Q1 批改**：核心直觉正确——用文本自身的下一个词作为预测目标，无需人工标注。"伪标签"和"来源"的定位准确：标签 = 下一个 token，来源 = 已有的前文。

你说的"遮挡右边所有词，从左往右做 mask"其实就是**因果掩码（causal masking）**——这是 decoder-only LLM 的标准训练机制。每个位置通过注意力掩码屏蔽未来 token，只能看到左边的前缀，然后用前缀预测下一个词。这和 BERT 的 `[MASK]` token 替换是两种不同的掩码策略——你描述的是前者（因果掩码），描述是准确的。

一个小补充：因果掩码发生在**注意力计算**层面（通过给未来位置的 attention score 加上 -∞ 来实现），而非在输入文本层面把 token 替换掉。可以说"注意力只允许看到左边"，但输入文本本身没有被修改——每个位置的输入仍是原来的 token。— 得分：**8/10**

<summary>📖 Q1 参考答案</summary>

**"假装有监督"的体现**：

LLM 预训练中，原始数据只是一串文本 "自然语言处理是人工智能的一个重要分支"，没有任何人工标注。但我们通过**滑动窗口**自动构造出监督学习的格式：

| 输入（x） | 标签（y） |
|-----------|----------|
| `["自然", "语言", "处理"]` | `"是"` |
| `["语言", "处理", "是"]` | `"人工智能"` |
| ... | ... |

每一对 (输入, 标签) 都构成了一个"有监督"的训练样本——输入是前缀，标签是下一个词。

**伪标签**：下一个 token（`"是"`, `"人工智能"`, ...）

**来源**：原始文本自身——文本中的每个 token 都同时扮演了两个角色：① 作为前一个位置的"标签"；② 作为后一个位置的"输入"的一部分。

**关键洞察**：整个预训练过程不需要任何人来标注"这句话的下一个词应该是什么"——因为文本自己就是答案。这就是"自监督"的本质：**数据自己提供了监督信号**。

**与 BERT MLM 的区别**：BERT 是随机遮盖部分词（`[MASK]`），让模型从左右两侧上下文预测被遮盖的词——这是"完形填空"。GPT 是单向的自回归——这是"续写"。两种都是自监督学习，但掩码策略不同。

**Q2 批改**：两个核心要素都踩到了——① 足够的数据（见过大量"任务格式"的文本模式）；② 足够的模型容量（小模型容纳不下这种范式）。Chinchilla 理论（20× 数据/参数比）的引入是将本章与第 9 章 Scaling Laws 串联的好做法。

两个可深化的方向：

① **"什么样的数据"才算是任务格式**——不只是显式的 few-shot 模板，更关键的是互联网上天然存在的大量"隐式 ICL 模式"：论坛 Q&A 帖（问题→多个回答→最佳答案）、代码文档（函数签名→示例调用→输出）、学术论文（摘要→正文→结论）。模型在预训练中反复见到"输入→输出→输入→输出"的交替模式，注意力头进化出了**复制和模式匹配**的能力。

② **涌现的机制层面**——ICL 可以被理解为**注意力层中隐式执行的梯度下降**。Akyurek et al. (2023) 的数学分析表明，Transformer 的线性注意力可以精确实现梯度下降的一步更新；few-shot 示例在模型的激活空间中形成了一个临时的"任务向量"，引导后续 token 的生成方向。小模型没有形成足够灵活的"induction heads"（归纳头）——这些注意力头专门负责"从上下文中提取模式并复制"。— 得分：**6/10**

<details>
<summary>📖 Q2 参考答案</summary>

**预训练数据中包含了什么？**

互联网文本天然富含"输入-输出"交替模式：
- 论坛 Q&A：用户提问 → 多个回答 → 楼主标记最佳答案
- 代码文档：函数签名 → 参数说明 → 示例输入 → 输出
- 学术论文：研究问题 → 方法 → 实验结果 → 结论
- 百科词条：标题 → 定义 → 分类 → 属性列表
- 翻译网站：源语言句子 → 目标语言句子 → 再一组源语言 → 目标语言

模型在预训练中反复见到这些"前半段给格式，后半段遵循格式"的文本模式，注意力机制学会了"看到类似模式就按已有格式续写"。

**为什么在足够大的模型上才涌现？**

1. **容量门槛**：ICL 需要注意力头形成"induction heads"——能识别上下文中的重复模式并复制。这需要足够的参数量来编码"模式检测 + 模式执行"的运算逻辑。小模型参数量有限，优先学到的是 trigram/ngram 级别的统计搭配，而非抽象的"任务格式"概念。

2. **涌现的临界点**：像 GPT-3 从 1.5B 跳到 175B（×100），跨过了某个临界容量——在这个容量之上，模型不再只是"记住常见搭配"，而是能抽象出"这个 prompt 模板想让我遵循什么规则"的元能力。

3. **机制可解释性视角**（Akyürek et al. 2023, ICL as Implicit Fine-Tuning）：线性注意力可以精确等价于梯度下降的一步更新。Few-shot 示例在模型的激活空间中产生了一个"任务向量"——后续 token 的生成被这个向量引导。小模型的激活空间维度不足以干净地分离不同任务的向量表示，导致 ICL 效果不明显。

**直觉**：小模型像是只背过 100 篇课文的考生——遇到新题型就懵了。大模型像是读过整个图书馆的人——即使没见过原题，也能从类似的格式中"猜到"你想要什么。

</details>

**Q3 批改**：三个行为描述精准——"答非所问""语句连贯但不合理""价值观错误"，分别对应了预训练模型的三种经典失败模式（格式不匹配、事实幻觉、缺少安全对齐）。最后一句"卓越而不实用"精准概括了 GPT-3 到 ChatGPT 之间的关键鸿沟——预训练模型有强大的语言建模能力，但缺乏"意图理解"和"安全边界"。

可强化的点：给一个具体到 token 级别的例子会让分析更有穿透力。例如：

```
用户输入：法国的首都是哪里？
预训练模型输出：法国的首都是哪里？法国的首都是巴黎，法国的首都是巴黎，法国的首都...
（模型看到"哪里？"后面在训练数据中常接陈述句，于是续写了答案——这算运气好）
预训练模型也可能输出：法国的首都是哪里？德国、意大利、西班牙...欧洲的许多国家都有...
（模型把"哪里"理解为"列举"的触发器，开始联想式续写而非精准回答）
```

这就展示了续写模型的核心问题：它只是概率性地续写，而不是理解用户意图后精确响应。— 得分：**7/10**

<summary>📖 Q3 参考答案</summary>

**具体例子**：

```
用户：什么是光合作用？

预训练模型可能的输出（之一）：
"什么是光合作用？光合作用是植物利用光能将二氧化碳和水转化为有机物和氧气的过程。光合作用是地球上最重要的生化反应之一。什么是呼吸作用？呼吸作用是..."
```

**行为分析**：

预训练模型把 "什么是光合作用？" 当作一个文本前缀，然后：
1. 续写了定义（恰好正确——因为训练数据中大量出现这种定义格式）
2. 然后"惯性"地继续问"什么是呼吸作用？"——因为在预训练数据中，类似的定义经常成群出现（百科词条、教科书段落）

**三种典型的失败模式**：

| 失败模式 | 原因 | 示例 |
|---------|------|------|
| **格式不匹配** | 用户输入是"问句"，模型把它当"段落的开头"续写 | 用户："给我写一首诗" 模型："给我写一首诗，然后分析它的韵律和意象，最后给出评分..."（它续写了要求，而非执行指令） |
| **幻觉编造** | 模型被训练为"总要有输出"，遇到不确定时依然生成看似合理的 token | "光合作用的发现者是牛顿"——因为"发现者是"后面最常接人名，模型挑了一个熟悉的 |
| **价值观失控** | 预训练数据包含了互联网上的有害内容，模型学会了生成它们 | 用户问"如何制作炸弹"，模型可能直接续写制作步骤 |

**为什么说"卓越而不实用"**：

- **卓越**：175B 参数的模型能从文本中学到翻译、数学、代码等多领域知识，仅靠 prompt 就能产生可用的输出——这在 2020 年是革命性的
- **不实用**：模型无法区分"用户想让我回答问题"和"用户想让我续写一段文字"，缺乏根本的意图理解。SFT 的作用正是教会模型"问答格式"——用 Alpaca/ChatML 格式的数据告诉模型"看到这种 pattern，你应该直接回答，而非续写"
