## 核心内容

### 1. PPO 要解决什么问题？

#### 1.1 从策略梯度到 PPO

##### 什么是"策略"？

在 LLM 的上下文中，**策略 π_θ 就是模型本身**：给定当前状态 s_t（前面的 token 序列），输出下一个 token a_t 的概率分布。

```
状态 s_t = ["法国", "的首都", "是"]    ← 已经生成的文本
策略 π_θ 输出 → { "巴黎": 0.7, "伦敦": 0.05, "法国": 0.02, ... }  ← 词表上的概率分布
动作 a_t = 采样得到的下一个 token
```

##### 策略梯度的直觉

强化学习的核心问题是：**如何调整模型参数 θ，让"好动作"的概率上升、"坏动作"的概率下降？**

假设我们知道每个动作的"好坏分数"——优势值 A_t（后面会详述）。最朴素的想法是：

> 对于每个动作，用 **A_t 作为权重**来调整它的概率。A_t > 0 就提升，A_t < 0 就压低。

这恰好等价于最大化以下目标（对"好动作"来说 A_t > 0，乘积更大）：

$$
J(\theta) = \mathbb{E}\left[\log \pi_\theta(a_t \mid s_t) \cdot A_t\right]
$$

对它求梯度（即"参数往哪个方向调能让这个目标变大"），就得到了策略梯度：

$$
\hat{g} = \hat{\mathbb{E}}_t\left[\nabla_\theta \log \pi_\theta(a_t \mid s_t) \cdot \hat{A}_t\right]
$$

##### 逐符号拆解

| 符号 | 含义 | LLM 场景对应 |
|------|------|------------|
| ∇_θ | 对模型参数 θ 求梯度 | "参数应该往哪个方向调" |
| log π_θ(a_t \| s_t) | 给定状态 s_t，模型输出 a_t 的**对数概率** | 下一个 token 的 log-prob |
| Â_t | 动作 a_t 的**优势估计**（这个动作比平均水平好多少） | 这个 token 对最终回复质量的贡献 |
| 𝔼̂_t | 对时间步 t 的**经验平均**（= 从实际采样数据中估计） | 对一批 prompt 的所有 token 取平均 |

##### 为什么用 log 概率而不是直接用概率？

这是一个纯数学技巧——**log-likelihood trick**。考虑：

$$
\nabla_\theta \log \pi_\theta = \frac{\nabla_\theta \pi_\theta}{\pi_\theta}
$$

两边乘以 π_θ 得到：π_θ × ∇_θ log π_θ = ∇_θ π_θ。

所以对 log 概率求梯度，本质上就是在对概率求梯度——但 log 形式在数值上更稳定（概率相乘变成 log 相加），且自然产生了"除以当前概率"的归一化效果，防止高频动作主导梯度。

##### 数值推演

假设一个简化的 LLM 场景，词表只有 3 个 token，当前状态 s_t = "法国的首都是"：

| token a_t | π_θ(a_t \| s_t) | A_t | ∇_θ log π_θ × A_t | 效果 |
|-----------|----------------|-----|-------------------|------|
| "巴黎" | 0.7 | +1.5 | 方向：提升 "巴黎" 概率 | ✅ 正确答案，强化 |
| "伦敦" | 0.2 | -0.8 | 方向：压低 "伦敦" 概率 | ❌ 错误答案，抑制 |
| "法国" | 0.1 | -0.3 | 方向：略微压低 "法国" | ⚠️ 重复输入，轻微抑制 |

梯度更新后，模型会更倾向于输出"巴黎"、更不倾向于输出"伦敦"。

##### 那直接用这个公式更新有什么问题？

<table>
<tr><th>问题</th><th>原因</th><th>具体表现</th></tr>
<tr>
<td><strong>更新步长敏感</strong></td>
<td>π_θ 变化后 log π_θ 变化剧烈，没有机制限制单步更新幅度</td>
<td>学习率稍大 → 概率分布直接跳到一个 token 上（如 "巴黎" 从 0.7 → 0.99），策略崩塌</td>
</tr>
<tr>
<td><strong>样本效率低</strong></td>
<td>策略更新后旧数据就"过时"了，必须重新采样</td>
<td>生成一次回复 → 更新一次参数 → 丢弃旧数据 → 再生成。训练极慢</td>
</tr>
<tr>
<td><strong>策略崩塌</strong></td>
<td>一次大跳跃后策略进入"坏区域"，后续采样全是垃圾数据</td>
<td>从此再也学不回来，只能重新开始训练</td>
</tr>
</table>

PPO 的三个核心机制分别解决这三个问题：重要性采样 → 样本复用，优势函数 → 降低方差，剪切 → 限制步长。

> 🌐 **补充（PPO 原论文 Schulman et al., 2017 / arxiv 1707.06347）**：PPO 在 2017 年由 OpenAI 的 John Schulman 等人提出，是 TRPO（Trust Region Policy Optimization）的简化版。TRPO 用 KL 散度显式约束策略更新幅度，但需要计算 Hessian 矩阵——PPO 用一个简单的 clip 操作绕过了这个计算，实现更简单、效果相当甚至更好。

### 2. 核心机制一：重要性采样（Importance Sampling）

#### 2.1 问题

你想用"旧策略 π_old"采样的数据来训练"新策略 π_θ"。但旧数据反映的是旧策略的行为分布，直接拿来用会导致估计偏差。

#### 2.2 解决方案

用**概率比**来修正偏差——如果新策略做某个动作的概率是旧策略的 2 倍，那旧数据中该动作的样本就应该被"放大 2 倍"：

$$
r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}
$$

这个比率就是**重要性权重**。将它乘以优势函数，就得到了用旧数据估计新策略梯度的公式：

$$
L^{\text{PG}}(\theta) = -r_t(\theta) \cdot A_t
$$

> 💡 `PG` = **Policy Gradient**（策略梯度）。上标仅标注这是策略梯度的损失函数形式，`-` 号是因为 PyTorch 优化器默认做梯度下降（最小化），而 RL 需要最大化奖励——加负号等价于"用下降的优化器实现上升的效果"。r_t 在这里充当**音量旋钮**：旧数据中该动作的"话语权"按新旧策略的概率比来调节。

#### 2.3 数值推演

假设旧策略在"回答是否安全"这个问题上的概率分布：

| token | π_old | π_new | r_t |
|-------|-------|-------|-----|
| "抱歉，我不能" | 0.6 | 0.8 | 0.8/0.6 = 1.33 |
| "好的，步骤如下" | 0.4 | 0.2 | 0.2/0.4 = 0.50 |

- token "抱歉" 在旧数据中每个样本贡献权重 1.33（新策略更常做，所以旧样本"被低估"了）
- token "好的" 贡献权重 0.50（新策略更少做，旧样本"被高估"了）

**意义**：一次采样 → 多次梯度更新使用，采样效率大幅提升。但这里有一个隐藏风险——如果 r_t 变得很大（比如 10 或 0.01），更新步长会失控。这就是下一个机制要解决的问题。

### 3. 核心机制二：优势函数（Advantage Function）

#### 3.1 问题

直接用原始奖励 R_t 做梯度估计，方差极大——同一个"好"动作可能在有的回合获得 +10 奖励，在另一个回合只有 +1（取决于后续的运气成分）。

#### 3.2 解决方案

引入**基线减法**——不关心"动作的绝对价值"，只关心"动作比平均水平好多少"：

$$
A(s,a) = Q(s,a) - V(s)
$$

- Q(s,a)：在状态 s 做动作 a 的**期望总回报**
- V(s)：在状态 s **所有动作的平均期望回报**
- A(s,a) > 0 → 这个动作比平均水平好，提升概率
- A(s,a) < 0 → 这个动作比平均水平差，压低概率

#### 3.3 GAE（Generalized Advantage Estimation）

实际计算中使用 GAE 来估计优势，它在偏差和方差之间提供了一个可调旋钮：GAE 的核心构件是 TD 误差。

**TD 误差**（**Temporal Difference Error**，时序差分误差）：

##### 核心公式

$$
\delta_t^V = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

| 符号 | 含义 |
|------|------|
| V(s_t) | 从状态 s_t 开始，**未来累计奖励的期望**（带折扣） |
| r_t | 在 s_t 执行动作后**立即获得的奖励** |
| s_{t+1} | 执行动作后进入的下一状态 |
| γ | 折扣因子（0~1），未来奖励的权重 |
| δ_t^V | **TD 误差**——当前估计与更可靠目标的差距 |

> 💡 **直觉**：你不需要等到一条完整轨迹结束才知道自己的判断对不对——只需看**下一步**就足够校准。TD 误差 = (即时奖励 + 下一步的折扣总奖励) - 当前估计的总奖励。

##### 数值推演

设定：状态 A 当前估计 V(s_t) = 10，从 A 移动到 B 获得即时奖励 r_t = 2，下一状态 B 的估计 V(s_{t+1}) = 9，γ = 0.9。

```
Target = r_t + γ · V(s_{t+1}) = 2 + 0.9 × 9 = 2 + 8.1 = 10.1
δ      = 10.1 - 10 = 0.1 (>0)
```

δ > 0 → V(s_t) = 10 偏低了，应该上调到接近 10.1。

##### 为什么 V(s_t) 可以大于 V(s_{t+1})？

因为从 A 出发**先拿到即时奖励 2**，再进入 B 拿未来累计奖励（折扣后 8.1）。A 的总价值 = 即时奖励 + 折扣后 B 的价值。

**直观类比**：从 A 出发 = 兜里已经赚了 2 块钱 + 未来还能赚 9 块（未来钱打 0.9 折）→ 相当于现在有 10.1 元。从 B 出发 = 兜里现在 0 元 + 未来 9 块（折扣后 8.1 元）→ 相当于现在有 8.1 元。**A 比 B 更值钱**（除非即时奖励为负）。

##### TD 误差的正负含义

- δ > 0 → 当前估计**偏低** → 需要增加 V(s_t)
- δ < 0 → 当前估计**偏高** → 需要减少 V(s_t)
- 注意："随着时间步往后价值递减"仅在**无即时奖励时**成立；一旦有 r_t，当前状态价值可以反弹上升

**反例**：若 r_t = -2（惩罚），V(s_{t+1}) = 9，γ = 0.9 → Target = -2 + 8.1 = 6.1，远小于 10，此时需要**降低** V(s_t)。

---

**GAE**（Generalized Advantage Estimation，广义优势估计）：

##### What：GAE 是什么？

GAE 是一种**在偏差和方差之间可调节**的优势估计方法。它不只用一步 TD 误差（太保守），也不等完整轨迹结束（太吵），而是用 λ 参数控制一个**指数衰减的加权窗口**，把近几步的 TD 误差聚合起来：

$$
A_t^{\text{GAE}} = \sum_{l=0}^\infty (\gamma\lambda)^l \delta_{t+l}^V
$$

展开来看（假设一条轨迹有 4 步）：

```
A_t = δ_t                          ← l=0, 权重 1
    + (γλ)·δ_{t+1}                 ← l=1, 权重 γλ
    + (γλ)²·δ_{t+2}               ← l=2, 权重 (γλ)²
    + (γλ)³·δ_{t+3}               ← l=3, 权重 (γλ)³
    + ...
```

越远的 TD 误差，权重呈指数衰减（乘以 (γλ)^l），影响越小。

##### Why：为什么需要 GAE？

根本矛盾是**偏差-方差权衡**（Bias-Variance Tradeoff）：

| 方法 | λ | 原理 | 偏差 | 方差 |
|------|---|------|------|------|
| **单步 TD** | λ→0 | 只用 δ_t（当前步的 TD 误差） | **高**：忽略了后续步的信息 | **低**：只看一步，不受远处噪声影响 |
| **蒙特卡洛（MC）** | λ→1 | 用整条轨迹的实际总回报 - V(s_t) | **低**：真实回报，无估计偏差 | **高**：后续所有步的随机波动全带进来了 |

单步 TD 的偏差来自哪里？因为 V(s_{t+1}) 是**估计值**而不是真实值——如果 V 网络还没有训练好，V(s_{t+1}) 本身就偏了，δ_t 自然也跟着偏。但它的方差低，因为每次只看一步。

蒙特卡洛没有这个问题——它用实际拿到的总回报（真实数字），所以无偏。但整条轨迹的每一步都有随机性（今天运气好拿高分、明天运气差拿低分），方差爆炸。

**GAE 用 λ 在两者之间插值**——λ=0 就是单步 TD，λ=1 就是 MC，中间值取两者的优点。

##### How：具体怎么算？

用一个 4 步轨迹的数值例子：

```
时间步:     t         t+1       t+2       t+3      (终点)
奖励:     r_t=0     r_{t+1}=1  r_{t+2}=0  r_{t+3}=5
V(s):    V_t=10    V_{t+1}=9   V_{t+2}=8   V_{t+3}=3   V(终点)=0
```

设 γ = 0.9，λ = 0.8。先算每步的 TD 误差：

```
δ_t     = 0 + 0.9×9 - 10  = 8.1  - 10  = -1.9
δ_{t+1} = 1 + 0.9×8 - 9   = 8.2  - 9   = -0.8
δ_{t+2} = 0 + 0.9×3 - 8   = 2.7  - 8   = -5.3
δ_{t+3} = 5 + 0.9×0 - 3   = 5    - 3   = +2.0
```

**关键**：t+2 时刻给了 r=5 的大奖励，但单步 TD 只看 t+2→t+3，只看到 δ_{t+2} = -5.3（V(s) 从 8 掉到 3，看似很糟）。**实际上 t+3 有个 +2.0 的正 TD 误差，说明 V(s) 虽然跌了，但最终拿到了大奖励**。

现在用 GAE 算 A_t（λ=0.8）：

```
A_t = δ_t                         ·1.0     = -1.90
    + δ_{t+1} × (0.9×0.8)¹        ·0.72    = -0.8 × 0.72 = -0.58
    + δ_{t+2} × (0.9×0.8)²        ·0.52    = -5.3 × 0.52 = -2.76
    + δ_{t+3} × (0.9×0.8)³        ·0.37    = +2.0 × 0.37 = +0.74
    ─────────────────────────────────────────────────────────
    A_t = -1.90 - 0.58 - 2.76 + 0.74 = -4.50
```

对比 λ→0（纯单步 TD）：A_t ≈ δ_t = **-1.90**（只看到当前步糟糕）
对比 λ=0.8（GAE）：A_t = **-4.50**（更糟！因为 t+2 那步确实很差）

**GAE 让模型"看远几步"**——λ=0.8 的 GAE 看到 t+2 的 δ 是大负值，所以给 A_t 更负的偏置，正确地告诉模型"你这一系列动作都不好"。而纯单步 TD 只看到 -1.9，惩罚不够。

**反过来看 t+3**（拿到大奖励的那步）：

```
A_{t+3}^GAE = δ_{t+3} = +2.0   ← 只有自己这一步，因为后面没步了
```

GAE 告诉模型：t+3 这一步**做对了**（+2.0），而前面 t~t+2 的准备步骤总体是负的（-4.50）——这个区分是单步 TD 做不到的。

##### How well：λ 怎么选？

| λ | 行为 | 适用场景 |
|----|------|---------|
| 0 | 只看当前步 TD（最短视） | V 网络已经很准、奖励信号密集 |
| 0.95 | 默认值，远视但不至于全写 MC | **大多数 RL 任务的起点** |
| 1 | 等价于 MC（看完整轨迹） | 轨迹短、V 网络不准、需要无偏估计 |

**实践指南**：
- λ = 0.95 是 PPO 原论文的默认值，几乎不需要调
- 如果奖励非常稀疏（几百步才来一个奖励），λ 可以调到 0.97~0.99——需要看更远
- 如果 V 网络训练得很好，λ 可以调低——单步 TD 的偏差已经很小了

### 4. 核心机制三：剪切目标（Clipped Surrogate Objective）

#### 4.1 问题

重要性权重 r_t 在多次更新后会偏离 1——比如 r_t 涨到 5，意味着新策略做这个动作的概率变成了旧策略的 5 倍。这会导致一次更新就彻底改变策略行为，可能直接崩掉。

#### 4.2 PPO 的剪切机制

给 r_t 画一条"安全通道"：[1-ε, 1+ε]，超出范围就掐断梯度：

$$
r_t^{\text{clip}} = \text{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon)
$$

$$
L^{\text{CLIP}}(\theta) = -\min\left(r_t(\theta) A_t,\; r_t^{\text{clip}} A_t\right)
$$

**核心思想**：取 `min` 意味着"走保守的那条路"：

| A_t 正负 | 策略方向 | 如果 r_t 太大 | 剪切怎么保护 |
|----------|---------|-------------|------------|
| A_t > 0（好动作） | 提升概率 | r_t > 1+ε → 会过度提升 | min 选 r_t^{clip} = 1+ε，掐断继续上涨 |
| A_t < 0（坏动作） | 压低概率 | r_t < 1-ε → 会过度压低 | min 选 r_t^{clip} = 1-ε，掐断继续下跌 |

#### 4.3 数值推演

设 ε = 0.2，旧策略概率 π_old = 0.5，新策略概率 π_new = 0.9：

- r_t = 0.9/0.5 = 1.8（远超 1.2 上限）
- 如果 A_t > 0（好动作）：
  - r_t × A_t = 1.8 × 2.0 = 3.6
  - r_t^{clip} × A_t = 1.2 × 2.0 = 2.4
  - min(3.6, 2.4) = **2.4** ← 剪切生效，限制了更新幅度
- 如果 A_t < 0（坏动作）：
  - r_t × A_t = 1.8 × (-2.0) = -3.6
  - r_t^{clip} × A_t = 1.2 × (-2.0) = -2.4
  - min(-3.6, -2.4) = **-3.6** ← 剪切**不**生效（坏动作 + 高概率比 → 应该大幅压低，不剪切）

> 💡 关键洞察：剪切只在"新策略比旧策略更激进"时生效——也就是 r_t > 1+ε 且 A_t > 0（过度自信的好动作），或 r_t < 1-ε 且 A_t < 0（过度自信的坏动作）。其他方向不受影响。

### 5. 完整 PPO 损失函数

最终的 PPO 损失由三部分组成：

$$
L^{\text{PPO}} = \underbrace{-\min\left(r_t A_t,\; \text{clip}(r_t, 1-\varepsilon, 1+\varepsilon) A_t\right)}_{\text{策略损失（剪切）}} \;+\; c_1\underbrace{L^{\text{VF}}}_{\text{价值损失}} \;-\; c_2\underbrace{H(\pi)}_{\text{熵正则}}
$$

| 组件 | 作用 | 典型系数 |
|------|------|---------|
| 策略损失（主项） | 优化动作概率 | — |
| 价值损失 L^VF | 让 critic 网络估计的状态价值更准 | c₁ = 0.5 |

### 6. PPO 在 RLHF 中的具体运作

#### 6.1 四个模型角色

在标准 RL 中，PPO 只需要策略网络和价值网络。但在 RLHF 中，有四个模型协同工作：

| 模型 | 作用 | 训练？ |
|------|------|--------|
| **策略模型 π_θ** | 当前正在优化的对话模型 | ✅ 训练 |
| **参考模型 π_ref** | SFT 后的冻结副本，提供"锚点" | ❌ 冻结 |
| **奖励模型 RM** | 给生成的回复打分 | ❌ 冻结 |
| **价值模型 V** | 估计每个 token 位置的状态价值（用于计算优势） | ❌ 冻结（通常） |

#### 6.2 KL 散度约束：RLHF 特有的保护层

标准 PPO 用剪切来限制策略更新。RLHF 在此基础上增加了一层 KL 惩罚——防止策略模型偏离 SFT 的"安全锚点"太远（否则模型会为了追逐高分而退化）：

$$
\text{reward}_{\text{token}} = r_\phi(\text{完整回复}) - \beta \cdot \text{KL}(\pi_\theta \parallel \pi_{\text{ref}})
$$

逐 token 的 KL 散度：
$$
\text{KL}_t = \log \pi_\theta(a_t \mid s_t) - \log \pi_{\text{ref}}(a_t \mid s_t)
$$

> 💡 **为什么没有乘 π_θ(a_t \| s_t)？** 标准 KL 公式是 Σ P·log(P/Q)。但这里 a_t 本身就是**从 π_θ 采出的具体 token**，不再是"对所有可能 token 求和"。此时 log-ratio 的期望等于完整 KL——因为 `𝔼_{a~π_θ}[log(π_θ/π_ref)] = Σ π_θ·log(π_θ/π_ref) = KL(π_θ∥π_ref)`。这正是蒙特卡洛估计：采样过程已经隐含了 P 的权重，不需要显式再乘。工程上，这种逐 token 估计避免了每步对 128k 词表求和，计算量从 O(vocab_size) 降到 O(1)。

**为什么需要这个？** 如果没有 KL 约束，模型会发现 RM 在某些模式上有"漏洞"——比如 RM 给长回复系统性地打分偏高。模型就会学会无限拉长回复来刷分（reward hacking），输出质量反而下降。KL 约束相当于说"你可以优化，但不能漂离原来的自己太远"。

#### 6.3 训练循环

```
初始化：π_θ = π_SFT, π_ref = π_SFT（冻结）, RM（冻结）

for each iteration:
    1. 用 π_θ 为一批 prompts 生成回复
    2. 用 RM 为每个回复打分 r(x, y)
    3. 减去 KL 惩罚得到逐 token 奖励
    4. 用 GAE 计算每个 token 的优势 A_t
    5. 用 PPO Clip 损失更新 π_θ（重复 4-10 个 epoch）
    6. 更新 π_old ← π_θ
```

#### 6.4 RLHF 典型超参数

| 参数 | 常见取值 | 说明 |
|------|----------|------|
| 剪切范围 ε | 0.1 ~ 0.2 | 限制策略更新幅度 |
| KL 惩罚系数 β | 0.01 ~ 0.1 | 越大越保守，越贴近 SFT |
| 更新轮数 | 4 ~ 10 epochs | 每批数据重复训练次数 |
| 批次大小 | 64 ~ 256 prompts | 每轮采样的 prompt 数 |
| 学习率 | 1e-6 ~ 5e-5 | 通常比 SFT 低 1-2 个数量级 |
