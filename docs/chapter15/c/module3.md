## 核心内容

### 1. Prompt 工程：用语言引导推理

Module 1 告诉我们预训练模型已经蕴含推理能力，Module 2 展示了后训练如何激发和增强这些能力。但用户还有一个最直接的交互入口——**Prompt（提示词）**。

Prompt 工程的核心矛盾在于：**模型有潜力产出高质量推理，但需要用户在提示中提供足够的"引导信息"来激活它。** 引导的质量，取决于用户对任务和模型能力的理解——这是 Prompt 工程既是"技巧"也是"先验门槛"的原因。

#### 1.1 结构化设计技巧

| 技巧 | 做法 | 为什么有效 | 示例 |
|------|------|-----------|------|
| **明确任务目标** | 清晰描述任务类型、输入、期望输出形式 | 减少模型对意图的歧义解析，将概率质量集中在正确的输出空间 | "以列表形式输出，每项不超过 20 字" |
| **提供背景信息** | 简洁补充领域知识、公式、概念 | 相当于为模型的隐藏层提供一个"知识锚点"，更精准地激活相关 FFN 记忆单元 | "这是一个代数问题，涉及二次方程判别式 Δ=b²−4ac" |
| **减少模糊描述** | 用具体数字代替"稍微""适当" | 模糊词没有可操作的语义映射，模型只能猜测用户的真实意图 | 将"写短一点"改为"300 字以内" |
| **合理使用分隔符** | 用 `---`、`###`、编号列表划分 Prompt 结构 | 帮助模型的 attention 准确区分"指令"和"内容"，避免任务描述与输入数据混淆 | 任务说明 → `---` → 输入内容 → `---` → 输出要求 |

#### 1.2 推理引导技巧

| 技巧 | 做法 | 为什么有效 | 示例 |
|------|------|-----------|------|
| **分步推理引导** | 加"请逐步推理解决以下问题" | 触发模型进入 CoT 输出模式——与 Module 1 的 CoT 解码不同，这是通过 prompt 引导而非解码策略 | "Let's think step by step" |
| **提供示例（Few-shot）** | 给出 1~N 个 input→output 示例 | 示例为模型提供了任务格式和推理模式的"模板"，attention 可参照示例的组织范式 | `输入：苹果 → 输出：水果` |
| **角色提示** | 设定身份如"你是一名资深软件工程师" | 将模型的输出分布约束到特定领域的语言风格和知识子空间 | "你是一名经验丰富的数学老师" |
| **约束输出格式** | 要求 JSON、表格、Markdown 等 | 减少输出格式的不确定性，使模型在受限的解码空间中做选择 | "以 JSON 格式输出，包含 name 和 age 字段" |

#### 1.3 Prompt 的局限

尽管 Prompt 设计能显著改善输出质量，但它不改变模型的底层能力：

- **对用户的先验要求高**：高质量 Prompt 需要用户理解任务结构、模型能力和领域知识。用户不知道"Δ=b²−4ac"，就无法在 Prompt 中提供这个背景
- **不注入新知识**：Prompt 引导的是"模型如何组织已有知识"，而非注入新知识。如果预训练中缺少某领域信息，再好的 prompt 也无法让模型给出专业回答
- **长 Prompt 稀释注意力**：过长的 Prompt（接近 context window 上限）会稀释关键指令的 attention 权重——与 CoT 倒 U 型相同的问题

### 2. 外部工具与 RAG：突破参数化知识的边界

#### 2.1 为什么需要外部工具？

LLM 的参数在训练后不再变化，知识具有**静态性**和**时间滞后性**。Denny Zhou 在演讲中总结了一个核心不等式：

$$\text{外部工具检索 + 推理} > \text{仅推理}$$

这个不等式的含义是：**推理的质量取决于前提信息的准确性**。模型的参数化知识过时，再好的推理链也只能推出错误结论。外部工具负责提供准确的"前提"，推理负责推导"结论"。

#### 2.2 RAG（检索增强生成）— 2W2H

**What（是什么）**：RAG 在模型生成回答之前，先从外部知识库检索相关文档，将检索结果作为额外上下文输入模型。模型基于"用户 query + 检索到的文档"共同生成回答。

```
用户问："GLM-5.2 的 hidden size 是多少？"
     ↓
检索系统：从文档库检索相关词条 → 找到"GLM-5.2 技术报告"
     ↓
LLM：阅读检索文档 + 用户问题 → 生成准确回答
```

**Why（为什么需要）**：
- 弥补静态知识不足：提供实时、可更新的知识来源
- 减少幻觉（hallucination）：模型被显式提供参考资料时，更倾向于引用而非编造
- 领域特化：无需为每个垂直领域微调模型，只需维护对应知识库

**How（核心设计决策）**：

RAG 的关键在于这些设计决策，而非"要不要检索"：
- **分块（Chunking）**：文档切多大？太大 → 检索精度低，太小 → 上下文碎片化。典型 chunk size：256-1024 token
- **检索方式**：稀疏检索（BM25，基于关键词匹配）vs 稠密检索（基于 embedding 向量相似度）→ 实践中多用**混合检索**（hybrid search）
- **排序与筛选**：检索到 50 个 chunk，取 top 几个？太少 → 信息不全，太多 → 稀释注意力。典型做法：top-5 到 top-10

**How much（局限）**：
- RAG 解决**知识获取**，不解决**推理能力**。检索到了正确信息，仍需推理才能综合应用
- "Lost in the middle"现象：上下文中间位置的信息容易被模型忽略——attention 偏向开头和结尾
- RAG 不能替代预训练：模型本身推理能力弱，给了再多检索信息也无法正确推理

> 🌐 **补充（Web Search）**：Gemini Deep Research 和 OpenAI Deep Research 将 RAG 升级为多步骤流程——多轮搜索 + 信息筛选 + 综合分析，LLM 在检索过程中动态调整检索方向，检索和推理在同一循环中而非先后串行。

### 3. 全景回顾：LLM 推理能力的层次框架

回顾本章五个分析角度：

```
┌─────────────────────────────────────────────────────────────┐
│                    LLM 推理能力的来源                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────┐    ┌──────────┐    ┌──────────────────┐      │
│  │ 预训练    │───→│ 后训练    │───→│ 推理时方法        │      │
│  │ 能力基础  │    │ 激发与对齐 │    │ 激发与扩展        │      │
│  └──────────┘    └──────────┘    └──────────────────┘      │
│       │               │                   │                │
│       ▼               ▼                   ▼                │
│  • 压缩=预测     • SFT: 格式对齐     • CoT: 草稿纸扩大     │
│  • 分布式表征    • RL: 概率重分配      有效计算深度         │
│  • FFN 键值记忆  • 蒸馏: 知识注入     • Prompt: 引导激活   │
│  • 记忆+泛化     • KL 约束防欺骗      • 多路径解码: 搜索   │
│                                       • RAG: 外部知识扩展  │
│                                                             │
│  ─────────────────────────────────────────────────────────  │
│  核心关联:                                                   │
│  Scaling Law → 预训练能力 ↑ → 后训练收益 ↑ → 推理表现 ↑     │
│  每层建立在前一层之上，不能跳过                               │
└─────────────────────────────────────────────────────────────┘
```

**五层递进关系**：

1. **预训练**是地基——通过压缩海量文本，参数空间内化了语言统计规律和深层推理范式（Module 1）
2. **后训练**是装修——不改变地基，让能力以符合人类期望的方式展现（Module 2）
3. **CoT**是草稿纸——通过显式中间步骤扩大有效计算深度，但过长反而有害（Module 2）
4. **Prompt**是交互界面——引导激活，但不增加新能力（本模块）
5. **外部工具**是扩展——突破参数化知识的时效性和覆盖范围限制（本模块）

### 4. 延伸思考：合成数据与 LLM 的自我改进

#### 4.1 AlphaGo Zero 的类比——及其在 LLM 场景的失效

课程原文提出一个有启发性的类比：AlphaGo Zero 通过自我博弈，不依赖人类棋谱达到超人类水平。LLM 能否通过类似的"自我生成 → 自我验证 → 自我改进"闭环突破人类数据的上限？

```
AlphaGo Zero 的自我博弈闭环：
  下棋（生成）→ 判断输赢（验证）→ 更新策略（学习）→ 下棋（生成）→ ...
       ↑                            │
       └────────────────────────────┘
      验证信号：围棋规则提供的完美、无噪声信号
```

**关键差异**：AlphaGo Zero 依赖围棋规则提供的**完美验证信号**——每一步的最终结果（赢/输）不可争议。LLM 面对的大多数开放性任务**不存在完美的自动验证器**。

课程原文一针见血：

> 对于可验证问题（数学、代码），可以利用已有的客观验证器构建自我博弈训练闭环（已被 DeepSeek-R1 验证有效）；对于开放式问题，不存在完美的奖励函数，当前只能依赖不完美的替代信号（人类偏好、模型互评等），且必须警惕奖励黑客和模型坍塌的风险。

#### 4.2 模型坍塌（Model Collapse）的风险

反复在自身生成的数据上训练可能导致：
- **分布收窄**：模型越来越偏向高频模式，丢失长尾知识
- **质量退化**：错误和偏差在循环中被不断放大
- **新颖性丧失**：模型不再能生成训练分布之外的内容

课程原文提出的缓解思路是"人工筛选 + 分布约束"——初期通过人工审核或高质量模型评估筛选合成数据，后续通过 KL 散度等指标监控合成数据与原始分布的偏移程度。但这本质上是**降低风险**，而非**消除根本矛盾**——开放式任务缺乏完美验证信号这个硬约束没有改变。

#### 4.3 一个开放问题：能否让模型用"自己的方式"推理？

课程文末的问题值得深思：

> LLM 在预训练中已形成一套自身独有的知识压缩方式与隐含推理范式，这套范式未必与人类思维习惯一致，但它或许是为模型架构天然优化的。是否可以不必强制对齐人类风格的思维链，而是允许模型以其"原生"的方式进行推理，随后再通过对齐阶段将最终输出转化为人类可读的形式？

这个问题的深层含义：**将高维推理过程强行约束在人类自然语言框架中，本质上是"用低维表示瓶颈化一个高维过程"**。

目前没有标准答案，但可能的探索方向包括：
- 在 embedding space 中做推理（而非 token space）
- 用"压缩 token"表示推理中间状态（潜空间推理）
- 训练阶段允许模型自由探索推理方式，只对最终输出做对齐（推理与表达解耦）

<summary>📖 Q1 参考答案（预训练 → 后训练）</summary>

**关系：递进（progressive）——后训练建立在预训练之上，不能独立存在**

以"解一道数学题"为例：

1. **预训练阶段**：模型在海量文本（包括数学教材、解题论坛、论文）上学习语言建模。通过压缩这些文本，模型的参数空间内化了代数规则、等式变换、因式分解等数学推理范式。此时模型"会做"数学题——但它的输出分布中，正确解题路径的概率可能只有 5%，其余 95% 分布在错误的路径上（Pass@k 分析验证了这一点）。

2. **后训练阶段（RL）**：通过对模型的输出进行奖励（正确 +1，错误 -1），RL 将正确路径的概率从 5% 提升到 90%。此时模型不仅"会做"，而且"习惯性做对"——用户 k=1 采样就能得到正确答案。

**递进的证据**：
- Mind Lab 2025 实验：小模型 + RL 收益有限，大模型 + RL 收益显著——因为预训练决定了 RL 的"激发上限"
- 如果跳过预训练直接做 RL（随机初始化的模型），RL 根本无法学到任何东西——因为没有可被"重分配"的正确路径

**与其他关系类型的对比**：
- 预训练与 CoT：**互补**——预训练给了能力，CoT 通过扩大有效计算深度让能力在推理时释放
- CoT 与外部工具：**互补但独立**——CoT 不需要外部工具也能推理（准确率受限于知识），外部工具不需要 CoT 也能提供信息（但无法深度整合）

**(a) 围棋 vs LLM 的验证信号差异**：

围棋的验证信号是"完美"的，因为：
- **客观性**：围棋规则明确规定了什么是合法落子、什么是终局、如何判定胜负。黑白胜负是规则**逻辑导出**的结果，不存在"有人觉得黑胜、有人觉得白胜"的歧义
- **二元性**：结果只有赢/输（0/1），没有中间状态
- **无噪声**：无论评估多少次，同一盘棋的胜负结果永远相同
- **不需要近似**：不需要"训练一个裁判"——规则本身是裁判

LLM 开放性任务的验证信号不完美，因为：
- **主观性**：写作、分析、建议等任务没有唯一正确答案，"好"是主观的
- **信号是近似的**：我们无法写一个数学公式来判定"这篇散文好不好"，只能训练奖励模型来模拟人类偏好——而这个奖励模型本身有 bug、有偏差、可被 exploit
- **多维性**：一个好的回答可能在正确性、可读性、完整性、创造性等多个维度有不同表现，将这些压缩成一维 reward 必然有信息损失

**(b) DeepSeek-R1 利用"可验证性"实现自我改进**：

DeepSeek-R1 在数学和代码领域利用了这两类任务的**客观可验证性**：

**数学**：最终答案可被自动判定（如与标准答案比较、代数等价检查）。模型生成解题过程 → 提取最终答案 → 与标准答案比对 → 正确 +1，错误 -1

**代码**：代码的功能正确性可以通过**执行测试用例**自动验证。模型生成代码 → 在沙箱中运行 → 测试通过 +1，失败 -1。这种验证比数学更强——它不仅验证最终输出，还能验证**整个程序的行为**

这个闭环的关键在于：验证信号是**算法自动生成的**，不需要人工标注。因此可以用大规模合成数据持续训练——模型生成 → 自动验证 → 奖励信号 → 更新模型 → 模型生成更好的结果 → ……

但需要注意的是，这仅适用于**可验证子集**。R1 的写作能力、对话能力等仍然需要依赖其他训练方法。

<summary>📖 Q3 参考答案（多角度综合分析）</summary>

这个开放问题没有标准答案，以下从三个维度分析可能的技术挑战：

**1. 训练信号问题**（最根本的挑战）
- 在 token space 推理时，每个 token 自身就是监督信号（teacher forcing 或 RL 的 token-level reward）
- 在 latent space 推理时，中间步骤不可见 → 只能用最终输出的正确性作为训练信号 → 信号极度稀疏
- 类比：训练一个学生解题，但只允许看他写的最终答案，不允许看他写的草稿——很难知道他在哪一步犯了错
- 可能的解决方向：用"推理步骤对齐"——训练一个 decoder 将 latent state 映射回可读的推理步骤，用这个映射后的步骤作为中间监督

**2. 表征质量与信息瓶颈**
- 如何设计一个 embedding space，使其既紧凑（过滤噪音）又信息充分（保留推理所需的所有信息）？
- 这与 VAE 的 latent bottleneck 是同一类问题——bottleneck 太窄 → 信息丢失导致推理错误；bottleneck 太宽 → 退化成另一种形式的 token-level 推理，效率增益消失

**3. 对齐与可解释性的根本矛盾**
- 如果"让模型用原生的方式推理"意味着推理过程人类不可理解，那如何做 alignment？
- 你可能无法在 latent reasoning 过程中注入 safety constraint——因为 constraint 本身需要 token-level 表达
- 这是一个深刻的 tension：效率 vs 可控性。越"原生"的推理越高效，但越难被人类监督

**4. 架构适配**
- 当前的 Transformer 架构是为逐 token 处理优化的——attention、FFN、residual 都是
- 在 embedding space 推理可能需要不同的架构设计（如 continuous-time models、neural ODE 风格的推理步骤、或专用的 reasoning layers）
