## 核心内容

### 0. 一个反直觉的现象

2026 年初，我们见证了 LLM 在复杂推理上的惊人突破——Claude 仅用 31 步攻克了 Knuth 未解的图论猜想，Gemini Deep Think 结合树搜索解决了理论物理开放难题。然而，当向同一个模型提问"9.169 和 9.6 哪个大？"时，它依然会展开一段冗长的"思考"过程。

这种**简单问题过度思考、复杂问题反而能解**的矛盾，引出了本章的核心问题：**LLM 的推理能力到底从何而来？** 本模块聚焦于预训练阶段——在 SFT/RL 之前，基座模型已经具备了怎样的推理潜能。

### 1. 解码策略如何影响推理能力的展现

#### 1.1 贪婪解码的"隐藏"效应 — 2W2H

**What（是什么）**：贪婪解码（greedy decoding）在每一步选择当前条件概率最大的 token：

$$\arg\max P(x_t \mid x_{<t})$$

这是局部最优搜索——每一步最优，但整条路径未必最优。

**Why（为什么需要关注它的问题）**：Denny Zhou 等人（2024, [arxiv 2402.10200](https://arxiv.org/abs/2402.10200)）提出了一个关键观点：**预训练 LLM 的参数空间中已经存在正确的推理路径，但贪婪解码只走"概率最高的一条路"，恰好错过了它。**

**How（具体机制）**：用一个两步生成的简化例子说明：

| 候选 token | 第1步概率 P(x₁) |
|-----------|----------------|
| **A**     | **0.6**        |
| B         | 0.4            |

若选 A 后的第2步：

| 候选 token | P(x₂ \| A) |
|-----------|-----------|
| **C**     | **0.6**   |
| D         | 0.4       |

若选 B 后的第2步：

| 候选 token | P(x₂ \| B) |
|-----------|-----------|
| C         | 0.05      |
| **D**     | **0.95**  |

**贪婪路径**：A(0.6) → C(0.6)，联合概率 = 0.6 × 0.6 = **0.360**

**全局最优路径**：B(0.4) → D(0.95)，联合概率 = 0.4 × 0.95 = **0.380**

0.380 > 0.360——贪婪解码在第一步选了 0.6 的 A，却**永远错过了**第二步那个条件概率高达 0.95 的 D。

> 这个例子的深层含义：高条件概率的节点（D=0.95）往往隐藏在初始概率较低的路径上。这正好对应推理的直觉——正确的推理第一步往往是"想到一个不那么显然的方向"，而不是"走最常规的路"。

**How much（边界与局限）**：
- 贪婪解码的优势是低延迟，每次只算一个 token
- 它在**事实性问答**（"法国的首都是什么？"）上通常没问题，因为答案路径本身就是高概率的
- 它在**多步推理**（数学证明、逻辑推理）上容易失败，因为正确的第一步往往不是概率最高的
- 束搜索（beam search）能缓解但非根治——扩大搜索宽度会增加计算量

#### 1.2 CoT 解码：不靠提示词，靠解码策略激发推理

Denny Zhou 团队的 CoT 解码方法（2024）不修改模型、不添加提示词，只改变解码方式：

1. **在每一步解码时考虑 Top-k 个候选 token**（而非仅 Top-1）
2. **并行维护多条候选推理路径**
3. **通过路径级置信度评分**（模型对答案的 logit 置信度）选出最连贯的推理链

实验发现：当 k≠0（即不走贪心路径）时，模型生成的内容中出现了**明显的思维链结构（CoT pattern）**，且模型对这些 CoT 路径的答案置信度通常更高。这说明正确的推理路径在参数空间中本就存在，只是概率不是最高。

> 🌐 **补充（Web Search / Google DeepMind）**：CoT 解码在 PaLM-2 Large 上进行了验证。该方法的关键创新在于：它证明了**不需要 few-shot 示例或"Let's think step by step"提示词**，仅靠解码策略就能从预训练模型中提取推理链。这从根本上区分了"模型有没有推理能力"和"解码策略有没有展示出来"。

**CoT 解码的美中不足**：多路径搜索需要同时维护和评估多条候选路径，**内部计算消耗更多 token 的分析资源**（但最终输出的 token 数未必增加）。这本质上是"用推理时的计算量换取推理质量"——与后文将要讨论的 CoT（思维链提示）和 test-time compute scaling 一脉相承。

### 2. Pass@k 分析：RL 是"激发"还是"创造"？

#### 2.1 核心实验 — 2W2H

**What（是什么）**：Pass@k 是一个评测指标——对每个问题生成 k 条候选回答，只要其中至少有一条正确，该问题即算通过。它衡量的是模型输出分布中**是否存在正确路径**，而非最可能路径是否正确。

**Why（为什么需要它）**：传统 accuracy（Pass@1）只能衡量"模型最可能给出的答案是否正确"。但如果我们想知道"模型到底会不会这道题"，需要看它的分布中是否包含正确答案——即使这个答案的概率很低。

**How（关键发现）**：Yue 等人（2025, [arxiv 2504.13837](https://arxiv.org/abs/2504.13837)）对 Qwen、LLaMA 等基座模型及其 RLVR 微调版本进行了系统比较：

<p>图：基座模型与 RLVR 变体在数学基准上的 Pass@k 曲线</p>
</div>

关键观察：
- **k 较小时**：RLVR 模型的 Pass@k **明显高于**基座模型
- **k 增大时**：基座模型的 Pass@k **逐渐逼近** RLVR 模型，部分任务上甚至**反超**

> 🌐 **补充（Web Search）**：该论文的核心结论是"RLVR just increases the frequency at which capabilities are sampled, rather than giving a base model fundamentally new capabilities"——RLVR 提高了正确推理路径在分布中的概率，而非赋予模型其参数空间中不存在的新能力。

**How much（边界与深层含义）**：
- 这一结论有适用边界：它适用于**预训练已经充分的大模型**。如果基座模型很小、预训练不充分，其参数空间中可能确实不存在正确的推理路径，这时 RL 的效果有限（Mind Lab 2025 的实验也印证了这一点——大规模基座模型的 RL 收益远大于小规模模型）
- Pass@k 分析说明 RLVR 的作用机制更像"**概率重分配**"（redistribution）而非"**能力注入**"（injection）
- 但这不意味着 RL 不重要——将正确路径的概率从 0.1% 提升到 80%，在实际应用中是决定性的

**与第 14 章的关联**：这正好呼应了 GRPO/PPO 的核心机制——通过优势函数 A_t 的符号（正/负），增加好 token 的概率、降低差 token 的概率。RLVR 在做的就是**概率重分配**，而 Pass@k 分析从宏观层面验证了这一微观机制的有效性。

### 3. LLM 问题求解能力的来源

如果预训练模型已经蕴含推理能力，那这个能力是从哪来的？本节从理论、实验和架构三个角度展开。

#### 3.1 信息论视角：压缩即预测

**What（是什么）**：语言模型的训练目标是**最小化交叉熵损失**：

$$H(p, q) = -\sum p(x) \log_2 q(x) = H(p) + D_{KL}(p \parallel q)$$

其中 H(p) 是真实分布的熵（理论最优编码长度），D_KL 是模型分布与真实分布的 KL 散度。最小化交叉熵 = 使模型预测分布 q(x) 逼近真实分布 p(x)。

**Why（为什么这意味着"智能"）**：从信息论看，预测概率越准 → 编码越接近理论最优。当模型对训练数据的压缩程度不断深入时，仅靠记忆表层统计共现模式将不再足够——模型需要逐步捕捉深层结构规律（逻辑推理范式、因果关系、数理法则），才能进一步降低预测误差。

> 💡 **补充（DeepMind, arxiv 2309.10668）**：DeepMind 团队的"Language Modeling Is Compression"研究通过实验证明：LLM（Chinchilla、Llama 2 等）本身就是强大的通用压缩器。他们用算术编码将 LLM 的预测概率转化为实际压缩，发现 LLM 在文本、图像、音频等多种数据上的压缩率优于专用压缩算法（如 PNG、FLAC）。

**How much（压缩类比的局限）**：
- 压缩视角解释了"能力从哪来"——因为要压缩得好，必须理解结构
- 但它不解释"为什么某些推理能力需要 CoT/RL 才能激发"——可能因为正确的推理路径压缩效率高但概率低
- Hinton 在演讲中提出的类比：DNA 是进化过程中对环境信息的压缩编码，LLM 的参数是预训练过程中对文本信息的压缩编码——两者都是通过压缩形成对"世界结构"的抽象表征

**数值推演**：假设一个 1GB 的文本数据集，真实熵 H(p) ≈ 2 bit/字符（英文文本）。如果用均匀分布（q=uniform）编码，每字符需 log₂(|vocab|) ≈ log₂(50000) ≈ 15.6 bit。训练后 LLM 的预测分布可能在每字符 2.5 bit 左右——这意味着模型学到了接近真实分布的统计结构（15.6 → 2.5 bit/char，压缩率 ~84%）。

#### 3.2 Hinton 家谱实验：分布式表征的起源

**What（是什么）**：1986 年，Hinton 等人在 Nature 上发表的经典论文中展示了一个实验——训练一个简单的多层神经网络，输入 (Person, Relation)，输出对应的 Target Person。例如：

$$(\text{Christopher}, \text{has\_wife}) \rightarrow \text{Penelope}$$

**Why（为什么重要）**：当时符号主义学派认为神经网络内部缺乏显式结构表示，无法形成抽象概念表征。这个实验直接反驳了这一点。

**How（发现了什么）**：训练完成后，研究者分析了隐藏层单元的激活模式，发现：
- 某些隐藏单元对**性别**（gender）有强烈响应——不管输入是谁，只要涉及男/女性关系，这些单元就激活
- 某些单元对**国籍**有响应——区分意大利裔和英裔人物
- 某些单元能区分**家族分支**关系——同一家族谱系内的不同分支

这意味着：**抽象概念不是以单一符号的形式存储，而是由多个神经元的联合激活模式共同表示**——这就是分布式表征（distributed representation）。

**How much（与 LLM 的关联）**：
- 现代 LLM 继承了这个核心机制：通过梯度优化，隐藏层逐渐形成能捕捉数据结构的内部表示
- LLM 将家谱实验的逻辑放大到万亿级参数和海量文本——模型可能将**问题求解的潜在逻辑（推理范式、结构化模式）隐式编码到权重中**
- 因为内化的是"抽象求解框架"而非"死板规则"，模型获得了 Zero-shot / Few-shot 泛化能力
- 但这也解释了为什么有时模型会"过度推理"简单问题——抽象的推理框架被激活后，即便是简单问题也走了"深层推理"路径

#### 3.3 FFN 作为键值记忆：Transformer 的知识存储

**What（是什么）**：Mor Geva 等人（2021, EMNLP）发现，Transformer 中的 FFN 层可以被解释为**键值记忆结构（key-value memory）**：

$$\text{FFN}(x) = f(x \cdot K^\top) \cdot V$$

其中第一层权重矩阵 K 的每一行代表一个"键"（可被输入模式激活的检测器），第二层权重 V 的每一列代表一个"值"（被激活后输出的信息）。中间的非线性激活函数 f 起到"选择哪些记忆被读取"的门控作用。

> 🌐 **补充（Web Search / Geva et al., EMNLP 2021）**：FFN 占据 Transformer 总参数的约 **2/3**。这意味着模型的"知识存储"主要发生在 FFN 层中，而非 Attention 层。Attention 负责的是"在当前上下文中，哪些 token 的信息应该被聚合"（information routing），FFN 负责的是"聚合后的信息触发了什么知识"（knowledge recall）。

**Why（为什么 FFN=记忆这个视角重要）**：它解释了 LLM 的"知识"物理上存在哪里，以及不同层之间的分工。

**How（深层与浅层的分工）**：Geva 等人通过寻找"能强烈激活某个神经元的输入前缀（triggering prefixes）"来研究不同层捕获的语言模式：

| 层级 | 捕获模式 | 触发特征 | 示例 |
|------|---------|---------|------|
| **浅层（1-9层）** | 表层语言模式 | 固定短语、词形、局部上下文 | "according to..."、"in the case of..." |
| **深层（10-16层）** | 抽象语义/语法特征 | 语义关系、实体类型、语用模式 | 时间表达、数量关系、因果连接 |

**关键机制**：残差连接使浅层的表层模式与深层的语义信息在多层结构中不断叠加——模型表示被逐层细化（refinement），最终形成合理的下一 token 预测。

**How much（局限与扩展）**：
- FFN=记忆的视角催生了**模型编辑**（model editing）技术——通过修改特定 FFN 神经元的权重来更新模型中的事实知识
- MoE（混合专家）架构的本质就是把 FFN 从"一个通用记忆库"扩展为"多个专业化记忆库"——DeepSeek-V3 有 256 个专家，每个 token 只激活其中 8 个，每个专家都是独立的键值记忆
- 但 FFN 不仅仅是记忆——它也有**计算能力**（非线性变换）。记忆和计算的界限在深层网络中往往是模糊的

#### 3.4 记忆与泛化的协同

综合以上三个视角，LLM 的推理能力并非单一来源，而是**记忆（Memorization）与抽象压缩（Generalization）的协同**：

```
记忆（Memorization）                    压缩/泛化（Generalization）
─────────────────                    ─────────────────────
存储具体知识片段                      内化结构化推理模式
FFN 键值记忆中的事实                  权重中的分布式表征
使模型能"回忆"特定信息                 使模型能"推理"新问题
└──────────────────────────────────────────────────────────┘
                        协同作用
             在面对新问题时，记忆提供"已知的相似案例"，
             泛化提供"如何类比和推断"的框架
             两者结合 → 隐式"理解"
```

Denny Zhou 团队的类比推理实验（[arxiv 2310.01714](https://arxiv.org/abs/2310.01714)）很好地展示了这种协同：当直接要求 LLM 求解一道复杂几何题时，模型通常失败；但如果加上提示"**回忆一个相关的几何问题，然后解决当前问题**"，模型就能给出正确答案——提示词激发了记忆中存储的相关知识，模型的泛化框架将其映射到新问题上。

> 当压缩比超过某个临界点时，模型不再能通过简单的"记录"来降低交叉熵损失——它必须通过"理解"世界的运行逻辑（数学规则、因果关系）来节省参数空间。这种从"**量变（数据堆砌）→ 质变（逻辑涌现）**"的过程，可能是 LLM 求解能力的终极答案。

**A3**：

观点："预训练模型已蕴含推理能力”

<summary>📖 Q1 参考答案</summary>

**(a) 正确推理路径概率不是最高的原因**：

从正文的两步生成例子可以看出核心原因——**局部最优 ≠ 全局最优**。贪婪解码每一步选 max P(token)，但单步概率最高的 token 锁死的后续路径，联合概率可能低于初始概率较低的路径。

更深层的原因：
- **正确的推理第一步往往是"非显然"的方向**。模型在预训练中见过大量"常规路径"（如直接给答案），这些路径的第一步概率最高，但不通向正确推理
- **高条件概率的后续节点隐藏在低初始概率的路径上**。B 只有 0.4，但一旦选 B，D 的条件概率高达 0.95——模型"知道"B 之后该做什么，只是 B 本身被 A 的 0.6 压住了
- **多样性 vs 概率的 tradeoff**：预训练模型需要拟合海量文本分布，正确推理只是众多可能路径之一，概率不一定排第一

**(b) CoT 解码的核心机制**：

CoT 解码不修改 prompt、不微调模型，只改变**解码时的 token 选择策略**：

1. **Top-k 候选展开**：每一步不只选概率最大的 1 个 token，而是保留 Top-k 个候选
2. **多路径并行搜索**：从这些候选出发，并行生成多条完整的推理路径
3. **路径级评分筛选**：通过模型对最终答案的 logit 置信度（答案 token 的概率）来评估每条路径的质量，选出置信度最高的那条

关键：CoT 解码**不改变**模型的输出分布 P(token | context)，它只是**搜索更多路径**而非只看贪婪的那一条。正确的推理路径本就存在于分布中——CoT 解码的任务是"找到它"，而非"创造它"。

**与 CoT Prompting 的本质区别**：

| | CoT Prompting | CoT Decoding |
|---|---|---|
| 改变什么 | 输入分布（加了 prompt）→ 输出分布随之改变 | 仅改变 token 选择策略，不改变分布 |
| 核心手段 | Prompt 引导（"Let's think step by step"） | Top-k 搜索 + 置信度筛选 |
| 对模型的假设 | 模型需要被"教会"推理 | 模型已经会推理，只是需要被"找到" |

<summary>📖 Q2 参考答案</summary>

**(a) RLVR 的作用机制：概率重分配（probability redistribution）**

Pass@k 曲线的核心结论：
- k 小（如 k=1）：RLVR 模型 >> 基座模型 → RLVR 让正确路径更容易被采样到
- k 大（如 k=100）：基座模型 ≈ RLVR 模型 → 基座模型的分布中**本来就存在**正确路径

这说明 RLVR 没有为模型注入其参数空间中不存在的新能力。它的机制是**重分配输出分布的概率质量**——将正确推理路径的概率从"存在但很低"提升到"大概率被采样"。

从 GRPO/PPO 的微观机制来看（回顾第 14 章）：
- A_t > 0 的 token → 增加概率
- A_t < 0 的 token → 降低概率
- 正确推理路径上的 token 接收到正优势信号 → 概率逐步提高

这验证了一个重要约束：**RL 受限于预训练所积累的能力上限**。如果基座模型很小、预训练不充分，其参数空间中可能确实不存在正确推理路径，RL 的效果就会非常有限。

**(b) 这不意味着"RL 没用"，恰恰说明 RL 至关重要**

- **k=1 场景是实际部署的标准**：用户问一个问题，模型给一个答案。没有人在生产中采样 100 次再选
- **概率重分配的价值是决定性的**：将正确路径的概率从 0.1% 提升到 80%，在使用 k=1 时就是从"几乎永远错"变成"大部分时候对"
- **RL 让模型的行为与人类期望对齐**：基座模型"会做"但"不展示"，RL 让它"展示出来"
- **类比**：一个学生脑子里知道答案（基座模型），但考试时总写错（贪心解码选不到）；RL 相当于训练学生在考试时把正确的思路写出来

Hinton 1986 年的家谱实验为"预训练模型蕴含推理能力"提供了最早的实验证据。实验中，一个简单的多层神经网络通过学习 (Person, Relation) → Target Person 的映射，在隐藏层中自发形成了**分布式表征**：不同神经元对性别、国籍、家族分支等抽象概念产生选择性响应，但这些概念并非以单一符号存储，而是分布在多个神经元的联合激活模式中。
