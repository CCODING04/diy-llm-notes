## 核心内容

### 1. 知识类基准的演进：层层递进的"更难考试"

知识与推理类基准的核心设计模式是**多项选择题**——给定问题和 4-10 个选项，模型需选出正确答案。它的演进史可以概括为一句话：**每当上一个基准被"刷满"，就用更难的题造下一个**。

```
MMLU (2020)           → 饱和（最强模型 90%+）
  ↓ 增加选项，删除简单题
MMLU-Pro (2024)       → 接近饱和（最强模型 ~90%）
  ↓ 让 PhD 来出题，要求"谷歌搜不到"
GPQA Diamond (2024)   → 接近饱和（最强模型 ~94%）
  ↓ 50 万美元悬赏，人类专家 vs 模型对抗
Humanity's Last Exam (2025) → 最强模型仅 ~54%
```

#### 1.1 MMLU：大规模多任务语言理解

**设计**：57 个学科（数学、历史、法律、伦理等）、约 16,000 道多选题，题目来自网络。初衷是测试模型的"知识广度"。

**GPT-3 时代的表现**：最大型号 X-Large 不到 50% → 当时被认为是极具挑战性的基准。

![GPT-3在MMLU上的少样本提示](<../images/12-16-GPT-3在MMLU上的少样本提示.png>)

**饱和现实**：到 2026 年初，Gemini 3 Pro 达到约 92%，GPT-5.3 Codex 达到 93%。天花板约 91%（部分题目本身存在歧义或标注错误）。

> 🌐 **补充（Web Search / CodeSOTA）**：MMLU 天花板的存在意味着即使完美模型也无法达到 100%——基准中的噪音（标注错误、歧义）构成了"不可约误差"。LifeArchitect 的 Alan Thompson 估算 MMLU 天花板约 91%。

#### 1.2 MMLU-Pro：MMLU 的"增压版"

MMLU 饱和后，MMLU-Pro 做了两个核心改进：

| | MMLU | MMLU-Pro |
|---|---|---|
| **选项数** | 4 个 | **10 个** |
| **题目质量** | 原始网络收集，含噪声/简单题 | 移除噪声大或过于简单的题目 |
| **随机猜测分数** | 25% | **10%** |
| **典型提示方式** | 少样本 | 少样本 + **思维链（CoT）** |

![MMLU-Pro对比MMLU](<../images/12-17-MMLU-pro对比MMLU.png>)

**为什么 10 个选项比 4 个难这么多？** 不只是随机概率从 25% 降到 10%。更重要的是，出题者需要构造 9 个"看起来合理"的干扰项——这些干扰项来自**常见的错误答案模式**。模型不能只靠"排除明显错误项"来做题，必须在精细的语义层面区分正确答案和高度相似的干扰项。

**饱和状态**：2025 年 11 月 Gemini 3 Pro 达到 90.1%，MMLU-Pro 天花板约 90%。MMLU-Pro 的历史使命可能已接近完成。

#### 1.3 GPQA Diamond：PhD 级别"防谷歌"问答

GPQA 的核心创新在于**出题方式**：

- 61 名 PhD 通过 Upwork 平台出题
- 设计要求：非专家即使花 30 分钟用谷歌搜索也**难以解答**
- 博士级专家准确率 65%，非专家（可用谷歌）34%，GPT-4 首次测试 39%

![GPQA](<../images/12-18-MMLU-pro对比MMLU.png>)

这标志着评估哲学的一个重要转变——MMLU 测试"模型知不知道"，GPQA 测试"模型能否进行专家级推理"。你可以把答案告诉模型（不存在数据污染），但没有推理能力依然无法在有限选项中找到正确答案。

**GPQA Diamond** 是 GPQA 的高质量子集（448 题），标准更高：专家一致率 > 2/3。当前最强（Gemini 3.1 Pro）达到 94.3%，正接近天花板（约 80-90%，取决于子集）。

#### 1.4 Humanity's Last Exam：50 万美元悬赏的"终极考试"

**设计哲学**：如果你想知道人类知识的边界在哪，就让全世界最聪明的人来出"只有他们自己能答对"的题。

HLE 包含 2500 道多模态、多学科的题，通过 50 万美元奖金池激励全球社区贡献题目，再经过前沿 LLM 筛选掉过于简单的问题，最后经多阶段人工审查。

![Humanity's Last Exam 收集筛选流程](<../images/12-19-Humanity's Last Exam 收集筛选流程.png>)

**关键数据**：
- 发布时（2025 年初）最强模型准确率 < 10%（GPT-4o: 3.3%, o1: 9.1%）
- 到 2026 年 4 月，Kimi K2.6 已达 54%
- **天花板不确定**：FutureHouse（2025 年 7 月）审查发现约 30% 的化学/生物答案可能是错误的，51.3% 得到研究支持，19.3% 存在争议

> 🌐 **补充（Web Search / LifeArchitect）**：HLE 的争议性来自其出题激励机制——50 万美元奖金鼓励"出足够难的题"，这可能导致部分出题者给出错误或高度争议性的"标准答案"。Alan Thompson 指出，如果把"有可靠研究支撑"作为正确性标准，HLE 的有效天花板仅约 51.3%。这暴露了极限难度基准的固有矛盾：**越难的问题，越难有唯一正确答案**。

### 2. 知识类基准的核心局限

在欣赏这些基准的演进逻辑的同时，必须认识它们的共性局限：

**局限一：多项选择题 ≠ 真实能力**

MMLU-Pro 仍残留了选择题的"捷径"——Chandak 等人 2025 年的研究显示，即使在 MMLU-Pro 上，模型也能利用选择题格式的统计偏差（如选项长度、否定词分布）。自由形式答案匹配（free-form answer matching）被证明与人类判断更一致。

**局限二：都是"考试"形式**

这些基准都是标准化的学术测试——它们测量的是模型在**封闭、有标准答案的场景**下的表现。但真实世界的知识应用往往是开放的、需要综合判断的、无唯一正确答案的。

**局限三：HLE 的"正确性"本身不确定**

HLE 的部分"标准答案"可能有误。一个能在 HLE 上得高分的模型，可能不是因为"知识更广"，而是因为"学会了猜测出题者的意图"。

### 3. 指令遵循基准：模型"听不听话"

知识类基准测的是"知不知道"，指令遵循基准测的是"听不听话"——模型能否按照用户的具体要求进行输出。

#### 3.1 Chatbot Arena：人类偏好的"盲测竞技场"

已在模块 1 中详细介绍。核心机制：匿名盲测 + 人类投票 + ELO 评分。

![Chatbot Arena](<../images/12-20-Chatbot Arena 分数排行榜单.png>)

在指令遵循的语境下，Chatbot Arena 的特殊价值在于它是**唯一大规模收集真实人类偏好信号**的评估平台。它的问题也是所有动态评估的共性——信号质量随博弈者的增多而下降（模块 1 的"评估污染"）。

#### 3.2 IFEval：机械化指令验证

IFEval 的独特设计在于——**不使用人类或 LLM 评分，而用程序化规则自动验证**：

![IFEval包含指令的详细描述](<../images/12-21-IFEval包含指令的详细描述.png>)

**工作原理**：给模型一条包含可验证约束的指令，然后用程序检查输出是否满足约束：

```
指令："用至少 5 句话解释光合作用，第 3 句必须包含'叶绿体'一词"
↓
模型输出
↓
程序检查：① 句数 ≥ 5？ ② "叶绿体"在第 3 句中？
↓
全部满足 → 通过
```

| 约束类型 | 示例 | 验证方式 |
|----------|------|---------|
| 长度约束 | "至少 5 句话" | 分句计数 |
| 关键词约束 | "必须包含 'quantum'" | 子串匹配 |
| 格式约束 | "以 JSON 格式输出" | JSON 解析器 |
| 负面约束 | "不要使用 'AI'" | 子串排除 |

**优点**：完全自动化、零裁判偏见、可大规模运行。**局限**：只能评估约束遵守情况，不能评估语义质量——模型可以完美遵守所有格式要求同时输出废话。

当前前沿模型 IFEval 准确率已达 0.951（HELM 排行榜）。

#### 3.3 AlpacaEval：LLM 当裁判

AlpacaEval 包括 805 条来自各种来源的指令。评估方式：让一个强大的 LLM（如 GPT-4）作为裁判，判断候选模型的回答是否优于 GPT-4 自身的回答，计算**胜率**。

![AlpacaEval排行榜](<../images/12-23-不同模型在AlpacaEval上的排行榜.png>)

**LLM-as-Judge 的核心风险**：

```
1. 裁判偏见（Judge Bias）
   GPT-4 倾向于偏好与自身风格相似的输出
   → 用 GPT-4 评的榜，GPT-4 系模型天然占优

2. 长度偏见（Length Bias）
   早期 AlpacaEval 版本严重偏爱更长的回答
   → 模型学会"写得长"而非"写得好"
   → AlpacaEval 2.0 引入长度控制机制缓解此问题

3. 位置偏见（Position Bias）
   裁判模型对先出现的回答有系统性偏好
   → 需要交换位置做两次评估取平均
```

> 🌐 **补充（Web Search / ICLR 2025）**：关于 LLM-as-Judge 可靠性的最新研究发现，AlpacaEval 上的评估一致性（不同裁判模型之间的排名相关性）为 0.839（Spearman），而 Arena-Hard（Chatbot Arena 子集）达到了 0.971。差异源于任务分布——AlpacaEval 大多为信息检索类任务（占 80%+），而 Arena-Hard 的代码/数学占比更高，这些任务有更客观的对错标准，裁判分歧更小。

#### 3.4 WildBench：平衡分布 + 清单打分

WildBench 试图解决 AlpacaEval 和 Arena-Hard 各自的任务分布偏差：

```
AlpacaEval (805 条)：  信息检索 80%+，代码 6%，数学 3%
Arena-Hard (500 条)：  代码/调试 57%+
WildBench (1024 条)：  各类分布更均衡
```

![WildBench构建流程](<../images/12-24-WildBench构建流程.png>)

WildBench 从 100 万+ 条真实人机对话中采样，避免了单一种类偏差。它的评估方式也是 LLM-as-Judge，但使用**逐项检查清单**（checklist）确保评估维度全面，而非一个笼统的"哪个更好"。

**关键验证**：WildBench 与 Chatbot Arena 的排名相关系数高达 **0.95**——这被视为新自动化基准有效性的"事实标准"（de facto validation）。一个新的自动化基准如果能和人类偏好信号达到这个级别的相关度，就被认为是一个可靠的评估工具。

![WildBench排行榜](<../images/12-25-HELM上不同模型在WildBench的排行榜.png>)

### 4. 知识类 vs 指令遵循：两条不同的评估哲学

```
知识类基准（MMLU → HLE）
  哲学："模型知道什么？"
  形式：多项选择题，有唯一标准答案
  演进驱动力：饱和 → 更高难度
  核心挑战：如何确保标准答案本身确实正确

指令遵循基准（IFEval → WildBench）
  哲学："模型听不听话？输出质量高不高？"
  形式：开放生成 + 规则/裁判打分
  演进驱动力：裁判偏见 → 更客观的评分机制
  核心挑战：如何在"可自动化"和"评估质量"之间权衡
```

**Q1**：MMLU-Pro 将选项从 4 个增加到 10 个，不仅降低了随机猜测概率（25%→10%），还改变了评估的**质量**。请解释：为什么 10 个选项对模型的推理能力要求不同于 4 个选项？提示——考虑干扰项的构造方式。

**A1**：

MMLU-Pro 选项新增，考虑了增加答案跟正确答案会相近或者类似，但是又不正确，容易让人造成误选，故意以此方式给模型设置干扰项。
此外，MMLU 的答案构造可能有文法、长度等作为随机猜测的依据，增加到 10 个答案后，答案更多选择更广，4个答案随机选择的依据在更多答案下无法奏效，也是对模型更多能力的要求。


**A2**：

IFEval 是 通过程序化规则，来评估模型是否能正确执行指令。
AlpacaEval 是通过 LLM-as-judge 的方式，评估模型输出结果是否能超过 judge llm 还是会低于其能力。

IFEval 因为判断的是指令的正确执行，因此其更适合 “任务类” 场景，比如 code、量化、电气执行 等，以及对 prompt 要求的满足类约束 等 需要指令执行的场景。最不适用于开放式回答的场景。

LLM-as-judge 更适合 文本类任务 场景的执行，总结一篇论文、提取文章主旨 等等。不适合 指令类任务。


**A3**：

当为了 “出足够难的题目” 获得奖金，则会出现更多为了获得奖金而设计 难题 的人们。
而题目如果足够难，可能答案设计也不够清晰，没有办法正确的判定答案是否正确，而无法正确判断答案是否正确，则会影响模型的评判基准。

### 📝 批改结果

**Q1 批改**：两个方向都踩准了。第一个方向（构造相近干扰项）是 MMLU-Pro 设计中最关键的质量提升——4 个选项允许"排除法"（三个明显错的排除，剩下一个就是了），10 个选项中有 9 个都是精心构造的"几乎正确"的干扰项，模型必须在知识层面做出精细区分。第二个方向（表面特征失效）也成立——4 选项时答案长度、句式、否定词分布等统计偏差可被利用，10 选项大大增加了干扰项的多样性，这些捷径更难以奏效。

可以强化的一点：给一个具体例子让分析更有说服力。比如"《哈姆雷特》的作者是谁？"——4 选项：莎士比亚、爱因斯坦、贝多芬、华盛顿（排除法秒杀）；10 选项：加入马洛、琼森、基德、米德尔顿、弗莱彻、德克尔等同时代剧作家——现在必须真正知道"哪个是莎士比亚写的《哈姆雷特》"。后者的难度来源不是"选项更多"，而是**干扰项不再来自"完全无关的领域"而是来自"正确答案的邻域"**，这才是 MMLU-Pro 质量提升的本质。 — 得分：**7/10**

<details>
<summary>📖 Q1 参考答案</summary>

**核心区别：干扰项从"异类"变成"近邻"**

4 个选项时，出题者只需找 3 个错误选项——这些选项可以来自完全不同的领域（狗、猫、汽车、莎士比亚），模型通过简单的语义分类就能排除。10 个选项时，出题者需要构造 9 个干扰项——它们必须来自**正确答案的语义邻域**（马洛、琼森、基德——都是同时代剧作家）。

这改变了评估的认知需求：
- 4 选项：粗粒度分类（"这是动物还是人？"）
- 10 选项：细粒度知识检索（"在 8 个同时代剧作家中，谁写了这部特定的剧？"）

**表面特征失效**

MMLU 中模型的"作弊"策略包括：① 选择最长的选项；② 选择包含"always/never"的选项；③ 根据否定词的分布模式推断。10 个选项中，干扰项数量增加使这些模式被稀释——出题者有足够的配额构造"和正确答案长度相同、也包含极端词汇"的干扰项。

**与随机猜测的关系**

25% → 10% 是表层的数学改变。深层的改变是：在 4 选项中，排除 2 个明显错误项后 = 50% 猜对概率；在 10 选项中，排除 5 个明显错误的 = 仍然只有 20% 猜对概率。排除法在 10 选项中的效力被大幅削弱。

**Q2 批改**：两个评估范式的适用范围区分得清楚——IFEval 对应"可验证约束"（任务类/指令执行），AlpacaEval 对应"偏好判断"（文本质量/开放性）。这个二分抓住了核心矛盾：**可自动化 ≠ 可评估质量**。

最大的提升空间在"最不适用"场景的分析。IFEval 不适用于"开放式回答"是对的，但原因应该更精确——IFEval 的**根本性局限不是"不适合"，而是"会给出错误的正面评价"**：一个完美遵守所有格式约束但内容完全错误（"光合作用的原料是铁和塑料"）的回答，IFEval 会给满分。AlpacaEval 的"最不适用"也不是笼统的"指令类任务"，而是**高客观性要求场景**（医疗诊断、法律咨询）——LLM-as-Judge 会因文笔流畅给错误回答高分，这是对"客观正确性"和"表达质量"的混淆。 — 得分：**7/10**

<summary>📖 Q3 参考答案</summary>

**Goodhart's Law 的经典表述**：当一个指标变成目标时，它就不再是一个好的指标。

**在 HLE 中的具体链条**：

```
预期用途："难度" = 代理指标，用于筛选能区分人类和 AI 的高质量题
实际使用："难度" = 奖金分配标准
结果：出题者优化"难度"这个指标本身，而非"区分能力"这个目标
```

**三种具体的失败模式**：

1. **冷知识难题**："1983 年第三届国际晶体学会议的第三作者的全名是什么？"——这题极难（全人类没几个人知道），但答对的人只是"恰好知道这个事实"，而非"更聪明"。这类题测试的是信息覆盖面而非推理能力，与 HLE 的目标（测试"人类知识的边界"）貌合神离。

2. **虚假共识**：出题者将自己的研究成果或个人观点设为"标准答案"。比如某位研究者坚信某个有争议的假说，将其作为单选题的唯一正确答案——业内其他专家可能选另一个选项。题目"难"不是因为需要深度推理，而是因为需要猜到出题者的立场。

3. **公平性退化**：出题者可能嵌入"陷阱"——在问题描述中故意省略关键信息，使得正确答案在逻辑上不可推出。此时题目变成了"你是否恰好知道缺失的那条信息"，而非"你能否推理出答案"。

**FutureHouse 的检验**：审查发现 HLE 中约 30% 的化学/生物答案可能是错误的，仅 51.3% 被独立研究明确支持。这意味着约一半的题目——在一个名为"Humanity's Last Exam"的基准中——其"正确答案"可能不是正确的。如果最强模型在这 30% 的"假难题"上得高分，我们实际上在奖励"学会了出题者的错误"而非"掌握了正确的知识"。
