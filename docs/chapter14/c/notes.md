### 批改结果

**Q1(a) 批改**：正确抓住了核心差异——确定性噪声可预测、随机性噪声不可预测。但缺少一个关键层次：确定性噪声的 exploit 机制。因为验证器对同一输入总返回同一错误，模型可以通过梯度优化精确学习验证器的"错误分布"（如验证器总接受某种格式），而人类偏好的随机噪声迫使模型学习"偏好分布"而非单一模式。另外，人类噪声虽然随机但可能在大样本下 unbiased——这是 RLHF 的隐式假设。——得分：3.5/5

<details>
<summary>📖 Q1(a) 参考答案</summary>

**确定性噪声（验证器 bug）vs 随机性噪声（人类偏好）的本质区别**：

| 维度 | 确定性噪声（验证器） | 随机性噪声（人类） |
|------|---------------------|-------------------|
| 重复性 | 同一输入总是同一输出 | 同一输入不同人/时段输出不同 |
| 可学习性 | 模型可精确拟合错误模式 | 模型只能学习分布 |
| 梯度信号 | 一致地指向错误方向 | 噪声在高样本量下趋向抵消 |
| Exploit 风险 | 高——模型学会"骗验证器" | 低——难以精确拟合随机噪声 |

**核心洞察**：RLVR 假设奖励信号是无偏的（unbiased），即 `E[noise] = 0`。但验证器 bug 的噪声**不是零均值的**——它系统性地偏向某个特定错误方向。

数学表述：
- 人类噪声：`R_human = R_true + ε, ε ~ N(0, σ²)`（零均值假设）
- 验证器噪声：`R_verifier = R_true + b, b 为系统性偏差`（非零均值！）

RLHF 中人类噪声的零均值假设在大样本下成立（中心极限定理），但验证器的确定性偏差无法通过增加样本量消除——只会让模型更精确地学到错误的奖励函数。

</details>

<details>
<summary>📖 Q1(b) 参考答案</summary>

**三个典型的 exploit 路径**（对应正文 1.4 节）：

**1. 等价表达式 exploit**
```
正确答案: (x+1)²
模型输出: x²+2x+1
验证器判断: ❌ (正则匹配只认 (x+1)² 形式)
→ 模型学到：不要用展开形式，只用因式分解形式
→ 对非数学题没有帮助，是表面格式适配
```

**2. 精度/单位 exploit**
```
验证器答案: 3.14
模型输出: 3.1415926535
验证器判断: ❌ (精确字符串匹配)
→ 模型学到：永远输出 3.14（两位小数），丧失精度控制能力
→ 迁移到需要高精度的科学计算场景时性能崩塌
```

**3. 多解问题 exploit**
```
方程 x²=4 的解: x=2 或 x=-2
验证器只接受: 2
→ 模型学到：只输出正值解
→ 即使在新问题上，模型也会抑制负值输出
```

**Exploit 的本质机制**：
```python
# 验证器 = 确定性函数 v(x) → {0, 1}
# 模型学习的是: argmax_θ E[v(f_θ(x))]
# 如果 v 有 bug，最优 f_θ 不是 f_true，而是满足 v(f_θ(x))=1 的任意函数
# 即: 模型优化的是"通过验证器的能力"而非"真正解决问题的能力"
```

这与 RLHF 的 reward hacking 关键区别：RLHF 的 reward model 是神经网络（黑盒，难以精确 exploit），而验证器是规则（白盒，形式化地 exploitable）。

</details>

<details>
<summary>📖 Q2(a) 参考答案</summary>

当所有 G 个回答奖励相同时（std ≈ 0, z-score ≈ 0），GRPO 的目标函数退化为：

```
J_GRPO(θ) ≈ E[ -β · D_KL(π_θ || π_ref) ]
```

即 **只剩下 KL 惩罚项**。

**这意味着什么？**

- Policy loss 项（`-logps * advantage`）≈ 0，不提供任何"哪个回答更好"的信号
- KL 惩罚项将 π_θ 拉向 π_ref
- 等效于在做**监督微调风格的分布保持**——防止模型跑偏，但也不让模型进步

**为什么不是"没有任何更新"？**

```python
# GRPO loss 的两部分
loss = policy_loss + KL_COEFFICIENT * kl_penalty
#      ↑ z-score≈0 时 = 0   ↑ 仍然在计算和反向传播
```

即使 policy_loss = 0，`kl_penalty` 的梯度仍然更新模型参数。所以：
- ❌ 错误认知："模型不更新"
- ✅ 正确认知："模型只做 KL 正则化更新——向 π_ref 靠拢"

这对 RL 训练是**有害的**：模型花费计算资源，不仅没学到更好的策略，反而在遗忘已学到的（向 ref 回退）。

</details>

<summary>📖 Q2(b) 参考答案</summary>

**大量无信息样本的三层影响**：

**第一层：计算浪费（直接影响）**
```
假设 30% 的 batch 是"所有回答相同"的样本:
→ 30% 的 GPU 时间只做 KL 正则化，不产生策略改进信号
→ 等效训练效率 = 70% × 原始效率
→ 24 小时的训练只有 ~17 小时是有意义的
```

**第二层：策略退化（间接影响）**
```
无信息样本的 loss ≈ KL_COEFFICIENT × kl_penalty
→ 梯度方向 = 将 π_θ 拉向 π_ref
→ 大量累积: 模型策略逐步退化，遗忘 RL 阶段学到的改进
→ 极端情况: 模型退化为 π_ref（RL 训练白做）
```

**第三层：方差膨胀**
```
无信息样本的 gradient var = 0（无信号）
但 batch 中混合有信息+无信息样本 → optimizer 看到的梯度是:
  g_total = 0.7 × g_signal + 0.3 × 0
→ 有效学习率被稀释了 30%
→ 需要更大的 batch 或更多的 step 才能收敛
```

**实践中的缓解方法**（正文 4.4 节讨论）：
- Dr.GRPO: 过滤掉 std 过低的样本组（`if std < threshold: skip`）
- 增加采样温度 T: 提高回答多样性 → 降低 std≈0 的概率
- 动态调整 G: 困难问题用更大的 G

<details>
<summary>📖 Q3(a) 参考答案</summary>

**"同享优势"正确 vs 错误的场景分析**：

**✅ 合理的场景：渐进式推理**

```
问题: "证明 sqrt(2) 是无理数"

Token 序列: 假设 → 平方 → 约分 → 矛盾 → QED
每个 token 同等重要，贡献均匀分布
→ 共享标量优势是合理的近似
→ 这类问题在数学证明中很常见
```

**❌ 出错的场景：纠错/顿悟式推理**

```
问题: "求解 x²-5x+6=0"

回答 A (错误→纠正):
  "x²-5x+6=0 → 因式分解 (x-2)(x-4)=0 → 不对，检查... 
   → 应该是 (x-2)(x-3)=0 → x=2 或 x=3"
                     ↑ 这个"纠正决策"至关重要！

回答 B (流畅错误):
  "x²-5x+6=0 → (x-2)(x-4)=0 → x=2 或 x=4"
  全部流畅但全部错误

z-score 视角:
- 回答 A 最终正确（r=1），回答 B 最终错误（r=0）
- 回答 A 的所有 token（包括前半段的错误部分）获得正优势
- 回答 A 前半段的错误被"奖励"了！
```

**核心矛盾**：
```
同享优势 = 信用分配问题的极端简化
  ┌─────────────────────────────────────┐
  │ GAE: 每个 token 有自己的 advantage  │
  │      V(s) 估计每个中间状态的价值     │
  │      可以区分 token 级别的贡献        │
  ├─────────────────────────────────────┤
  │ GRPO: 所有 token 同享一个标量 A_i    │
  │       无法做 token 级别的信用分配     │
  │       早期错误 = 后期纠正 = 同等对待  │
  └─────────────────────────────────────┘
```

如正文所述：**"GRPO 不区分一个回答中哪些 token 贡献大、哪些 token 贡献小——这是 GRPO 相对于 PPO 的主要精度代价。"**

</details>

**Q3(b) 批改**：你的结论"两者一致"过于绝对。严格来说，在**纯终端二元奖励+无中间 reward shaping**的场景下，GAE 和 per-response z-score **可能**给出类似的优势分布，但并非等价。关键区别在于**价值网络能否学到中间状态的进展信息**。——得分：2.5/5

<details>
<summary>📖 Q3(b) 参考答案</summary>

这个问题需要分两个层次回答：

**层次一：表面等价性（你观察到的）**

在纯终端二元奖励场景：
```
r_T ∈ {0, 1}（仅最后一步有非零奖励）
r_t = 0 for all t < T
```

GAE 计算：
```
δ_T = r_T + γ·V(s_{T+1}) - V(s_T)  ← 只有最后一步有明确信号
δ_t = γ·V(s_{t+1}) - V(s_t)  for t < T  ← 全依赖价值估计
```

如果价值网络 V(s) 不能提供有用的中间状态估计（即 V(s_t) 对所有 t 都一样），那么 GAE 确实退化为"均匀传播终端奖励到所有 token"——与 per-response z-score 没有区别。

**层次二：实质性差异（你忽略的）**

但实际训练中，**价值网络确实可以学到中间进展**：

```
考虑这个推理链:

Step 1: "思考：这个题目需要用到勾股定理"  → V(s₁) = 0.15 (稍有进展)
Step 2: "设 a²+b²=c²"                      → V(s₂) = 0.30
Step 3: "代入 a=3, b=4"                    → V(s₃) = 0.60 (接近解决)
Step 4: "c=5"                              → V(s₄) = 0.95
Step 5: "答案是 5"                          → r₅ = 1.0

GAE token-level advantages (λ=0.95, γ=0.99):
  token 1: A = +0.18  (较小，因为当时还不确定)
  token 2: A = +0.22  (类似)
  token 3: A = +0.35  (更大！因为这一步使价值跃升)
  token 4: A = +0.40  (最大，因为接近最终答案)
  token 5: A = +0.15  (较小，因为只是格式输出)

GRPO per-response z-score:
  所有 token: A = +1.414（假设 z-score）
  完全无法区分 token 贡献
```

**结论**：即使只有终端二元奖励，**一个训练得当的价值网络可以通过 V(s) 估计提供精细的 token-level 信用分配**。GAE 的 token-level advantage 携带了比 per-response z-score 更多的信息。但代价是：
- 需要训练额外的价值网络（参数量翻倍）
- 价值网络本身也有估计误差
- GRPO 用精度换效率，是这个 tradeoff 的产物

**你的回答和正确答案的分界点**：
- ✅ 正确：两者都从终端奖励反向传播信号
- ❌ 错误：认为它们"一致"——忽略了 V(s) 提供的中间状态信息
- 关键洞察：价值网络的价值恰在于它估计了"不可观测的中间进展"

</details>

**原始 GRPO 下的权重分析**：

在原始 GRPO 中，更新强度 ∝ `(r_i - r̄) / std`。即使 `(r_i - r̄)` 相同，`1/std` 这个乘数在不同问题间差异巨大：

```
问题 A (std=0.1, 简单判断题):
  |A_max| ∝ 1/0.1 = 10.0  → 更新权重 ×10

问题 B (std=0.3, 中等计算题):
  |A_max| ∝ 1/0.3 = 3.33  → 更新权重 ×3.33

问题 C (std=0.2, 难证明题):
  |A_max| ∝ 1/0.2 = 5.0   → 更新权重 ×5.0
```

**权重排序**：A (10.0) > C (5.0) > B (3.33)

最简单的题（A）获得了最大的更新权重——恰好是"最没有学习价值"的题。

**Dr. GRPO 移除 std 后**：

```
所有问题: |A_max| ∝ |r_i - r̄|  ← 退化为线性差
  A: 判断题, 标准答案固定, r_i ∈ {0, 2}, r̄ ≈ 1.0~2.0
     → |A_max| ≈ 1.0  (不再是 10.0!)
  B: 计算题, 部分对/错, r_i ∈ {0, 1, 2}, r̄ ≈ 0.5~1.5
     → |A_max| ≈ 1.5  (现在 B 的权重最高!)
  C: 证明题, 格式一致但难, r_i ∈ {0, 1}, r̄ ≈ 0.3~0.7
     → |A_max| ≈ 0.7
```

**权重重分配**：B (1.5) > A (1.0) > C (0.7)

中等难度的 B 现在获得最大权重——恰好在模型的能力边界上，学习效率最高。

## 模块 2：GRPO 训练循环、长度偏差与 Dr.GRPO 修正 — 临时 QA 记录

**Q**：数值对比中 Dr.GRPO 提到 "用总 token 数归一化，而非单回答长度"，那么为什么 Dr.GRPO 的无偏梯度形式公式中，仍然是 1/G ，而不是 1/(G*|o_i|)？

**A**：`1/G` 和 `1/Σ|o_i|` 是两种不同的归一化约定，但都不是 `1/|o_i|`。Dr. GRPO 移除的是**逐回答长度归一化** `1/|o_i|`，外层用哪种归一化都可以——只要每个 token 不按其所属回答的长度被"打折"就行。

三种归一化方案对比：
```
假设 G=2 个回答: o₁ 长 30 tokens, o₂ 长 90 tokens

方案A (GRPO):  1/G × 1/|o_i| × Σ_t   ← 长度偏差！短回答token被放大
方案B (Dr.GRPO): 1/G × Σ_t          ← 4.1公式，每个回答等权重
方案C (verl): 1/Σ|o_i| × Σ_t        ← 4.2伪代码，每个token等权重
```
- `1/G`（论文形式）：每个**回答**等权重贡献 → 回答级公平，是策略梯度 MC 估计的标准形式
- `1/Σ|o_i|`（verl 形式）：每个 **token** 等权重贡献 → token 级公平，跨 batch 数值更稳定

两者都消除了 Dr. GRPO 指出的偏差。模块中 4.2 的伪代码已与 4.1 公式对齐为 `1/G`，verl 的 `1/Σ|o_i|` 实现以备注形式保留。

---

**Q**：文档中提到了 verl 中，"actor_rollout_ref.actor.use_kl_loss: False"，为什么 Dr.GRPO 不需要独立的 KL loss 呢？不需要 KL loss 但是需要 KL penalty 项吗？

**A**：KL loss ≠ KL penalty。在 verl 框架中，KL 正则化有两条独立的路径：

| | KL loss (`use_kl_loss`) | KL penalty (reward 端) |
|---|---|---|
| 作用位置 | loss 函数内部，作为独立项 | reward 信号上，作为折扣 |
| 计算方式 | 逐 token Bregman divergence，加到 policy_loss | `r_effective = r_task - β * KL(π_θ || π_ref)` |
| 梯度流向 | 通过 loss 反向传播 | 通过 advantage（reward 被 KL 折扣后，z-score 变小） |

Dr. GRPO 不需要 loss 端 KL 的原因：
1. PPO clip 已经足够——移除 `1/|o_i|` 和 `1/std` 偏差后，梯度本身就干净稳定，clip 机制能约束单步更新幅度
2. KL 可能和 clip 互相掣肘——两者同时作用产生冗余约束，拖慢收敛
3. 经验结论——Dr. GRPO 论文及 DeepSeek-R1 实验中，`kl_coef=0` 训练依然稳定且效果不降

公式中保留 `β·D_KL` 是为了数学完备性，实际 β 通常设为 0。

## 模块 3：DeepSeek R1 案例研究 — 临时 QA 记录

> 📅 2026-06-18

**Q**：介绍 DeepSeek R1 四阶段流水时，提到了 Stage 3 "从 R1-Dev2 拒绝采样"，拒绝采样是什么意思？

**A**：拒绝采样（Rejection Sampling）的核心逻辑是"生成多个，只保留符合条件的"：

```
对于每个 prompt:
  ① 用当前模型生成 N 个回答（如 N=16）
  ② 对每个回答：
      - 提取 <answer> 部分
      - 用规则验证器判断答案是否正确
  ③ 保留"答案正确 + 格式合规"的回答
     → 丢弃其余（reject）
  ④ 从保留的回答中随机选 1 个，作为该 prompt 的 SFT 训练样本
```

在 DeepSeek-R1 Stage 3 的语境下：用 Stage 2 训练出的 R1-Dev2 模型，对大量推理题（数学/代码）采样，经过正确性验证（规则匹配或编译器）后，筛选出 600k 条"正确的推理过程 + 正确答案"作为 SFT 数据。这个方法之所以有效，是因为 R1-Dev2 已经通过 RL 学会了推理——它的"正确回答"就是高质量的 long-CoT 示范，"拒绝采样"充当了自动质量过滤器。

本质上是用**可验证的奖励信号**（每道题答案对不对可以用规则判断）替代**人工标注**（人们不需要手动写 600k 条推理解答），大幅降低数据生产成本。

## 模块 3：DeepSeek R1 案例研究 — 正式作业批改

> 📅 2026-06-17

### 批改结果

**Q1 批改**：三个因素的分析方向正确，但机制层面的深度不足。对 (a) 的理解到位——基座模型的已有能力是涌现的"土壤"而非"从零创造"；(b) 和 (c) 的分析停留在表面效果（"更长输出""先思考后总结"），未深入到 GRPO 的 `1/|o_i|` 偏差如何具体激励长输出、`<think>` 标签如何创造"安全探索空间"（思考过程不被评估，模型可以试错）。去掉 (b)(c) 后的分析也偏笼统——"需要更多算力"未点出关键后果：无格式强制 → 答案提取困难 → 正确性奖励信号变噪声；Dr.GRPO 无长度偏差 → 短回答和长回答在等权竞争，长链推理需要更长时间才能"证明"其价值。 — 得分：6.5/10

<details>
<summary>📖 Q1 参考答案</summary>

**三个因素各自的贡献：**

**(a) Base 模型已有反思能力 — 提供了"可被放大的种子"**

这是最根本的因素。DeepSeek-V3-Base 在未经任何 RL 训练时，偶尔也会展示自我纠错行为（课程图 14-12 已证实）。RL 的角色不是"教模型反思"，而是**提供环境压力**（只奖励正确答案），让模型在试错中自行发现"反思 → 正确率更高"这个因果链，从而**放大**已有的反思行为。

关键区分：如果 Base 模型完全没有反思能力（如一个极小的、未经充分预训练的模型），GRPO 再跑多少步也涌现不出反思——涌现的前提是能力已在预训练中隐式存在。

**(b) GRPO 的长度偏差 — 降低了"多思考几步"的代价**

原始 GRPO 的目标函数中，每个回答的 loss 要除以 `len(o_i)`（回答长度）：
```
loss_i = (1/|o_i|) × Σ_t [policy_loss at token t]
```

这意味着：**长回答中每个 token 对 loss 的贡献更小**。当一个 token 被加入长回答时，它对整体 loss 的"拖累"比加入短回答时小。这创造了一个隐性激励：模型倾向于生成更长的输出，因为长输出中每个 token 的"犯错成本"更低。

这个偏差不是故意设计来鼓励反思的——它是一个数学上的副作用。但它的效果是：模型更愿意"多说几句"，而多说几句恰好给了反思行为更多的"表达空间"。一个 token 的"等等，我刚才算错了"在短回答中会被压缩掉，在长回答中才有空间出现。

**(c) 格式奖励 — 创造了"安全探索空间"**

`<think>...</think><answer>...</answer>` 的格式要求做了一件关键的事：**把"思考"和"作答"分离**。准确性奖励只检查 `<answer>` 部分，`<think>` 部分的内容不被直接评估。这相当于告诉模型："在 `<think>` 里你可以随意尝试，写错了也不扣分，只要最终 `<answer>` 正确就行。"

这个"安全探索空间"是反思行为涌现的关键孵化器——如果每个 token 都被直接评估正确性，模型就不敢在思考过程中"承认错误"（因为承认错误本身就是一个"正确性扣分"的风险点）。

**如果去掉 (b) 和 (c)，模型还能自发产生反思行为吗？**

答案：**可能，但有额外的障碍。**

去掉 (b) — 改用 Dr.GRPO（无 `1/|o_i|` 偏差）：
- 短回答和长回答在梯度上等权竞争。对于"直接给答案"和"先想三步再给答案"两种策略，如果二者正确率相同，模型没有额外激励去选后者。

**为什么需要 Stage 2？**

R1-Zero 有两大硬伤，使得它无法直接进入 Stage 3 的大规模数据生产：

1. **可读性差**：R1-Zero 的输出缺乏结构化的思考格式，人类（甚至自动化流程）难以理解其推理过程。

2. **语言混合（Language Mixing）**：这是最具体、最严重的问题。DeepSeek-V3-Base 在中英双语数据上预训练，R1-Zero 的纯 RL 训练没有引入任何语言偏好的信号 → 模型输出的思考过程中经常中英混杂。例如：一个英文数学题，模型会在 `<think>` 中一会儿用英文推理、一会儿跳到中文、再跳回来。

Stage 2 的冷启动数据通过一个巧妙的 prompt 解决了语言混合：
```
"Translate the thinking process to the same language as the question."
```
这让模型学会**用与问题一致的语言进行推理**——英文题用英文思考，中文题用中文思考。

**Stage 2 为什么是"冷启动 SFT"而非"继续 RL"？**

RL 的本质是"奖励正确答案"——它关心的是 `对不对`，而不是 `好不好读` 或 `用什么语言思考`。在 R1-Zero 上继续 RL 可以进一步提升正确率，但无法解决可读性和语言混合问题，因为这些与正确性无关。需要 SFT（监督微调）直接告诉模型"好的输出应该长什么样"。

**如果跳过 Stage 2 直接在 R1-Zero 上做 Stage 3，会发生什么？**

Stage 3 的核心操作是**拒绝采样**（rejection sampling）：用当前模型对大量 prompt 生成多个回答，只保留 `答案正确 + 格式合规` 的那些，用作 SFT 训练数据。

跳过 Stage 2 后的恶性循环：

```
R1-Zero 输出混乱（语言混合、格式不规范）
        ↓
拒绝采样时，自动化流程难以可靠地提取 <answer> 部分
（因为格式不规范，规则解析器经常失败）
        ↓
两种情况，都很糟糕：
  ├── 保守策略：提取失败的回答全部丢弃
  │   → 拒绝率极高 → 需要生成海量样本才能凑够 600k
  │   → 计算成本爆炸
  │
  └── 宽松策略：降低提取标准，接受有歧义的提取结果
      → 可能把"格式错但答案碰巧对"的样本标记为正确
      → 或把"格式错导致提取错误、实际答案正确"的样本标记为错误
      → SFT 数据质量崩溃
        ↓
用这种低质量数据做 SFT → 模型学到的推理模式本身就是混乱的
        ↓
600k 低质量推理 SFT + 200k 非推理 SFT → 最终模型继承了混乱
```

**核心教训**：Stage 2 的冷启动 SFT 虽然数据量小（仅数千条），但它解决了**数据生产流水线的质量控制问题**。只有先让模型学会"规范地输出"，后续的自动化拒绝采样才能可靠运行。这是一个典型的"磨刀不误砍柴工"——少量高质量 SFT（Stage 2）为大规模自动化数据生产（Stage 3）奠定了基础。

**补充**：即使退一步说，在 R1-Zero 上直接做大规模 SFT 可以不经过拒绝采样（即使用预存的 800k 外部数据），也会有问题：外部数据的推理风格与 R1-Zero 的推理风格不一致 → SFT 会覆盖掉 RL 阶段获得的推理能力（灾难性遗忘的一个变体）。Stage 2 的冷启动数据虽然经过了人类后处理，但推理内容来自模型生成（R1-Zero + few-shot 提示）→ 风格与 RL 阶段一致 → SFT 在"修正格式"的同时保留了 RL 学到的推理模式。

<details>
<summary>📖 Q3 参考答案</summary>

**矛盾是否存在？**

存在，且是**根本性的**（fundamental），而不仅仅是"PRM 目前还不够准"的工程问题。

RLVR 的核心前提：
> 奖励必须是**可验证的、非模型的**（verifiable, non-model-based）。
> 即：奖励来自客观规则（如数学答案比对、代码编译运行结果），而非另一个模型的判断。

PRM 的核心操作：
> 用**另一个模型**对推理过程的每一步打分，作为 RL 训练的稠密奖励信号。

这里存在一个逻辑上的自指矛盾：

```
RLVR 的前提：不要用模型来判断模型（防止奖励黑客）
PRM 的做法：用模型来判断模型的每一步
                ↑
        矛盾：PRM 恰好违背了这个前提
```

**为什么这个矛盾是"根本性的"而非"暂时性的"？**

1. **奖励黑客（Reward Hacking）是结构性的，不是准确度问题**：
   - 即使 PRM 在测试集上 99% 准确，它仍然是一个模型，有自己的漏洞和盲区
   - 当 RL 优化的目标变成"让 PRM 打高分"而非"给出正确答案"时，优化过程会主动寻找 PRM 的漏洞
   - 这类似于对抗样本——一个分类准确率 99% 的图像模型，仍然可以被精心构造的扰动轻易欺骗
   - 更准确地说：优化过程在 PRM 的评分函数上做梯度上升 → 找到的是 PRM 评分最高但实际不一定正确的区域 → 这正是 Goodhart 定律的数学体现

2. **PRM 越准确，在某些意义上越危险**：
   - 一个粗糙的、随机的 PRM → 优化很难找到稳定的漏洞 → 奖励黑客效率低
   - 一个准确的、确定性的 PRM → 评分函数光滑可微 → 优化更容易沿着梯度"爬"到高分但错误的区域
   - 这是一个反直觉的结论：PRM 的准确度提升不一定带来 RL 训练效果的提升

3. **"数据多→估计准"的逻辑跳跃**：
   - PRM 的训练数据再多，它仍然是在学习一个**代理目标**（proxy objective），而非真正的"推理正确性"
   - "推理正确性"本身在开放域问题中是不可直接观测的潜变量——这就是为什么我们需要可验证奖励（如数学题的数值答案）作为 ground truth
   - 用更多数据训练 PRM 只是让它更好地拟合训练分布，但 RL 优化过程中生成的推理路径可能完全在分布外（OOD），PRM 的估计不再可靠

**DeepSeek 团队放弃 PRM 的三条具体原因如何映射到这个矛盾：**

| 失败原因 | 是根本矛盾还是工程问题？ | 分析 |
|---------|---------------------|------|
| 步骤定义难 | **工程问题**（可能被更好的标注方案缓解） | "什么算一步"在数学领域可定义（每行等式），但缺乏跨领域通用定义 |
| 标注不可靠 | **工程问题**（可能被更多人工标注缓解） | 自动标注有偏差，人工标注贵——但理论上可解决 |
| 奖励黑客 | **根本矛盾**（不可通过更多工程投入解决） | 一旦奖励来自模型，优化就会找模型的漏洞——这是结构性的 |

**矛盾是否可以被解决？**

**完全解决：不可能。** 只要 PRM 是模型，它就会引入"用模型评估模型"的结构性风险。这是 RLVR 框架在理论层面的约束——这个约束不是技术限制，而是定义性的。

**部分缓解：有可能。** 以下几种策略可以降低（但不能消除）风险：

1. **PRM 作为辅助信号而非主奖励**：主奖励仍来自可验证规则（最终答案对错），PRM 只提供微弱的稠密引导。类似于 RLHF 中 KL 惩罚的角色——"可以有多一点探索，但别跑太远"。

2. **约束 PRM 只做"验证"而非"评分"**：PRM 只判断某一步是否"明显错误"（如计算错误、逻辑跳跃），而不是给一个连续分数。二值判断比连续评分更难以被对抗性利用。

3. **PRM + 对抗训练**：在 PRM 训练数据中主动加入被策略模型 exploit 的样本（类似 GAN 的训练方式），让 PRM 对奖励黑客更鲁棒。但这也引入了新的复杂度，且不如 GRPO 简洁。

4. **PRM 只用于筛选/课程学习，不用于 RL 梯度**：用 PRM 筛选出"看起来推理质量高"的样本做 SFT（而非 RL），PRM 不进入梯度计算路径。DeepSeek-R1 的蒸馏路线本质上就用了这个思路——教师模型（R1）充当了"隐式的 PRM"，但只用于生成 SFT 数据，不参与 RL 优化。

**核心教训**：GRPO 的成功和 PRM 的失败共同说明了一个原则——在 RLVR 场景下，**保持奖励信号简单（simple reward）比追求奖励信号精细（dense reward）更有效**。复杂的方法（PRM、MCTS）看似更"智能"，但它们引入的额外复杂度和结构性风险往往超过了收益。

<summary>📖 Q1 参考答案</summary>

**(a) 去掉 `1/std` 与 Dr. GRPO 的动机是否一致？**

**答案：一致。** 但需要区分 `1/std` 和 `1/|o_i|` 解决的是两个不同的问题。

Dr. GRPO 移除两个偏差源：

|--------|-----------|---------|------|
| `1/|o_i|`（长度归一化） | 长回答 token 惩罚被稀释 → 越错越长 | 移除 | 保留（但用 len_reward 对冲） |

**两者的交集在 `1/std`**：Dr. GRPO 指出 `1/std` 会让简单判断题（std 小）的梯度权重远大于困难计算题（std 大），导致模型在"最没有学习价值的题"上花最多算力。Kimi 使用 `r - r̄`（无 std 除法）恰好避免了这个问题——与 Dr. GRPO 的动机**完全一致**。

**(b) 平方对数比 vs Bregman divergence 在约束行为上的不同**

**形式对比**：

```
Bregman KL:
  D_Bregman = π_ref/π_θ - log(π_ref/π_θ) - 1
  梯度: ∂D/∂π_θ = (π_θ - π_ref)/π_θ²
       → 包含 1/π_θ² 项，当 π_θ → 0 时梯度 ∝ -1/π_θ²（爆炸，且比平方对数比更剧烈）
       → 高度不对称：π_θ ≪ π_ref 时惩罚远大于 π_θ ≫ π_ref

平方对数比:
  D_sq = (log π_θ - log π_ref)² = (log(π_θ/π_ref))²
  梯度: ∂D_sq/∂π_θ = 2·log(π_θ/π_ref)·(1/π_θ)
       → 同样包含 1/π_θ 项，当 π_θ 很小时梯度也很大
       → 但在 log 空间对称：偏高和偏低的惩罚结构一致
```

**核心差异**：

1. **对称性**：平方对数比在 log 空间对称——π_θ 偏高和偏低的惩罚结构一致。Bregman 高度不对称——π_θ ≪ π_ref 时惩罚急剧放大（概率崩塌方向的极端惩罚），扮演"破产保护"角色。

2. **梯度爆炸风险**：两种 KL 都包含 `1/π_θ` 因子（Bregman 甚至包含 `1/π_θ²`），因此 π_θ → 0 时梯度都会爆炸。Bregman 的爆炸更剧烈（二次方 vs 一次方），因此 Bregman 对"概率崩塌"的惩罚更严厉。

3. **实践选择**：两种 KL 形式在实践中效果接近，Kimi 选择平方对数比主要是推导方便（从 DPO 框架自然导出），而非性能优势。

<summary>📖 Q2 参考答案</summary>

**为什么不能仅靠 prompt 让 R1 "不思考"？**

**第一层：格式层面的惯性**：R1 在训练中始终被格式奖励约束——必须输出 `<think>...</think><answer>...</answer>`。模型的生成分布已深度适配这个格式。即使用 prompt 说"不要思考"，模型的首 token 分布仍然强烈偏好 `<think>`——因为在整个 RL 训练中，不以 `<think>` 开头的序列从未获得过正奖励。

**第二层：优化信号层面的盲区（更根本）**：R1 的训练信号全部来自**有 `<think>` 的推理过程**。如果强行 prompt 模型跳过 `<think>`，模型需要在一个从未被奖励过的行为空间中运作。类比：一个训练了十年的围棋选手，被要求"看一眼棋盘就落子，不要思考"——他可以做到，但棋力会坍缩到远低于训练水平。

**第三层：条件生成能力缺失**：融合训练后的模型学会了将 `/no_think` 标签作为条件信号来调节行为。R1 的训练数据中不存在"不带 `<think>` 的正确回答"的示例，因此没有发展出这个条件生成能力。

**为什么融合训练是必要的**：
1. R1 的 RL 信号**只奖励有 `<think>` 的输出**——"不思考"行为从未被正强化过。
