## 核心内容

### 1. Kimi k1.5：长上下文 + 简化 RL

Kimi k1.5（Moonshot AI, 2025）与 DeepSeek-R1 几乎同期发布，两者在核心理念上惊人地一致——都用纯 RL 激发推理能力，都拒绝了 MCTS/PRM 等复杂方法。但 Kimi k1.5 在具体实现上做出了几个不同的选择。

#### 1.1 核心设计

```
Kimi k1.5 的三个关键要素:
  ├── Long Context Scaling (128K)：给模型足够的"思考空间"
  ├── Improved Policy Optimization：自研策略梯度变体
  └── Multi-modal：文本 + 视觉联合推理
```

与 R1 的关键区别：Kimi k1.5 没有使用 GRPO，而是推导了一套自己的策略梯度公式。

#### 1.2 Kimi RL 策略梯度

Kimi 的目标函数本质上与 GRPO 类似（最大化期望奖励 + KL 正则化），但推导路径不同——借鉴了 DPO 的无奖励偏好优化思想：

**目标函数**：

$$
\max_{\theta} \mathbb{E}_{(x,y^*) \sim \mathcal{D}} \left[ \mathbb{E}_{(y,z) \sim \pi_\theta} \left[ r(x, y, y^*) \right] - \tau \text{KL}(\pi_\theta(x) || \pi_{\theta_i}(x)) \right]
$$

其中 $y^*$ 是参考答案，$z$ 是思考过程（CoT），$\tau$ 控制 KL 惩罚强度。

**最终梯度更新公式**：

$$
\frac{1}{k} \sum_{j=1}^{k} \left( \nabla_\theta \log \pi_\theta(y_j, z_j | x) \left( r(x, y_j, y^*) - \bar{r} \right) - \frac{\tau}{2} \nabla_\theta \left( \log \frac{\pi_\theta(y_j, z_j | x)}{\pi_{\theta_i}(y_j, z_j | x)} \right)^2 \right)
$$

公式由两部分组成：

| 组件 | 作用 | 与 GRPO 的对应 |
|------|------|---------------|
| $\nabla_\theta \log \pi_\theta \cdot (r - \bar{r})$ | 奖励驱动：鼓励高奖励策略 | 类似 GRPO 的 z-score 优势（`(r_i - mean)/std`） |
| $-\frac{\tau}{2} \nabla_\theta (\log \frac{\pi_\theta}{\pi_{\theta_i}})^2$ | 正则化驱动：约束策略不跑偏 | 类似 GRPO 的 KL 惩罚项（$-\beta \cdot D_{KL}$） |

**Kimi vs GRPO 的核心差异**：

| 维度 | GRPO (R1) | Kimi k1.5 |
|------|-----------|-----------|
| 优势估计 | z-score 组内归一化：`(r_i - mean)/std` | 简单去均值：`r - r̄`（无 std 除法） |
| KL 形式 | Bregman divergence：`p_ref/p - log(p_ref/p) - 1` | 平方对数比：`(log(p/p_ref))²` |
| 采样策略 | 等概率采样 | 按 `(1 - success_rate)` 加权（困难题更频繁采样） |
| 上下文长度 | 未特殊强调 | 128K，核心卖点 |
| 模态 | 纯文本 | 文本 + 视觉 |

> 💡 **补充（Kimi k1.5 论文 / arXiv 2501.12599）**：Kimi k1.5 的 long-CoT 模型达到 AIME 77.5、MATH 500 96.2、Codeforces 94th percentile，与 o1 相当。其 short-CoT 模型（通过 long2short 蒸馏）达到 AIME 60.8、MATH500 94.6，远超 GPT-4o 和 Claude Sonnet 3.5（最高 +550%）。

#### 1.3 长度控制：不同于 GRPO 偏差的思路

模块 2 中我们分析了 GRPO 的 `1/|o_i|` 偏差——它**隐式地**鼓励长输出。Kimi 则采用**显式长度奖励**直接控制：

$$
\text{len\_reward}(i) = \begin{cases}
    \lambda & \text{若 } r(x, y_i, y^*) = 1 \text{（正确）} \\
    \min(0, \lambda) & \text{若 } r(x, y_i, y^*) = 0 \text{（错误）}
\end{cases}
$$

其中 $\lambda = 0.5 - \frac{\text{len}(i) - \text{min\_len}}{\text{max\_len} - \text{min\_len}}$。

**机制解读**：

```
正确回答（r=1）:
  - 越短 → len(i) 小 → λ 越接近 0.5 → 奖励加成
  - 越长 → len(i) 大 → λ 越接近 -0.5 → 奖励打折
  → 鼓励"用尽量少的 token 答对"

错误回答（r=0）:
  - 越短 → λ 越接近 0.5 → 但 min(0, 0.5) = 0（不加分也不扣分）
  - 越长 → λ 越接近 -0.5 → min(0, -0.5) = -0.5（额外惩罚）
  → 绝不奖励错误长回答，且惩罚"错得啰嗦"
```

这与 Dr. GRPO 的动机一致（消除长度偏差），但实现方式不同：Dr. GRPO 从**梯度层面**移除偏差（改公式），Kimi 从**奖励层面**直接加上长度信号。

**GRPO 长度偏差 vs Kimi 长度奖励对比**：

| 维度 | GRPO 的 `1/\|o_i\|` 偏差 | Kimi 的 `len_reward` |
|---|---|---|
| 作用层 | 梯度归一化（隐式） | 奖励信号（显式） |
| 对正确短回答 | 放大梯度（正面） | 额外奖励（正面） |
| 对错误长回答 | 稀释惩罚（负面） | 额外惩罚（正面） |
| 可控性 | 不可调（由公式决定） | 可调（λ 公式可改） |
| 副作用 | 越错越长 | 可能过早截断有效探索 |

#### 1.4 数据管理：按难度采样

Kimi 的数据管理策略值得关注：

```
RL Prompt Set 三个标准:
  ├── 多样化覆盖：STEM + 代码 + 通用推理，按领域标签均衡
  ├── 平衡难度：用模型自身评估每个 prompt 的难度，过滤过简单题
  └── 精确可评估：排除选择题/判断题/证明题（容易猜对答案产生假阳性）

采样策略:
  问题的采样比例 ∝ (1 - success_rate)
  → 模型已经擅长的题少采样，模型困难的题多采样
  → 等价于"自适应课程学习"
```

此外，对代码任务生成新测试用例防止过拟合，对数学任务训练了 800k 样本的 CoT 奖励模型用于答案等价性检查。

### 2. Qwen 3：思考模式融合

Qwen 3（阿里，2025）的最大创新不是又一个 RL 训练技巧，而是**将"思考"和"不思考"整合到同一个模型中**，让用户动态控制推理预算。

#### 2.1 四阶段后训练流水线

![Qwen3系列模型的后训练管道](<../images/14-25-Qwen3系列模型的后训练管道.png>)

```
Stage 1 — Long-CoT Cold Start
  │  用多样化 long-CoT 数据（数学、代码、逻辑、STEM）做 SFT
  │  目的：让模型获得基本推理能力
  │
  ├─→ Stage 2 — Reasoning RL
  │  使用 GRPO + 规则奖励，大规模 RL 训练
  │  数据：仅 ~4k 个精心筛选的提示（课程提到 3995 条）
  │  注意：这个数量远小于 R1 的数据规模，说明数据质量 > 数量
  │
  ├─→ Stage 3 — Thinking Mode Fusion（核心创新）
  │  混合训练：long-CoT 数据 + 标准指令调优数据
  │  数据来自 Stage 2 的增强模型生成
  │  目的：让同一个模型既能"深思熟虑"也能"快速响应"
  │
  └─→ Stage 4 — General RL
      在 20+ 通用领域任务上做 RL（指令遵循、格式遵循、Agent 能力等）
      目的：修正不需要的行为，增强通用能力
```

> 🌐 **补充（Qwen 3 博客 / qwenlm.github.io）**：Qwen3-235B-A22B 在代码、数学、通用能力上与 DeepSeek-R1、o1、o3-mini、Grok-3、Gemini-2.5-Pro 等顶级模型竞争。小型 MoE 模型 Qwen3-30B-A3B 以 10 倍激活参数的优势超越 QwQ-32B。

#### 2.2 思考模式融合的 SFT 数据设计

![思考模式融合阶段的SFT数据示例](<../images/14-26-思考模式融合阶段的SFT数据示例.png>)

核心做法：在同一个 SFT 数据集中混合两类样本：

```
类型 1：带 <think> 标签的思考数据
  用户: "证明 sqrt(2) 是无理数"
  助手: "<think>假设 sqrt(2)=p/q... [长推理过程] ...因此矛盾。证明完毕。</think>
        因此，sqrt(2) 是无理数。"

类型 2：不带 <think> 标签的直接回答数据
  用户: "你好，今天天气怎么样？"
  助手: "你好！今天天气晴朗，适合出门活动。"
```

模型从混合数据中学习到：**是否使用 `<think>` 取决于问题类型**——复杂推理问题需要思考，简单闲聊直接回答。

#### 2.3 思考预算控制（Thinking Budget Control）

思考模式融合带来了一个"意外收获"：模型能处理**截断的思考过程**。

```
机制:
  ① 用户设置思考预算上限（如 4096 tokens）
  ② 模型开始 <think> 推理
  ③ 当思考 token 数达到预算上限时，系统插入:
     "考虑到用户的时间有限，我必须直接根据思考给出解决方案。\n</think>\n\n"
  ④ 模型基于已积累的不完整推理直接输出最终答案
```

**关键**：这个截断响应能力不是显式训练的——是思考模式融合的自然产物。因为模型在训练中见过了各种长度的混合数据，它学会了"在任何思考深度被截断时，都能基于当前进度给出合理答案"。

![Qwen3-235B-A22B随thinking budget的性能表现](<../images/14-27-Qwen3-235B-A22B随thinking budget的性能表现.png>)

上图展示了 Qwen3-235B-A22B 在不同思考预算（Thinking Budget）下的 Pass@1 性能：

- **单调递增但不线性**：预算从 0 增加到 4K tokens 时性能跃升最陡，4K → 8K 继续增长但边际递减
- **不同任务敏感度不同**：AIME（数学竞赛）从思考中获益最大，GPQA Diamond（科学推理）次之
- **非思考模式（Non-Thinking mode）** 作为基线，在简单任务上已足够

#### 2.4 用户端的模式切换

Qwen 3 提供了两种控制方式：

**硬切换（Chat Template）**：
```python
# enable_thinking=True → 思考模式（默认）
# enable_thinking=False → 非思考模式
text = tokenizer.apply_chat_template(
    messages,
    enable_thinking=True  # 或 False
)
```

**软切换（Prompt 内指令）**：
```
用户: "这道微积分题怎么解？ /think"     → 触发思考模式
用户: "今天天气怎么样？ /no_think"       → 触发非思考模式
```

`/think` 和 `/no_think` 可在多轮对话中动态切换，模型遵循最近一次指令。

#### 2.5 不同训练阶段的效果贡献

![Qwen3-32B在不同阶段的性能](<../images/14-28-Qwen3-32B在不同阶段的性能.png>)

课程图 14-28 展示了 Qwen3-32B 在各后训练阶段的性能变化：

- **SFT 冷启动**：打下基本推理能力
- **Reasoning RL**：数学/STEM 能力大幅跃升（主要增益来源）

### 3. 三个案例的并排对比

| 维度 | DeepSeek-R1 | Kimi k1.5 | Qwen 3 |
|------|------------|-----------|--------|
| **RL 算法** | GRPO（组内 z-score） | 自研策略梯度（DPO-style 推导） | GRPO |
| **价值网络** | 无 | 无 | 无 |
| **MCTS/PRM** | 尝试后放弃 | 从未使用 | 未使用 |
| **冷启动** | 数千条 long-CoT + 人类后处理 | Long-CoT SFT（prompt 工程引导） | Long-CoT Cold Start SFT |
| **RL 数据规模** | 未公开（大） | 未公开（大） | **仅 ~4k 条** |
| **长度控制** | 无（依赖 GRPO 的隐式偏差） | 显式 len_reward 公式 | 思考预算上限 + 截断 |
| **多模态** | 否 | 是（文本 + 视觉） | 否 |
| **核心创新** | 纯 RL 涌现推理 | 长上下文 RL + 长度控制 | **思考模式融合 + 预算控制** |
| **蒸馏** | R1 → 小模型（800k 数据 SFT） | long2short 蒸馏 | 强到弱蒸馏 |

**共同规律**：

1. **三种模型都放弃了 MCTS/PRM**——简单 RL 胜于复杂方法
2. **冷启动 SFT + RL 成为标准范式**——纯 RL（R1-Zero）证明可行，但冷启动 SFT 提升了可读性和稳定性
3. **长度控制是共同的工程挑战**——GRPO 有偏差、Kimi 有 len_reward、Qwen 有预算截断，三种不同解法
4. **数据质量压倒数量**——Qwen 3 只用 ~4k RL 提示就达到顶级性能
5. **RLHF 对齐与推理能力之间存在 tradeoff**——R1 和 Qwen 3 都在最终对齐阶段观察到了推理能力的轻微退化

**Q1**：Kimi k1.5 的梯度更新公式中，去掉了 GRPO 的 `1/std` 除数（用 `r - r̄` 代替 z-score），同时用平方对数比代替 Bregman divergence 作为 KL 正则化。请分析：(a) 去掉 `1/std` 与 Dr. GRPO 的动机是否一致？(b) 平方对数比 KL：`(log π_θ/π_ref)²` 与 GRPO 的 Bregman KL：`π_ref/π_θ - log(π_ref/π_θ) - 1` 在约束行为上有何不同？

**A1**：

a) 去掉 `1/std` 应该与 Dr.GRPO 的动机不一致，因为 Kimi k1.5 中加入了 长度控制：对于 对了 的结果，越短奖励保持，越长奖励减半；对于 错了 的结果，也是越短惩罚保持，越长惩罚加倍。因此 `1/std` 应该不是为了与 Dr.GRPO 一致，只是刚好不需要这一项控制长度趋势

b) 平方对数比 KL 和 Bregman KL 两周约束行为上的不同，其实更多是根据公式的不同：两者都是希望优化得到 `π_ref`  近似 `π_θ`，因此在两个 KL 约束上最优解都是 `π_θ = π_ref `, 但是 平方约束会让 分布偏离较大时，加大惩罚力度。而 Bregman KL，则更平缓。


**A2**：

Qwen3 的 "思考模式融合" 相当于将 "是否思考" 通过 "硬编码" 的形式，encode 入模型的能力中去。通过格式和数据的约束，在 sft 阶段让 模型具备这个能力（选择 think 或者 no-think）。

如果通过 prompt 来约束，不是"硬编码"，需要模型自己具有这个推理能力，在模型都是通过 <think><answer>约束的情况下，模型无法去产生新的格式输出，因此可能做不到 "不思考"（也即是无法稳定切换）。


**A3**：

1. GRPO 隐式的 `1/\|o_i\|` 从梯度层面解决：通过将 reward 按照 token 平均，消除 token 越多 reward 越大的问题。好处是确实能解决 length 和 reward 的问题，劣势就是根据 token 做了平均，token 越长 loss 越低，会形成 越错越啰嗦；
2. kimi 的 len_reward：从奖励层进行了优化，鼓励对了少说；惩罚错了多说。但是 Qwen 3 有研究表明，think 越长正确率越高，因此对了少说不是个好的奖励机制；
3. Qwen3 的思考模式截断：降低了推理成本，当推理过长则直接截断根据当前 think 步骤生成对应的结果。在推理端是个好的优化，将推理成本控制在一定范围内，但是对于复杂任务，长程任务，think 需要的很长，这不是一个好的优化目标

### 📝 批改结果

**Q1 批改**：(a) 的核心推理方向有误——你将 `1/std` 和 `1/|o_i|` 混淆了。`1/std` 移除处理的是**难度偏差**（低方差问题被过加权），而非长度偏差。Dr. GRPO 和 Kimi 在两个偏差上的立场是：`1/std` 都移除（一致），长度偏差处理方式不同（Dr.GRPO 移除 `1/|o_i|`，Kimi 用 len_reward）。(b) 方向正确——平方形式对大幅偏离惩罚更重，但缺少梯度层面的分析：Bregman KL 的梯度随 `π_θ/π_ref` 线性增长，平方对数比的梯度包含 `(log ratio) × (1/π_θ)` 项，在 π_θ 很小时梯度会爆炸。 — 得分：5.5/10

|--------|-----------|---------|------|
| `1/\|o_i\|`（长度归一化） | 长回答 token 惩罚被稀释 → 越错越长 | 移除 | 保留（但用 len_reward 对冲） |
| `1/std`（标准差归一化） | 低方差问题（太简单/太难、std≈0.1）获得极大更新权重 | 移除 | 移除（用 `r - r̄` 替代 z-score） |

**两者的交集在 `1/std`**：Dr. GRPO 指出 `1/std` 会让简单判断题（std 小）的梯度权重远大于困难计算题（std 大），导致模型在"最没有学习价值的题"上花最多算力。Kimi 使用 `r - r̄`（无 std 除法）恰好避免了这个问题——与 Dr. GRPO 的动机**完全一致**。

你提到的"Kimi 有 len_reward 所以不需要 `1/std` 控制长度"是一个范畴错误——`1/std` 和长度无关，它影响的是**问题间的权重分配**。len_reward 影响的是**回答内的长度激励**。两者作用于不同维度。

结论：Kimi 和 Dr. GRPO 都发现了 `1/std` 的问题并移除了它。Kimi 额外用 len_reward 替代了 `1/|o_i|` 的角色（但方向相反——从"稀释错误惩罚"变为"主动惩罚错误长回答"）。

**(b) 平方对数比 vs Bregman divergence 在约束行为上的不同**

**形式对比**：

```
Bregman KL:
  D_Bregman = π_ref/π_θ - log(π_ref/π_θ) - 1

  梯度: ∂D/∂π_θ = -(π_ref/π_θ²) + 1/π_θ = (π_θ - π_ref)/π_θ²
       → 包含 1/π_θ² 项，当 π_θ → 0 时梯度 ∝ -1/π_θ²（爆炸，且比平方对数比更剧烈）
       → 高度不对称：π_θ ≪ π_ref 时惩罚远大于 π_θ ≫ π_ref

平方对数比:
  D_sq = (log π_θ - log π_ref)² = (log(π_θ/π_ref))²

  梯度: ∂D_sq/∂π_θ = 2·log(π_θ/π_ref)·(1/π_θ)
       → 同样包含 1/π_θ 项，当 π_θ 很小时梯度也很大
       → 但在 log 空间对称：偏高和偏低的惩罚结构一致
```

**行为差异的数值推演**：

假设 `π_ref = 0.1`（参考策略在某个 token 上的概率）：

| 当前 π_θ | 偏离程度 | Bregman 值 | 平方对数比值 | 梯度比 |
|----------|---------|-----------|------------|--------|
| 0.1 | 无偏离 | 0 | 0 | - |
| 0.2 | 2× 偏高 | 0.19 | 0.48 | Bregman 梯度 ≈ 2.5，对数比梯度 ≈ 6.9（~3×） |
| 0.5 | 5× 偏高 | 0.79 | 2.59 | Bregman 梯度 ≈ 8，对数比梯度 ≈ 6.4（相当） |
| 0.01 | 10× 偏低 | 4.10 | 5.30 | Bregman 梯度 ≈ 890，对数比梯度 ≈ 920（相当） |
| 0.001 | 100× 偏低 | 49.0 | 21.2 | Bregman 梯度 ≈ 99k，对数比梯度 ≈ 9.2k（Bregman 更大！） |

**核心差异解读**：

1. **对称性**：平方对数比是对称的——`π_θ` 偏高（0.5 vs 0.1）和偏低（0.001 vs 0.1）的惩罚大致对称（在 log 空间）。Bregman 高度不对称——`π_θ ≪ π_ref` 时惩罚急剧放大（概率崩塌方向的极端惩罚）。

2. **梯度爆炸风险**：两种 KL 都包含 `1/π_θ` 因子（Bregman 甚至包含 `1/π_θ²`），因此在 π_θ → 0 时梯度都会爆炸。Bregman 的爆炸更剧烈（二次方 vs 一次方），因此 Bregman 对"概率崩塌"的惩罚更严厉。实践中 LLM 的 token 概率很少真正降到 `1e-6` 以下（词汇表大，概率分散），这个风险在 LLM 场景中相对可控。

3. **Bregman 的"破产保护"**：Bregman 在 π_θ 极小（概率崩塌）时惩罚极大（梯度 ∝ 1/π_θ²），这在 RL 训练中扮演了"破产保护"——防止模型彻底忘记某些 token 的可能性。平方对数比在这个区域的保护较弱（梯度 ∝ 1/π_θ，仅随概率倒数线性增长）。

4. **实践选择**：两种 KL 形式在实践中效果接近（参见 Kimi 论文的消融），Kimi 选择平方对数比主要是推导方便（从 DPO 框架自然导出），而非性能优势。

</details>

**为什么不能仅靠 prompt 让 R1 "不思考"？**

有三层原因，从浅到深：

**第一层：格式层面的惯性**

R1 在训练中始终被格式奖励约束——必须输出 `<think>...</think><answer>...</answer>`。模型的生成分布已深度适配这个格式。即使用 prompt 说"不要思考，直接回答"，模型的首 token 分布仍然强烈偏好 `<think>`——因为在整个 RL 训练中，不以 `<think>` 开头的序列从未获得过正奖励。少数情况下模型可能碰巧跳过 `<think>` 直接输出，但这是低概率事件，不可靠。

**第二层：优化信号层面的盲区（更根本）**

R1 的训练信号全部来自**有 `<think>` 的推理过程**：

```
R1 训练的奖励结构:
  accuracy_reward: 检查 <answer> 是否正确
  format_reward: 检查是否有 <think>...</think> + <answer>...</answer>
  
模型学到的优化路径:
  <think> → [推理] → </think> → <answer> → [答案] → </answer>
  ↑ 整套流程被联合优化
```

如果强行 prompt 模型跳过 `<think>`：
- 模型需要在一个**从未被奖励过的行为空间**中运作（无 `<think>` 的直接回答）
- 它的内部表征（hidden states, attention patterns）从未在"直接回答数学题"的场景下被优化过
- 结果：要么格式错误（仍然输出 `<think>`），要么答案质量崩溃（因为缺少了模型赖以推理的中间步骤）

类比：一个训练了十年的围棋选手，你突然要求他"看一眼棋盘就落子，不要思考"——他可以做到，但他的棋力会坍缩到远低于训练水平。

**第三层：条件生成能力缺失**

思考模式融合训练的本质不是"硬编码两个模式"，而是让模型学会**条件生成**：

```
融合训练后的模型内部逻辑:
  if prompt contains /no_think or enable_thinking=False:
    → 跳过 <think>，直接生成 <answer>
    → 使用经过 SFT 优化的"快速响应"通路
  else:
    → 正常 <think> → <answer> 流程
    → 使用 RL 优化的"深度推理"通路
```

这个条件分支是通过 SFT 数据中的**共现模式**学到的——模型在训练中反复看到"`/no_think` + 直接回答"和"`/think` + 长推理"两种模式，学会了将标签作为行为开关。

R1 没学过这个——它的训练数据中不存在"不带 `<think>` 的正确回答"的示例，因此没有发展出这个条件生成能力。

**为什么"融合训练是必要的"——三句话总结**：

1. R1 的 RL 信号**只奖励有 `<think>` 的输出**——"不思考"行为从未被正强化过。
2. R1 的**内部表征**围绕 think-then-answer 优化——跳过 think 意味着模型在从未优化过的表征空间中运作。
3. 融合 SFT 提供了**两种模式的共现数据**，让模型学会将标签作为条件信号——这不是 prompt 能事后补救的，因为条件生成是分布内（in-distribution）能力，需要训练时暴露。

**适用场景分析**：

**GRPO `1/|o_i|` 偏差**：

- ❌ 任何场景都不应该保留——这不是一个"设计选择"，而是一个被识别出的缺陷。Dr. GRPO 论文已经证明移除它能提升训练效率和效果。
- 唯一"勉强可接受"的场景：初期训练，模型还在学习基本格式，需要长度偏差来鼓励尝试更多 token。但即使此时，也应该使用温和的显式长度奖励（如 Kimi 方案）而非隐式偏差。

**Kimi `len_reward`**：

- ✅ 适用：训练阶段需要精细控制"效率 vs 正确率"平衡。λ 可调：加大 len_reward 权重 → 更鼓励简洁；减小 → 更鼓励探索长推理。
- ✅ 适用：评估指标包含 token 效率的场景（如生产部署，每 token 都有成本）。
- ❌ 缺陷 1：你提到的"思长正确率越高"确实是个问题。但这可以通过调整 λ 缓解——λ 接近 0 时 len_reward 几乎无效，模型自由探索长推理。更优雅的做法是将 λ 设为递减——训练早期 λ 小（鼓励探索），后期 λ 大（鼓励收敛到高效策略）。
- ❌ 缺陷 2：需要额外调参（λ 的范围、min_len/max_len 的设定），增加了实验负担。
- ❌ 缺陷 3：λ 是全局参数，无法针对不同难度的问题差异化——简单题应该严格限制长度，难题应该放宽。Kimi 的采样策略（按难度加权）部分缓解了这点，但未在奖励层面区分。

**Qwen 3 思考预算截断**：

- ✅ 适用：用户对推理延迟/成本有不同需求。同一个模型，简单场景给 512 token 预算，复杂场景给 8192 token 预算——无需重新训练。
- ✅ 适用：A/B 测试不同预算对用户体验的影响——直接改推理参数即可。
- ✅ 独特优势：是唯一一个**训练后可控**的方案。模型训练完成后，预算可以在推理时动态调整——GRPO 和 Kimi 的方案都在训练时"烧入"模型参数中。
- ❌ 缺陷 1：你说的"长任务不适用"精确——对于需要极长推理链的任务（如 IMO 级数学证明、复杂代码架构设计），硬截断可能打断关键推理步骤。不过 Qwen 3 的截断并非简单 `truncate`，而是插入"时间有限，请基于当前进度给出答案"的提示，模型能在一定程度上进行"紧急收尾"。
- ❌ 缺陷 2：截断是"生硬"的控制——token 数 ≠ 推理质量。一个聪明的 500-token 推理可能比冗长的 5000-token 推理更有效。纯按 token 数截断无法区分"有效思考"和"水字数"。
- ❌ 缺陷 3：预算控制要求模型具备"在任意深度被截断后能给出合理答案"的能力，这依赖于思考模式融合训练。对于没有经过融合训练的纯推理模型（如 R1），插入截断指令后可能输出混乱或不完整的答案。
