## 核心内容

### 1. R1-Zero：纯强化学习的推理涌现

DeepSeek R1 最令人震惊的发现是：**不需要 SFT，直接在 Base 模型上跑 GRPO，推理能力会自行涌现。**

#### 1.1 实验设置

来自 [DeepSeek-R1 论文](https://arxiv.org/abs/2501.12948)（2025）：

```
基座模型: DeepSeek-V3-Base（预训练模型，未经过任何 SFT）
算法: GRPO（组内 z-score 优势）
奖励:
  ├── accuracy reward: 答案对/错（规则匹配或编译器验证）
  └── format reward: 必须用 <think>...</think>\n<answer>...</answer> 格式
数据: 未公开（仅说明使用了可验证的数学/代码问题）
```

> 这与 R1-Zero 的命名逻辑一致——"Zero"表示**零人工标注**、**零 SFT 冷启动**，纯粹从 RL 信号中学习。

#### 1.2 训练曲线揭示的涌现过程

![DeepSeek-R1-Zero 在训练期间的 AIME 准确率和平均响应长度](<../images/14-10-DeepSeek-R1-Zero在训练期间的AIME准确率和在训练集上的平均响应长度.png>)

两条曲线的互动是理解 R1-Zero 的关键：

| 训练阶段 | AIME 准确率 | 平均响应长度 | 发生了什么 |
|---------|-----------|------------|----------|
| 早期（~0-2k steps） | ~15% → 逐步上升 | 平稳或缓增 | 模型在学基本格式，正确率低 |
| 中期（~2k-6k steps） | 快速跃升 | **显著增长** | 模型发现"多思考几步 → 正确率更高" |
| 后期（~6k+ steps） | 持续提升至 ~71% | 持续增长 | 自反思、验证等复杂策略出现 |

**核心洞察**：响应长度不是被强制拉长的——是模型**自发**学会了"思考越久，对的概率越大"。这是涌现（emergence），不是工程设定。

#### 1.3 "Aha Moment"：模型学会自我纠错

![Aha Moment 的发现](<../images/14-11-aha-moment的发现.png>)

R1-Zero 在训练中途出现了一个显著的行为变化——模型开始使用"等等"（wait）来标记自我纠错：

```
模型输出示例:
  "第一步：计算 x = 3 + 5 = 8
   第二步：代入公式...等等，我算错了。应该用 3×5=15，不是加法。
   第三步：重新计算..."
           ↑ "等等" = 模型自我检测到错误并修正
```

论文统计了"等等"的使用频率——在某个训练节点突然飙升，说明模型**自主习得**了反思能力，而非从人类示范中学来。

#### 1.4 冷静看待：Aha Moment 的真实性

课程指出了一些使"aha moment"不那么神奇的事实：

- **Base 模型已有反思能力**：DeepSeek-V3-Base 在未经 RL 训练时，偶尔也会展示自我纠错行为（见下图）。RL 训练只是**放大**了这种已有能力，而非从零创造。

![DeepSeek-V3-Base 早已展现 aha moment](<../images/14-12-DeepSeek-V3-Base早已展现出aha-moment现象案例.png>)

- **长度偏差的助攻**：模块 2 中分析的 `1/|o_i|` 偏差天然鼓励模型生成更长的输出。R1-Zero 使用原始 GRPO（有偏版本），响应长度的增长部分来源于算法的隐性激励，而非完全"自发涌现"。

- **格式奖励的引导**：`<think>` 标签强制模型在输出最终答案前先写思考过程，这本身就在结构上鼓励了"多步推理"。

> 💡 **关键教训**：RL 在这个场景中的角色不是"教模型推理"，而是**提供环境压力**——只奖励正确答案，模型为适应环境而自行发现并强化有效的推理策略。

### 2. DeepSeek-R1：从 Zero 到生产可用

R1-Zero 虽强，但有两大硬伤：**可读性差**和**语言混合**（中英混杂）。DeepSeek-R1 引入多阶段训练来解决这些问题。

#### 2.1 四阶段流水线全景

![DeepSeek-R1 开发流程](<../images/14-13-Deepseek-R1开发流程.png>)

```
Stage 1 ─── R1-Zero
│  DeepSeek-V3-Base + GRPO (纯 RL)
│  产出: 有推理能力但不可读的模型
│
├─→ Stage 2 ─── 冷启动 + RL
│   │  ① 用 R1-Zero 生成数千条高质量 long-CoT 回答
│   │  ② 人工筛选 + DeepSeek-V3 精炼（解决语言混合）
│   │  ③ 用这些"冷启动数据"对 V3-Base 做 SFT → R1-Dev1
│   │  ④ 在 R1-Dev1 上继续 GRPO（加入语言一致性奖励）→ R1-Dev2
│   │
│   ├─→ Stage 3 ─── 大规模 SFT
│   │  ① 从 R1-Dev2 拒绝采样: 600k 推理相关样本
│   │  ② DeepSeek-V3 pipeline: 200k 非推理样本（写作、翻译等）
│   │  ③ 用 800k 数据对 V3-Base 做 SFT → R1-Dev3
│   │
│   └─→ Stage 4 ─── 全场景 RL
│       推理数据: rule-based reward (accuracy + format)
│       通用数据: Reward Model (helpfulness + safety)
│       → 最终 DeepSeek-R1
```

#### 2.2 各阶段的设计意图

**Stage 1 → Stage 2：解决"说什么语言"的问题**

R1-Zero 的输出经常中英混杂（V3-Base 在双语数据上预训练）。Stage 2 的冷启动数据通过一个巧妙的 prompt 解决：

```
"Translate the thinking process to the same language as the question."
```

→ 模型学会用与问题一致的语言推理。

**Stage 2 → Stage 3：解决"不只是推理"的问题**

R1-Dev2 只会推理，不会写文章、翻译、聊天。Stage 3 的 800k SFT 数据中 200k 是非推理数据——让模型在保持推理能力的同时恢复通用能力。

**Stage 3 → Stage 4：解决"通用任务的奖励信号"问题**

对于写作、翻译等开放任务没有规则验证器。Stage 4 的通用数据部分回退到传统 RLHF——用 Reward Model 评估 helpfulness 和 safety。

#### 2.3 最终性能

![DeepSeek-R1 和其他模型的比较](<../images/14-15-DeepSeek-R1和其他模型的比较.png>)

DeepSeek-R1 在大多数推理基准上与 OpenAI o1-1217 性能相当。

### 3. 蒸馏：大模型的推理能力可以传给小模型

R1 的另一个重要贡献是证明了**推理能力可蒸馏**。

![DeepSeek-R1 蒸馏模型和其他模型的比较](<../images/14-16-Deepseek-R1蒸馏模型和其他模型的比较.png>)

```
方法: 用 DeepSeek-R1 生成 800k 条带 long-CoT 的回答
      → 对 Qwen2.5-7B/14B/32B 等小模型做 SFT
      → 学生模型学会教师模型的推理模式

结果: 蒸馏后的 Qwen2.5-32B 性能显著超越原版 Qwen2.5-32B，
      甚至接近一些更大的模型
```

> 蒸馏 ≠ 训练小 R1。蒸馏是行为克隆——学生学的是"教师怎么想"，而非"RL 环境如何反馈"。这比从头训练一个小 R1 便宜得多，但不一定泛化到教师没见过的领域。

---

### 4. 极简路线：少量高质量 SFT 样本也能出推理能力

除了 RL 路线，两篇同期工作证明了一条更简单的路——**高质量 long-CoT 数据 + SFT**：

| 工作 | 数据量 | 基座模型 | 核心方法 | 效果 |
|------|--------|---------|---------|------|
| [s1](https://arxiv.org/abs/2501.19393)（李飞飞团队） | **1,000 条** | Qwen2.5-32B-Instruct | 精心筛选的 long-CoT 数据 + SFT | 超越 o1-preview（数学） |
| [LIMO](https://arxiv.org/abs/2502.03387)（上交刘鹏飞团队） | **817 条** | Qwen2.5-32B-Instruct | 高质量多样本筛选 + SFT | 大幅提升数学推理 |

**共同发现**：
- 数据质量 >> 数据数量：1k 精选远超 50k 随机
- 需要强基座模型：Qwen2.5-7B 和 3B 上用同样方法效果显著下降
- 关键是"长思维链"的完整性和正确性——不是所有 long-CoT 都有效

> 🌐 **补充（Web Search / s1 论文）**：s1 的数据筛选标准极为严格——从多个来源的 59,029 道题中，经过质量检查、难度过滤（移除模型不经 CoT 就能答对的题）、多样性采样，最终保留 1,000 条。筛选过程中 Claude 3.5 Sonnet 被用于评估推理正确性。

### 5. 不成功的尝试：PRM 与 MCTS

DeepSeek 团队坦诚分享了他们在 R1 开发早期探索过但**失败**的两条路径——这些"负面结果"对社区的参考价值不亚于成功经验。

#### 5.1 过程奖励模型（PRM）—— 为什么放弃了？

PRM 试图对推理的**每个中间步骤**打分（而非只看最终答案），理论上可以解决 GRPO 的"同享优势"问题（模块 1 Q3）。

**三个失败原因**：

| 问题 | 具体表现 |
|------|---------|
| **步骤定义难** | 什么算一个"中间步骤"？数学推理中可能是每行等式，代码生成中可能是每行代码，但难以给出跨领域的通用定义 |
| **标注不可靠** | 自动标注中间步骤正确性不可靠（模型自己判断自己），人工标注成本太高且难以规模化 |
| **奖励黑客** | 一旦引入基于模型的奖励（PRM 自己也是模型），模型可能找到"骗 PRM"的路径——奖励不再是客观的可验证信号 |

> 核心矛盾：PRM 试图用"另一个模型"来提供更精细的 RL 信号，但这恰好违背了 RLVR 的核心前提——**奖励必须是可验证的、非模型的**。

#### 5.2 蒙特卡洛树搜索（MCTS）—— 为什么放弃了？

受 AlphaGo 启发，探索用 MCTS 在 token 生成过程中搜索最优推理路径。

**两个失败原因**：

1. **搜索空间指数爆炸**：围棋的搜索空间虽大但有结构（19×19 棋盘），token 生成的搜索空间是 `|vocab|^seq_len`，每个 token 有 ~128k 个选择。即使限制每步扩展数，也容易陷入局部最优。

2. **价值网络难训练**：MCTS 需要价值网络指导搜索方向，但训练一个细粒度的 token 级价值网络本身就极其困难，且会引入 PRM 同样的奖励黑客问题。

> 关键教训：AlphaGo 的成功依赖于"完美的环境模拟器 + 明确的价值信号"，而 LLM 推理缺乏这两个条件。**简单粗暴的 GRPO 反而比这些复杂方法更有效。**

### 6. 关键教训总结

| 教训 | 来源 | 含义 |
|------|------|------|
| RL 本身足以激发推理 | R1-Zero | 不需要标注推理步骤，只需奖励正确答案 |
| 冷启动数据解决可读性 | R1 Stage 2 | RL 关注"对不对"，SFT 关注"好不好读" |
| 800k SFT 恢复通用能力 | R1 Stage 3 | 推理 RL 会损害通用能力，需要混合数据弥补 |
| 蒸馏有效但依赖教师 | R1 蒸馏 | 小模型可以学大模型的推理模式 |
| 1k 精选 > 50k 随机 | s1/LIMO | 数据质量压倒数量——在推理领域尤为明显 |
| PRM 和 MCTS 都失败了 | R1 失败经验 | 复杂方法在 LLM 推理中不一定有效；保持奖励信号简单 |
| 基座模型质量决定上限 | s1/LIMO | Qwen2.5-7B 用同样方法效果差很多——推理能力的天花板由预训练决定 |

<details>
<summary>📖 Q1 参考答案</summary>

**三个因素各自的贡献：**

**(a) Base 模型已有反思能力 — 提供了"可被放大的种子"**

这是最根本的因素。DeepSeek-V3-Base 在未经任何 RL 训练时，偶尔也会展示自我纠错行为（课程图 14-12 已证实）。RL 的角色不是"教模型反思"，而是**提供环境压力**（只奖励正确答案），让模型在试错中自行发现"反思 → 正确率更高"这个因果链，从而**放大**已有的反思行为。

关键区分：如果 Base 模型完全没有反思能力（如一个极小的、未经充分预训练的模型），GRPO 再跑多少步也涌现不出反思——涌现的前提是能力已在预训练中隐式存在。

**(b) GRPO 的长度偏差 — 降低了"多思考几步"的代价**

原始 GRPO 的目标函数中，每个回答的 loss 要除以 `len(o_i)`（回答长度）：
```
loss_i = (1/|o_i|) × Σ_t [policy_loss at token t]
```

这意味着：**长回答中每个 token 对 loss 的贡献更小**。当一个 token 被加入长回答时，它对整体 loss 的"拖累"比加入短回答时小。这创造了一个隐性激励：模型倾向于生成更长的输出，因为长输出中每个 token 的"犯错成本"更低。

这个偏差不是故意设计来鼓励反思的——它是一个数学上的副作用。但它的效果是：模型更愿意"多说几句"，而多说几句恰好给了反思行为更多的"表达空间"。一个 token 的"等等，我刚才算错了"在短回答中会被压缩掉，在长回答中才有空间出现。

**(c) 格式奖励 — 创造了"安全探索空间"**

`<think>...</think><answer>...</answer>` 的格式要求做了一件关键的事：**把"思考"和"作答"分离**。准确性奖励只检查 `<answer>` 部分，`<think>` 部分的内容不被直接评估。这相当于告诉模型："在 `<think>` 里你可以随意尝试，写错了也不扣分，只要最终 `<answer>` 正确就行。"

这个"安全探索空间"是反思行为涌现的关键孵化器——如果每个 token 都被直接评估正确性，模型就不敢在思考过程中"承认错误"（因为承认错误本身就是一个"正确性扣分"的风险点）。

**如果去掉 (b) 和 (c)，模型还能自发产生反思行为吗？**

答案：**可能，但有额外的障碍。**

去掉 (b) — 改用 Dr.GRPO（无 `1/|o_i|` 偏差）：
- 短回答和长回答在梯度上等权竞争。对于"直接给答案"和"先想三步再给答案"两种策略，如果二者正确率相同，模型没有额外激励去选后者。
- 反思行为的收益（正确率提升）仍然存在，但模型需要更多样本来"发现"长链推理的价值——因为每个 token 的权重相同，长回答中的反思步骤必须通过"提高正确率"来证明自己的存在价值，而不能靠长度偏差"搭便车"。
- **结论**：反思仍可能出现，但涌现速度可能更慢，且更容易被短平快的"捷径策略"压制。

去掉 (c) — 无格式强制：
- 最大的问题不是"模型不会反思"，而是**答案提取变难**。如果模型输出中没有结构化的 `<answer>` 标签，规则验证器可能无法可靠地提取最终答案 → 正确性奖励信号变噪声 → RL 优化的目标函数本身被污染。
- 其次，没有了"安全探索空间"，模型在思考过程中如果写了错误内容，可能会被错误地当作"最终答案"来评估，产生假阴性奖励。
- **结论**：反思能力本身不依赖格式标签，但**可靠的奖励信号**依赖格式标签来定位"最终答案"。去掉格式强制后，RL 训练的稳定性会大幅下降。

**综合判断**：三因素中 (a) 是必要条件，(b) 和 (c) 是加速器和稳定器。去掉 (b)(c) 后反思仍可能出现（因为 (a) 仍在），但训练的样本效率会显著降低，且奖励信号的噪声会增加。这不是"多跑几步"能简单弥补的——如果奖励信号本身被噪声污染（因无法可靠提取答案），再多的迭代也是在优化错误的目标。

</details>

<details>
<summary>📖 Q2 参考答案</summary>

**为什么需要 Stage 2？**

R1-Zero 有两大硬伤，使得它无法直接进入 Stage 3 的大规模数据生产：

1. **可读性差**：R1-Zero 的输出缺乏结构化的思考格式，人类（甚至自动化流程）难以理解其推理过程。

2. **语言混合（Language Mixing）**：这是最具体、最严重的问题。DeepSeek-V3-Base 在中英双语数据上预训练，R1-Zero 的纯 RL 训练没有引入任何语言偏好的信号 → 模型输出的思考过程中经常中英混杂。例如：一个英文数学题，模型会在 `<think>` 中一会儿用英文推理、一会儿跳到中文、再跳回来。

Stage 2 的冷启动数据通过一个巧妙的 prompt 解决了语言混合：
```
"Translate the thinking process to the same language as the question."
```
这让模型学会**用与问题一致的语言进行推理**——英文题用英文思考，中文题用中文思考。

**Stage 2 为什么是"冷启动 SFT"而非"继续 RL"？**

RL 的本质是"奖励正确答案"——它关心的是 `对不对`，而不是 `好不好读` 或 `用什么语言思考`。在 R1-Zero 上继续 RL 可以进一步提升正确率，但无法解决可读性和语言混合问题，因为这些与正确性无关。需要 SFT（监督微调）直接告诉模型"好的输出应该长什么样"。

**如果跳过 Stage 2 直接在 R1-Zero 上做 Stage 3，会发生什么？**

Stage 3 的核心操作是**拒绝采样**（rejection sampling）：用当前模型对大量 prompt 生成多个回答，只保留 `答案正确 + 格式合规` 的那些，用作 SFT 训练数据。

跳过 Stage 2 后的恶性循环：

```
R1-Zero 输出混乱（语言混合、格式不规范）
        ↓
拒绝采样时，自动化流程难以可靠地提取 <answer> 部分
（因为格式不规范，规则解析器经常失败）
        ↓
两种情况，都很糟糕：
  ├── 保守策略：提取失败的回答全部丢弃
  │   → 拒绝率极高 → 需要生成海量样本才能凑够 600k
  │   → 计算成本爆炸
  │
  └── 宽松策略：降低提取标准，接受有歧义的提取结果
      → 可能把"格式错但答案碰巧对"的样本标记为正确
      → 或把"格式错导致提取错误、实际答案正确"的样本标记为错误
      → SFT 数据质量崩溃
        ↓
用这种低质量数据做 SFT → 模型学到的推理模式本身就是混乱的
        ↓
600k 低质量推理 SFT + 200k 非推理 SFT → 最终模型继承了混乱
```

**核心教训**：Stage 2 的冷启动 SFT 虽然数据量小（仅数千条），但它解决了**数据生产流水线的质量控制问题**。只有先让模型学会"规范地输出"，后续的自动化拒绝采样才能可靠运行。这是一个典型的"磨刀不误砍柴工"——少量高质量 SFT（Stage 2）为大规模自动化数据生产（Stage 3）奠定了基础。

**补充**：即使退一步说，在 R1-Zero 上直接做大规模 SFT 可以不经过拒绝采样（即使用预存的 800k 外部数据），也会有问题：外部数据的推理风格与 R1-Zero 的推理风格不一致 → SFT 会覆盖掉 RL 阶段获得的推理能力（灾难性遗忘的一个变体）。Stage 2 的冷启动数据虽然经过了人类后处理，但推理内容来自模型生成（R1-Zero + few-shot 提示）→ 风格与 RL 阶段一致 → SFT 在"修正格式"的同时保留了 RL 学到的推理模式。

> 📝 **冷启动数据的实际来源（论文 2.3.1 节）**：并非单一来源。论文列出了四种收集方式：① 用 long CoT 做 few-shot 示例让模型模仿生成；② 直接 prompt 模型生成带反思和验证的详细回答；③ 从 R1-Zero 已有输出中收集格式可读的部分；④ **人类标注者对以上所有结果做后处理精炼**（修正格式、统一语言、增强可读性）。人类不写推理链——推理内容来自模型，人类做的是质量把关和格式润色。

</details>

**Q3 批改**：矛盾识别准确——PRM 是模型估计值而非可验证信号，这一点抓住要害。但"可以解决"的分析过于乐观，存在一个关键盲区：**即使数据无限多、PRM 完美准确，奖励黑客问题依然存在**——这是 Goodhart 定律的体现（当一个度量成为优化目标，它就不再是好的度量）。一个"准确"的 PRM 可能比"不准确"的 PRM 更容易被对抗性利用，因为它的评分模式更可预测。DeepSeek 团队放弃 PRM 的核心原因恰恰不是"PRM 不够准"，而是"PRM 引入了基于模型的奖励 → 违背了 RLVR 的非模型前提"。 — 得分：6/10

<details>
<summary>📖 Q3 参考答案</summary>

**矛盾是否存在？**

存在，且是**根本性的**（fundamental），而不仅仅是"PRM 目前还不够准"的工程问题。

RLVR 的核心前提：
> 奖励必须是**可验证的、非模型的**（verifiable, non-model-based）。
> 即：奖励来自客观规则（如数学答案比对、代码编译运行结果），而非另一个模型的判断。

PRM 的核心操作：
> 用**另一个模型**对推理过程的每一步打分，作为 RL 训练的稠密奖励信号。

这里存在一个逻辑上的自指矛盾：

```
RLVR 的前提：不要用模型来判断模型（防止奖励黑客）
PRM 的做法：用模型来判断模型的每一步
                ↑
        矛盾：PRM 恰好违背了这个前提
```

**为什么这个矛盾是"根本性的"而非"暂时性的"？**

1. **奖励黑客（Reward Hacking）是结构性的，不是准确度问题**：
   - 即使 PRM 在测试集上 99% 准确，它仍然是一个模型，有自己的漏洞和盲区
   - 当 RL 优化的目标变成"让 PRM 打高分"而非"给出正确答案"时，优化过程会主动寻找 PRM 的漏洞
   - 这类似于对抗样本——一个分类准确率 99% 的图像模型，仍然可以被精心构造的扰动轻易欺骗
   - 更准确地说：优化过程在 PRM 的评分函数上做梯度上升 → 找到的是 PRM 评分最高但实际不一定正确的区域 → 这正是 Goodhart 定律的数学体现

2. **PRM 越准确，在某些意义上越危险**：
   - 一个粗糙的、随机的 PRM → 优化很难找到稳定的漏洞 → 奖励黑客效率低
   - 一个准确的、确定性的 PRM → 评分函数光滑可微 → 优化更容易沿着梯度"爬"到高分但错误的区域
   - 这是一个反直觉的结论：PRM 的准确度提升不一定带来 RL 训练效果的提升

3. **"数据多→估计准"的逻辑跳跃**：
   - PRM 的训练数据再多，它仍然是在学习一个**代理目标**（proxy objective），而非真正的"推理正确性"
   - "推理正确性"本身在开放域问题中是不可直接观测的潜变量——这就是为什么我们需要可验证奖励（如数学题的数值答案）作为 ground truth
   - 用更多数据训练 PRM 只是让它更好地拟合训练分布，但 RL 优化过程中生成的推理路径可能完全在分布外（OOD），PRM 的估计不再可靠

**DeepSeek 团队放弃 PRM 的三条具体原因如何映射到这个矛盾：**

| 失败原因 | 是根本矛盾还是工程问题？ | 分析 |
|---------|---------------------|------|
| 步骤定义难 | **工程问题**（可能被更好的标注方案缓解） | "什么算一步"在数学领域可定义（每行等式），但缺乏跨领域通用定义 |
| 标注不可靠 | **工程问题**（可能被更多人工标注缓解） | 自动标注有偏差，人工标注贵——但理论上可解决 |
| 奖励黑客 | **根本矛盾**（不可通过更多工程投入解决） | 一旦奖励来自模型，优化就会找模型的漏洞——这是结构性的 |

**矛盾是否可以被解决？**

**完全解决：不可能。** 只要 PRM 是模型，它就会引入"用模型评估模型"的结构性风险。这是 RLVR 框架在理论层面的约束——这个约束不是技术限制，而是定义性的。

**部分缓解：有可能。** 以下几种策略可以降低（但不能消除）风险：

1. **PRM 作为辅助信号而非主奖励**：主奖励仍来自可验证规则（最终答案对错），PRM 只提供微弱的稠密引导。类似于 RLHF 中 KL 惩罚的角色——"可以有多一点探索，但别跑太远"。

2. **约束 PRM 只做"验证"而非"评分"**：PRM 只判断某一步是否"明显错误"（如计算错误、逻辑跳跃），而不是给一个连续分数。二值判断比连续评分更难以被对抗性利用。

3. **PRM + 对抗训练**：在 PRM 训练数据中主动加入被策略模型 exploit 的样本（类似 GAN 的训练方式），让 PRM 对奖励黑客更鲁棒。但这也引入了新的复杂度，且不如 GRPO 简洁。

4. **PRM 只用于筛选/课程学习，不用于 RL 梯度**：用 PRM 筛选出"看起来推理质量高"的样本做 SFT（而非 RL），PRM 不进入梯度计算路径。DeepSeek-R1 的蒸馏路线本质上就用了这个思路——教师模型（R1）充当了"隐式的 PRM"，但只用于生成 SFT 数据，不参与 RL 优化。

**核心教训**：GRPO 的成功和 PRM 的失败共同说明了一个原则——在 RLVR 场景下，**保持奖励信号简单（simple reward）比追求奖励信号精细（dense reward）更有效**。复杂的方法（PRM、MCTS）看似更"智能"，但它们引入的额外复杂度和结构性风险往往超过了收益。

</details>
