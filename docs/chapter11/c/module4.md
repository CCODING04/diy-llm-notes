## 核心内容

### 1. 训练数据安全：250 份恶意文档即可投毒

#### 1.1 传统假设 vs 新发现

在模块 1 中我们提到数据投毒是训练数据安全的核心威胁之一。传统研究有一个**默认假设**：攻击者需要控制训练数据的一定**比例**才能成功投毒。这个假设看起来很合理——更大的模型用了更多数据，毒药自然也需要更多，否则会被"稀释"。

但 Anthropic 与英国 AI 安全研究所（UK AISI）、Alan Turing 研究所的联合研究彻底推翻了这个假设。

**核心发现**：无论模型规模（600M → 13B）或训练数据量（6B → 260B tokens），**仅需约 250 份恶意文档**即可在模型中植入后门漏洞。中毒所需的文档数量是**近乎常数**的，不随模型和数据规模增长。

```
实验设置（来自 arxiv:2510.07192）：
┌──────────────┬─────────────────┬──────────────────┐
│   模型规模    │  训练数据量      │  投毒文档数       │
├──────────────┼─────────────────┼──────────────────┤
│   600M       │   6B tokens     │    250           │
│   1.3B       │  26B tokens     │    250           │
│   3B         │  60B tokens     │    250           │
│   13B        │ 260B tokens     │    250           │
└──────────────┴─────────────────┴──────────────────┘
所有四个规模的模型均被成功植入后门，尽管最大模型的干净数据是
最小模型的 20+ 倍。
```

#### 1.2 为什么是常数而非比例？

这个发现之所以"反直觉"，是因为它挑战了我们对数据投毒的直觉模型。

**传统直觉（比例模型）**：毒药像墨水——倒进一杯水（小模型）会变色，倒进一池水（大模型）会被稀释。攻击者需要按比例投入更多墨水。

**实际机制（常数模型）**：毒药像"触发器-响应"配对学习——250 份文档提供了足够多的训练信号让模型学会"看到触发词 → 输出特定模式"。这不是关于"毒药浓度"，而是关于**学习一个简单的条件映射所需的样本数**。250 个样本对于学习"触发词 → 胡言乱语"这个映射来说已经足够。

> 🌐 **补充（Web Search / Exa）**：Anthropic 官方博客指出，这项研究聚焦于**低风险后门行为**（生成胡言乱语文本），并非高危行为（如泄露敏感数据）。但这一发现的意义在于揭示了投毒攻击的**可行性远超此前预期**——如果 250 份文档就能植入一个简单后门，更复杂的攻击可能同样只需要少量文档。此外，研究还验证了**微调阶段的投毒具有同样的动态特征**，这意味着即使预训练数据是安全的，下游微调仍然面临此威胁。

> 💡 **同名异义提醒**：此处的"投毒"（poisoning）指的是向训练数据中注入恶意文档，与强化学习中的"奖励投毒"（reward hacking/poisoning of reward model）是不同概念。前者是数据层面的攻击，后者是训练信号层面的偏差。另一个容易混淆的术语是"数据中毒"（data contamination），在 LLM 领域常指评测基准数据泄露到训练集中，这属于数据质量问题而非恶意攻击。

#### 1.3 防御方向

研究明确指出：**唯一有效的防御是对训练数据来源进行严格审计和防御性过滤**。这对模块 2（KenLM/BERT 质量过滤）和模块 3（去重）的研究提出了更高要求——不仅要过滤低质量数据，还要能识别具有恶意意图的文档。

### 2. 数据可用性：合成数据新范式

#### 2.1 范式的转变

模块 1 中我们讨论了合成数据在后训练（SFT/RLHF）中的作用。但合成数据的影响远不止于此——它正在从"数据增强的辅助手段"演变为"驱动科学研究的核心引擎"。

世界经济论坛（WEF）2025 年报告 *Synthetic Data: The New Data Frontier* 指出，数据正从"被动记录世界"转向"可被主动设计、生成与验证"：

```
旧范式：谁拥有更多数据？
  真实世界 → 产生数据 → 收集 → 清洗 → 训练
  竞争优势 = 数据获取能力

新范式：谁能生成更有价值的数据？
  物理定律 + 计算模拟 → 合成数据空间 → 训练 + 验证
  竞争优势 = 数据生成与设计能力
```

#### 2.2 数字孪生与 LQM

课程原文中提到的**数字孪生**（Digital Twin）和**大型定量模型**（LQM, Large Quantitative Models）是这一范式的核心技术支撑：

| 概念 | 定义 | 示例 |
|------|------|------|
| **数字孪生** | 物理系统的精确虚拟副本，可实时模拟、分析和优化真实世界性能 | Waymo 创建旧金山街景的数字孪生来测试自动驾驶 |
| **LQM** | 受物理定律约束的计算模拟体系，生成具有因果可信度的合成数据 | 虚拟患者用于药物试验、分子交互模拟、复杂系统仿真 |

**数字孪生与 LQM 的关系**：LQM 是构建数字孪生的建模工具——它用数学/物理方程描述系统的定量行为，数字孪生则是这些模型与实时数据流结合后形成的动态镜像。举个例子：
- LQM 提供"人体对某种药物的生化反应方程"
- 数字孪生是将该方程应用于特定"虚拟患者"的参数集，实时模拟给药后的生理变化

> 🌐 **补充（Web Search / Tavily + Exa）**：WEF 2025 报告识别了合成数据的五个主要应用场景：① 训练数据多样化（如字节跳动用合成数据增强 LLM 训练集）；② 添加噪声提升模型鲁棒性并防止过拟合；③ 场景建模与预测（危机模拟、供应链崩溃推演）；④ 机器人与自动驾驶（Waymo 在合成旧金山街道上测试危险驾驶场景）；⑤ 成本效益——替代昂贵的高质量真实数据集。

#### 2.3 核心洞察

课程原文的这句话值得重点咀嚼：

> 科研与产业竞争的重心正从"谁拥有更多既有数据"，转向"谁能够持续、可靠地生成高价值合成数据"

这意味着，未来的数据工程不再只是"清洗和筛选"，而是**设计数据生成流水线**——就像模块 1 中说的"真实数据奠基、合成数据精调"范式，合成数据的设计能力将成为核心竞争力。

### 3. 数据评估与记忆行为：信息引导探针（Information-Guided Probe）

#### 3.1 问题背景

商业 LLM（GPT-4、Claude 等）的提供商几乎不披露训练数据细节。这带来多重挑战：
- **版权侵权**无法审计
- **数据作者**的权益无法保障
- **数据污染**（评测基准泄露）难以检测

传统方法是**前缀补全**——给模型一段文本的前几个词，看它能否一字不差地补全。但这种方法在 API 提供商加入过滤/安全机制后变得不可靠。

NAACL 2025 论文 *Information-Guided Identification of Training Data Imprint in (Proprietary) Large Language Models* 提出了一种全新的**黑盒审计方法**——不需要模型权重，甚至不需要 token 概率（如 GPT-4 只返回生成的文本）。

#### 3.2 Surprisal：香农信息论的核心度量

Surprisal 是整个方法的基础概念，来自香农 1948 年信息论：

$$
\mathrm{Surprisal}(w_t) = -\log P(w_t \mid h_t)
$$

其中：
- $h_t$ = 上下文（模型看到的输入）
- $w_t$ = 目标 token
- $P(w_t \mid h_t)$ = 模型预测 $w_t$ 的概率

**直觉理解**：

| 场景 | $P(w_t\|h_t)$ | Surprisal | 含义 |
|------|---------------|-----------|------|
| "The capital of France is ___" → "Paris" | ~0.95 | $-\log(0.95) \approx 0.05$ | 低意外——模型很确定 |
| "My favorite book is ___" → "1984" | ~0.01 | $-\log(0.01) \approx 4.6$ | 高意外——模型难以预测 |
| "The patient was diagnosed with ___" → 罕见病名 | ~0.0001 | $-\log(0.0001) \approx 9.2$ | 极高意外——几乎不可能猜中 |

> ⚠️ **同名异义提醒**：Surprisal（信息量/意外程度）在 LLM 研究中有三个不同的应用场景，容易混淆：
>
> | 场景 | Surprisal 度量什么 | 代表工作 |
> |------|-------------------|---------|
> | **记忆检测**（本模块） | 给定上下文，模型对某个 token 的意外程度——高 surprisal token 是好的"探针材料" | NAACL 2025 |
> | **AI 文本检测** | 比较人写文本与 AI 生成文本的 surprisal 分布差异 | SurpMark, DivEye |
> | **人类语言处理** | 用 surprisal 预测人类阅读时的眼动/脑电信号 | Hale 2001, Levy 2008 |
>
> 这三个场景使用同一个数学公式，但目标和解释完全不同。本模块聚焦于第一种。

#### 3.3 为什么高 Surprisal Token 是好的"记忆探针"？

论文的核心洞察可以用一个类比来理解：

**类比：考试检测学生是否看过答案**

- 如果你问学生"1+1=?"，几乎所有人都能答对 → **低 surprisal** → 无法区分"真正知道"和"死记硬背"
- 如果你问学生"请默写《红楼梦》第 73 页第 5 行"，能答对的学生极大概率是**看过那一页** → **高 surprisal** → 这是记忆的强信号

用课程原文的表述：

> 模型通常能够判断"这里应出现什么类型的信息"，但难以提前确定"具体是哪一个"，而高信息量 token 正是帮助模型明确具体类型的关键。

**数值验证**：假设一段小说文本中出现了角色名"Elandra"：

```
上下文: "The mysterious figure turned out to be"
候选 token:  "Elandra" (P=0.0003), "a" (P=0.42), "the" (P=0.15)

Surprisal("Elandra") = -log(0.0003) ≈ 8.1  ← 极高意外
Surprisal("a")       = -log(0.42)   ≈ 0.87 ← 低意外
```

如果模型在给定扰动上下文（移除了"Elandra"附近的关键词）后，仍然能在自由生成中准确输出"Elandra"，这就构成了**该 token 已被记忆**的统计证据。

#### 3.4 Information-Guided Probe 三步法

论文提出的方法分为三个阶段。注意这是一个**统计检验**而非直接证明——它提供"模型很可能见过这些训练数据"的证据，而非"模型逐字存储了这些数据"。

```
第一步：识别高 Surprisal Token
─────────────────────────────────────────────
输入文本 → 参考模型（如 LLaMA）计算每个 token 的 P(w_t|h_t)
         → 筛选 Surprisal > 阈值的 token
         → 这些是"候选探针 token"

第二步：知识过滤
─────────────────────────────────────────────
候选 token → 低能力指令微调模型尝试预测
           → 如果小模型也能猜对 → 剔除（这是通用知识，不是记忆）
           → 如果小模型猜不对 → 保留（这可能是被记忆的特殊内容）

第三步：重构测试
─────────────────────────────────────────────
保留的 token → 从原文本中移除该 token 及其周围内容
             → 构造"扰动上下文"
             → 让目标模型（如 GPT-4）在扰动上下文下自由生成
             → 观察是否生成了被移除的 token
             → 重构成功率显著高于随机水平 → 记忆痕迹
```

> 💡 **补充（Context7 / NAACL 2025 论文）**：论文中的关键实验发现——**更大的模型重建了更多高 surprisal token**。在虚构文本测试中，70B 模型恢复的高 surprisal token 数量是 7B 模型的约 **7 倍**。这意味着：**模型越大，记忆越多**，信息引导探针在更大模型上的检测能力也越强。

#### 3.5 方法局限性

课程原文明确指出了这一点：

> 信息引导探针并不直接证明模型存储了完整训练样本，而是提供了一种在"黑盒"条件下检测异常记忆行为的统计证据。

换句话说：如果 GPT-4 能重建你小说中的角色名"Elandra"，这不等于 GPT-4 逐字背诵了你的整本小说——但它在统计意义上构成了"该角色名被记忆"的有力证据。多个这样的证据累积起来，就可以构建训练数据使用的合规性评估。

**A1**：

因为直觉上，模型越大需要的数据就越多，而 恶意文档 只有在越多的数据中保持一定的占比（百分比）才能影响到模型的效果。定量的数据会在更大的模型规模（会需要更多的数据），而定量的数据直觉上会在更多的数据中被稀释。
且 模型学习的是 p(w_t|w_0 ... w_t-1) 即学习的是这部分内容出现的概率，如果数据越多，那么这部分概率会被平均掉，只有恶意文档的频率增加，模型学习到这部分内容的可能性才会增加。 

**A2**：

“obfuscate” 的 surprisal 是 -log0.002 ≈ 6.215
“the” 的 surprisal 是 -log0.35 ≈ 1.05

因为 高 surprisal 的 token，在这个上下文下出现的概率极低，如果模型能产生这部分 token，有极大的概率说明模型“见过”这部分上下文组合，从而“记住”。从统计学上来理解，是更有可能训练了这部分数据，所以更适合作为“记忆探针”。

**A3**：

“合成数据” 往往是在 SFT/RL 部分需要提高模型质量以及下游任务（code/文本 等任务） 的表现能力来根据任务、环境构建对应数据的方式。
这部分数据 去重 同样重要，但是不再局限于 简单的文本相似度，应该更着重语义的相似性，KenLM 虽然能快速判断文本相似性，但是更精确的内容用 语言模型 判断会更好。因为这部分合成数据量不是关键，质量才是重中之重，且可以同样用 已经训练好的 语言模型 交叉验证生成数据的质量。

<summary>📖 Q1 参考答案</summary>

**角度一：比例稀释直觉**

传统数据投毒研究默认假设攻击者需要控制训练数据的一定**比例**。这个直觉来自"浓度稀释"类比——毒药像墨水，倒进一杯水会变色，倒进一池水会被稀释到无法察觉。因为更大的模型使用更多的训练数据（Chinchilla 定律：数据量随模型规模线性增长），直觉上毒药也需要等比例增加才能维持"浓度"。

但 Anthropic 的实验推翻了这一直觉：13B 模型的训练数据是 600M 模型的 **20+ 倍**，但 250 份毒文档同样有效。

**角度二：条件映射学习**

关键区别在于模型的任务是什么：
- 如果模型需要"学习整个数据分布 P(w_t|h_t)"，那毒药确实需要影响全局分布 → 需要按比例
- 但投毒的实际任务只是"学习一个简单的条件映射：看到触发词 → 输出胡言乱语" → 这是**少样本可学的**

250 个样本对于学习"trigger → gibberish"这个映射来说已经足够。模型不需要"中毒分布"在训练集中占显著比例，只需要看到足够多触发-响应对，让梯度在这个映射方向上累积即可。

**直觉检验**：这类似于教一个人"当有人说 X 时你就回答 Y"。不管这个人一生中经历了多少其他对话，只要这 250 次 X→Y 的训练被内化，条件反射就建立了。数量取决于"映射的复杂度"而非"背景数据的总量"。

**Q2 批改**：计算完全正确（使用自然对数，与模块文档中的示例一致）。核心逻辑——高 surprisal token 在上下文中出现概率极低，如果模型能产生它就有极大的记忆嫌疑——准确抓住了信息引导探针的核心洞察。两个可加强的点：① "如果模型能产生这部分 token"应当精确为"在扰动上下文（已移除该 token 相关信息）中能重建"——正常上下文中任何模型都可以产生常见 token，关键是在**信息被剥夺后仍能恢复**；② 可以补充低 surprisal token 的对比：`-log(0.35) ≈ 1.05` 的 "the" 任何具备基本语言能力的模型都能在给定上下文后预测，因此**无法区分"语言能力"和"记忆痕迹"**——这正是高 surprisal token 作为探针的独特价值所在。 — 得分：**8/10**

<details>
<summary>📖 Q2 参考答案</summary>

**计算部分**：

| Token | P(w_t\|h_t) | Surprisal = -ln(P) | 含义 |
|-------|-------------|-------------------|------|
| "obfuscate" | 0.002 | -ln(0.002) ≈ **6.215** | 极高意外——模型几乎不认为这个词会出现 |
| "the" | 0.35 | -ln(0.35) ≈ **1.050** | 低意外——模型认为这是常见选择之一 |

**为什么高 Surprisal token 更适合作为记忆探针？**

关键在于**可区分性**：

- "the"（Surprisal ≈ 1.05）：任何有基本英语能力的模型都能在给定上下文后预测冠词"the"。如果模型在扰动上下文中生成了"the"，你无法判断这是"语言能力"还是"记忆痕迹"——就像任何人都能答对"1+1=?"，你无法判断他是否看了答案。

- "obfuscate"（Surprisal ≈ 6.215）：这个罕见词在给定上下文中出现的概率极低（0.2%）。如果模型在**扰动上下文**（已经移除了暗示该词的关键信息）中仍然精确生成了"obfuscate"，有极大的统计嫌疑表明**模型在训练中见过这个具体的上下文-词语配对**——就像"请默写《红楼梦》第 73 页第 5 行"，能答对的人几乎肯定看过那一页。

**与 NAACL 2025 论文的直接对应**：

论文用这个逻辑识别 GPT-4 的训练数据：
1. 找一段小说，计算每个专有名词（角色名、地名）的 Surprisal
2. 高 Surprisal 的角色名 → 候选探针
3. 从原文中移除角色名相关信息，让 GPT-4 自由生成
4. 如果 GPT-4 精确生成了被移除的角色名 → 统计证据表明该角色名被记忆

**常见误解**：Surprisal 高不代表模型"不知道"这个词——恰恰相反，模型对罕见词的"精确重建能力"才暴露了记忆。Surprisal 度量的不是"模型的知识"，而是"在给定上下文下该 token 的不可预测性"。

**Q3 批改**：正确抓住了"语义去重"和"质量>数量"两个核心转变，且提到用语言模型交叉验证质量的思路非常好。三个可补充的关键点：① 合成数据引入**新型冗余**——模板生成会产出"结构相同但词面不同"的文本（如"请描述[事物A]的历史" × 1000 次生成），MinHash 对此完全无能为力，语义去重的需求因此大幅上升；② 质量过滤有机会从"事后筛选"转向**"前置嵌入"**——既然数据是生成的，完全可以在生成阶段把质量约束嵌入 prompt（如要求逻辑链完整性、引用可靠性），质量过滤变成质量设计，而非事后补救；③ 合成数据的**递归风险**——如果模型 A 的合成数据用于训练模型 B，模型 B 的合成数据又用于训练模型 C，分布会逐渐漂移并坍缩（model collapse），这是真实数据去重中不存在的"代际退化"风险。 — 得分：**7/10**

<details>
<summary>📖 Q3 参考答案</summary>

**对去重的影响**

| 维度 | 真实数据去重（模块 3） | 合成数据去重（新挑战） |
|------|---------------------|---------------------|
| 冗余来源 | 网页镜像、转载、引用 | 模板化生成、同 prompt 多次采样 |
| 检测方式 | MinHash + LSH（n-gram 重叠） | 需要语义级去重——结构相同但词面不同的生成文本 MinHash 无法捕获 |
| 新机遇 | — | 合成数据的生成参数（prompt、温度、模型版本）本身可作为去重的"元数据标识"——同一 prompt 的多次生成天然可追踪 |

**对质量过滤的影响**

| 维度 | 真实数据过滤（模块 2） | 合成数据过滤（新挑战/机遇） |
|------|---------------------|--------------------------|
| 过滤时机 | 事后过滤（KenLM/FastText 在数据收集后打分） | **生成时过滤**——质量约束可嵌入 prompt（"请确保逻辑链完整，引用可靠来源"），过滤前置 |
| 质量定义 | 语法正确性、信息密度、与高质量语料的相似度 | 可用下游任务表现直接验证——合成一条 SFT 数据，用 reward model 打分，低分别丢弃/重写 |
| 新风险 | — | **model collapse**：合成数据被递归用于训练下一代模型时，分布的尾部分布（罕见但真实的知识）逐渐消失，模型输出趋向均值化 |

**核心转变**：真实数据时代，工程师是"淘金者"——从海量沙砾中筛出金粒。合成数据时代，工程师是"冶金师"——直接设计并铸造所需材料，质量控制的范式从"筛"变成"造+验"。
