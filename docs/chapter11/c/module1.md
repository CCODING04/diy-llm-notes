## 一、先导：为什么数据比模型架构更重要？

在前 10 章中，我们默认"训练数据已经准备好了"，专注于模型架构、优化方法、推理加速。但从这一章开始，我们面对一个更根本的问题：**语言模型到底应该用什么数据来训练？**

一个反直觉的现实是：

```
Llama 3、DeepSeek、Qwen 等主流模型：
  ✅ 开源模型权重
  ✅ 公开架构细节
  ❌ 唯独对训练数据闭口不谈
```

原因很简单：在 Transformer 架构高度同质化的今天，**数据清洗和配方才是真正的护城河**。即便有相同的模型架构和训练代码，换了数据就会得到完全不同的模型。

> 🌐 **补充（Web Search / FineWeb 论文，NeurIPS 2024）**：HuggingFace 团队在 FineWeb 论文中明确指出——"The performance of a large language model depends heavily on the quality and size of its pretraining dataset." 他们通过消融实验证明，仅更换数据过滤策略就能带来显著的 benchmark 性能提升，而模型架构完全不变。

## 二、LLM 训练的三阶段生命周期

现代大模型不是"一口气训练完"的，而是分三个阶段，每个阶段对数据的要求完全不同：

```
┌──────────────────────────────────────────────────────┐
│                    三阶段训练流程                       │
├───────────────┬──────────────────┬───────────────────┤
│  预训练        │  中期训练         │  后训练            │
│  Pre-training │  Mid-training    │  Post-training    │
├───────────────┼──────────────────┼───────────────────┤
│ 数据：网页抓取  │ 数据：高质量筛选   │ 数据：人工标注      │
│ 规模：3T-15T   │ 规模：100B-1000B  │ 规模：百万级        │
│      tokens   │        tokens    │      条指令        │
├───────────────┼──────────────────┼───────────────────┤
│ 目标：         │ 目标：            │ 目标：             │
│ 学习语言规律   │ 强化推理/代码能力  │ 对齐人类偏好        │
│ 掌握世界知识   │ 长文本理解        │ 遵循指令           │
└───────────────┴──────────────────┴───────────────────┘
```

用一个比喻来理解这三个阶段：

- **预训练 = 通识教育**：大量阅读，建立对世界的基本认知
- **中期训练 = 专业课程**：集中学习数学、编程等硬技能
- **后训练 = 职业培训**：学会如何与人打交道，遵循指令

> 💡 **本章重点**：后续内容（也是实际工程中最复杂的部分）主要集中在预训练阶段的数据处理。

## 三、训练数据的演变史

### 3.1 BERT（2018）：文档级语料的智慧

BERT 的训练数据量按今天的标准"很小"——BooksCorpus（约 8 亿词）+ 英文维基百科（约 25 亿词）。但它的数据选择有一个**被很多人忽略的精妙设计**：

```
BERT 的核心目标：学习跨句子、跨段落的语义依赖关系
        ↓
需要的不是"随机句子堆砌"，而是"长、连续、自然的文档"
        ↓
维基百科的处理：只保留正文段落，刻意剔除列表、表格、标题
        ↓
原因：列表和标题的结构化格式会"打断"自然语言的上下文流动
```

**一个关键对比**：

| 数据集 | 结构特征 | 适合 BERT 吗？ |
|--------|---------|---------------|
| BooksCorpus | 长篇、叙事连贯 | ✅ 非常适合 |
| Wikipedia（纯正文） | 段落连续、论述完整 | ✅ 适合 |
| Billion Word Benchmark | 句子随机打乱、互相独立 | ❌ 不适合 |

> BERT 的设计告诉我们一个至今仍然成立的原则：**数据的组织结构（文档级 vs 句子级）直接影响模型能学到什么类型的语言知识**。

### 3.2 GPT-2（2019）：从网页中"淘金"

GPT-2 面临一个新问题：书籍和维基百科虽然质量高但规模有限，网络数据覆盖面广但噪声严重。如何从垃圾堆里淘出金子？

OpenAI 的解决方案出人意料地简单巧妙——**用 Reddit 用户的点赞行为作为质量信号**：

```
WebText 构建方法：
  爬取 Reddit 上获得 ≥3 个赞（karma）的帖子中的外部链接
        ↓
  提取这些链接指向的网页内容
        ↓
  逻辑：如果至少 3 个人觉得这个链接有价值，那它大概率不是垃圾
```

这个方法的精妙之处在于：**零人工标注成本，利用社区自发的 curation（策展）行为作为质量过滤器**。这开创了"用社交信号替代人工标注来做数据筛选"的思路。

### 3.3 GPT-3（2020）：规模化 + 多样性

GPT-3 将参数量推到 175B，单一数据源（哪怕 WebText 规模）也不够了。它引入了两个至今仍影响深远的策略：

**策略一：引入 Common Crawl（公共网络爬虫）**

Common Crawl 是一个非营利组织，定期爬取整个互联网并免费公开快照（snapshot）。但原始 Common Crawl 的质量……一言难尽：

```
原始 Common Crawl 的问题：
  - 大量 HTML 标签和 JavaScript 代码混在文本里
  - 同一篇内容被数百个网站镜像/转载（严重重复）
  - 广告、导航栏、页脚等非正文内容
  - 乱码、机器生成的垃圾页面
```

为此 GPT-3 进行了系统的清洗流程：

```
Common Crawl 原始数据
    ↓ 去重：删除重复文档
    ↓ 去 HTML 标签：剔除网页标记和脚本
    ↓ 清理非文本内容：移除乱码和低质量文本
    ↓
可用于训练的干净文本
```

**策略二：The Pile — 多样化语料集**

EleutherAI 社区发布的 The Pile 覆盖了 22 个高质量领域：

| 领域类型 | 数据来源示例 | 训练收益 |
|---------|------------|---------|
| 学术论文 | ArXiv | 科学推理、专业术语 |
| 代码 | GitHub | 逻辑推理、结构化思维 |
| 问答 | StackExchange | 问题拆解、指令遵循 |
| 书籍 | Books3 | 长文本理解、叙事能力 |

> GPT-3 的经验锁定了一个核心公式：**高性能 LLM = 海量数据规模 × 严格质量控制 × 充分领域多样性**。任何一项的缺失都会导致模型能力的短板。

### 3.4 OLMo 2（2024）：完全透明的数据配比

Allen AI 的 OLMo 2 是目前**最透明的开源 LLM 之一**——不仅开源权重，还公开了完整的训练数据配比和代码。

**预训练阶段（占总训练计算量的 90%-95%）**：

```
OLMo 2 预训练数据 ≈ 3.9 万亿 tokens

  DCLM-Baseline（通用网页）  ████████████████████████████████  >95%
  StarCoder（代码）           ██
  arXiv（STEM 论文）          █
  OpenWebMath（数学）         █
  Wikipedia（百科）           █
```

**中期训练阶段（占总训练计算量的 5%-10%）**：

> 💡 中期训练的核心理念：用量少但质量极高的数据做"针对性补强"。

```
高质量网页：DCLM 中得分最高的 7% + FineWeb 高指标内容
课程数据（Curriculum）：FLAN 指令 + StackExchange + 学术论文
数学增强（约 107 亿 tokens）：
  ├── TuluMath：合成数学题
  ├── TinyGSM-MIND：合成数学对话
  └── MathCoder2：合成数学书籍
```

> 🌐 **补充（Web Search / OLMo 2 论文, COLM 2025）**：OLMo 2 的 7B、13B、32B 模型位于 "Pareto frontier of performance-to-training compute"——即用更少的训练 FLOPs 达到与 Llama 3.1、Qwen 2.5 等模型相当的性能。这侧面说明其数据策略非常高效。

### 3.5 Qwen3（2025）：超大规模 + 多语言

Qwen3 将预训练数据规模推向 **36 万亿 tokens**（是 Qwen2.5 的近两倍），覆盖 **119 种语言和方言**。

```
Qwen3 数据策略的三个亮点：

1. PDF 文档深度提取
   大量知识存在于 PDF 而非网页中
   → 使用微调后的 Qwen2.5-VL（视觉-语言模型）识别 PDF 内嵌文字
   → 再用 Qwen2.5 基础模型清洗提取出的文本

2. 专家模型合成数据（中期训练）
   Qwen2.5-Math  → 生成数学问题及解析
   Qwen2.5-Coder → 生成代码示例和程序语料
   → 额外补充约 5 万亿高质量 tokens

3. 长上下文能力培养（后训练）
   从 4,096 tokens 扩展到 32,768 tokens 上下文长度
   使用大量长上下文语料（部分由大模型合成生成）
```

> 💡 **Qwen3 的启示**：合成数据（用已有模型生成训练数据）已成为现代 LLM 训练流程的标准组件。其成本远低于人工标注，且质量可控。但需要注意——合成数据只能"锦上添花"（在真实数据基础上微调），不能"无中生有"（完全替代真实数据做预训练）。

## 四、特殊领域数据：通用知识的三大补丁

通用网页文本（维基百科、新闻、社交媒体）让模型掌握**基础常识**。但要让模型在专业领域表现出色，需要三类"补丁数据"：

### 4.1 代码：不只是为了写代码

```
GitHub 代码数据的处理流程：
  Clone 全仓库 → 过滤非代码文件 → 去重 → License 检查 → 质量筛选
                                    ↑
                         关键步骤：解析 LICENSE 文件
                         确保不包含未授权的专有代码
```

**代码数据的"溢出效应"**：研究反复证明，在代码数据上训练的模型，不仅代码能力增强，**在多步骤推理、问题分解、抽象思维方面也有显著提升**。代码天然是"结构化逻辑"的完美教材——每一步都必须精确、有因果、可验证。

### 4.2 书籍：叙事与长文本理解的教材

| 数据特征 | 网页文本 | 书籍 |
|---------|---------|------|
| 单篇长度 | 几百到几千词 | 几万到几十万词 |
| 叙事连贯性 | 低（碎片化） | 高（章节递进） |
| 逻辑链条 | 短（一个观点） | 长（论证递进） |
| 版权风险 | 低（多数公开） | **高（需关注）** |

> ⚠️ **版权提醒**：优先使用公版书（如 Gutenberg 项目）或已获授权的书籍。Books3 等数据集可能来源于影子图书馆，存在法律风险。

### 4.3 数学与科学：推理能力的训练场

两类互补的数据源：

| | ArXiv 论文 | StackExchange |
|---|---|---|
| 形式 | LaTeX 科学文本 | 问答对 |
| 内容 | 公式推导、理论证明 | 问题拆解、多步推理 |
| 训练价值 | 专业术语、知识体系 | 指令遵循、解题思维 |
| 处理要点 | 解析数学公式 | 答案-问题对齐 |

## 五、数据安全：无法回避的"雷区"

### 5.1 版权困境

几乎所有互联网内容都默认受版权保护（即使没有明确声明）。AI 公司的辩护逻辑是"合理使用（fair use）"——模型是在学习**统计规律**，而非复制原文。但这个逻辑正在法庭上被检验：

> 🌐 **参考（Web Search）**：截至 2025 年底，《纽约时报》等主流新闻机构对 OpenAI 的版权诉讼仍在审理中。如果判例不利于 AI 公司，未来的模型训练可能需要大规模购买版权许可，训练成本可能大幅上升。

**给开发者的实用建议**：使用有明确许可的数据（公版、开源、自有数据），对来源不明的数据保持警惕。

### 5.2 数据投毒：250 篇文档就能攻陷一个 LLM

数据投毒（Data Poisoning）指攻击者在公开数据源（如维基百科、论坛）中注入恶意内容，使抓取并训练后的模型产生异常行为。

> 🌐 **补充（Web Search / Anthropic + UK AISI + Alan Turing Institute 联合研究, 2025.10）**：一项由 Anthropic、英国 AI 安全研究所和艾伦·图灵研究所联合发表的研究揭示了一个令人震惊的发现——

```
实验结论：仅需约 250 篇恶意文档，即可在 LLM 训练中实现投毒攻击

  实验设置：
  - 在 13B 参数模型的训练数据中插入投毒样本
  - 恶意文档仅占总训练 tokens 的 0.00016%
  - 攻击类型：拒绝服务（DoS）后门
     触发特定短语 → 模型输出乱码（gibberish）

  关键发现：所需恶意文档数量接近常数（~250），几乎不随模型规模增长
  → 更大的模型并不会天然更抗投毒
```

**为什么这么少的文档就能产生效果？** 因为训练数据的分布极不均匀（长尾特性）——某些特定模式（如触发短语）在正常数据中极少出现，攻击者只需让这些模式在训练中"重复出现足够多次"，模型就会学到错误关联。

**防御策略**：
- 数据清洗过滤异常内容（但攻击可以设计得看起来像正常文本）
- 关键领域数据需要人工或半自动审核
- 训练后持续监控模型输出的安全性

## 六、互联网数据清洗：两大核心方法

### 6.1 启发式规则过滤

"启发式"（heuristic）是指基于经验设计的简单规则——不需要训练模型，直接根据文本的**表面特征**判断质量。

**C4 数据集的经典清洗策略**：

```
一条网页文本要"存活"下来，必须满足：
  ① 不是代码块、表格、列表、引用块
  ② 段落以标点符号结尾（。！？.!?）  → 过滤标题、导航栏
  ③ 段落至少包含 3 个句子               → 过滤碎片化内容
  ④ 不包含"lorem ipsum"等占位文本
  ⑤ 不包含"Terms of Service"等模板文本
```

**完整清洗代码解析**（来自课程文档）：

```python
# 来自 docs/chapter11/chapter11_数据工程.md

def clean_web_text_strict(html_text):
    # Step 1: 剔除结构化标签
    soup = BeautifulSoup(html_text, 'html.parser')
    for tag in ['table', 'pre', 'code', 'ul', 'ol', 'li', 'blockquote']:
        for element in soup.find_all(tag):
            element.decompose()  # 彻底删除该元素

    # Step 2: 提取纯文本，按段落拆分
    text = soup.get_text(separator='\n')
    paragraphs = [p.strip() for p in text.split('\n') if p.strip()]

    # Step 3: 逐段落过滤
    filtered_paragraphs = []
    for para in paragraphs:
        # 规则 A：必须以标点结尾
        if not re.search(r'[。！？\.!?]$', para):
            continue
        # 规则 B：至少 3 个句子
        sentence_count = len(re.findall(r'[。！？\.!?]', para))
        if sentence_count < 3:
            continue
        filtered_paragraphs.append(para)

    return '\n'.join(filtered_paragraphs)
```

**启发式方法的优缺点**：

| 优点 | 缺点 |
|------|------|
| 计算极快（无需 GPU） | 规则覆盖有限 |
| 实现简单、可解释 | 容易误删非常规但有效的文本（如代码、诗歌） |
| 适合大规模数据的第一轮粗筛 | 无法识别"看起来正常但内容低质"的文本 |

### 6.2 基于困惑度的文本质量过滤（CCNet）

"困惑度"（perplexity, PPL）是语言模型对一段文本的"惊讶程度"：

```
困惑度的直觉理解：

  文本："今天天气很好，适合出去散步"
  → 语言模型预测：每个词都很"合理"
  → 困惑度低（≈ 20-50）  → 这大概是一段正常的自然语言

  文本："asdf jkl qwert zxcv 123 !! #￥%"
  → 语言模型预测：完全无法理解
  → 困惑度高（≈ 500-1000+） → 这大概不是正常的自然语言
```

**CCNet 的工作原理**（CCNet: Extracting High Quality Monolingual Datasets from Web Crawl Data, Wenzek et al., LREC 2020）：

```
┌─────────────────────────────────────────────────────────┐
│                       CCNet 流水线                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ① 训练参考语言模型                                        │
│     在"黄金标准"语料（如 Wikipedia）上训练 5-gram KenLM 模型  │
│     → 这个模型定义了"什么是好的该语言文本"                    │
│                         ↓                               │
│  ② 逐文档计算困惑度                                         │
│     用 ① 中训练的 LM 对 Common Crawl 中的每个文档打分        │
│     → PPL 越低 = 越接近 Wikipedia 质量                     │
│                         ↓                               │
│  ③ 按语言分别设阈值（关键创新！）                              │
│     不同语言的困惑度分布差异极大——                             │
│     英语 Wikipedia 数据多 → LM 训练充分 → PPL 值低且集中       │
│     小众语言 Wikipedia 数据少 → LM 欠训练 → PPL 值高且分散      │
│     → 因此每种语言独立设置分位数阈值                           │
│                         ↓                               │
│  ④ 三级分类                                               │
│     head（前 33%）：最接近 Wikipedia 的高质量文本              │
│     middle（中 33%）：通用自然语言                           │
│     tail（后 33%）：可能是噪声、口语或特殊领域文本              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**CCNet 的简化实现解析**（来自课程文档）：

```python
# 来自 docs/chapter11/chapter11_数据工程.md

class AutoPerplexityFilter:
    def __init__(self, model_name='distilgpt2'):
        # 使用 GPT-2 的蒸馏版——参数少，推理快
        self.tokenizer = GPT2Tokenizer.from_pretrained(model_name)
        self.model = GPT2LMHeadModel.from_pretrained(model_name)

    def calculate_score(self, text: str) -> float:
        """
        核心公式：PPL = exp(Cross-Entropy-Loss)

        交叉熵损失：模型预测下一个词的"错误程度"
        取指数：将 loss 转换为更直观的"困惑度"指标
        例如：loss=3.0 → PPL=e^3.0≈20.1
             loss=7.0 → PPL=e^7.0≈1096.6（模型非常困惑）
        """
        inputs = self.tokenizer(text, return_tensors="pt")
        with torch.no_grad():
            outputs = self.model(**inputs, labels=inputs["input_ids"])
            loss = outputs.loss
            ppl = torch.exp(loss).item()
        return ppl
```

**校准机制——CCNet 最精巧的设计**：

```python
def calibrate(self, lang: str, sample_texts: List[str]):
    """
    用该语言的"黄金参考文本"来设定基准阈值

    例如中文校准：
    sample_texts = [
        "人工智能是计算机科学的一个分支...",
        "今天北京的天气非常晴朗...",
        ...
    ]
    → 计算这些文本的 PPL 分布
    → t1 = 33% 分位数（"好文本"的上界）
    → t2 = 66% 分位数（"噪声文本"的下界）
    """
    scores = [self.calculate_score(t) for t in sample_texts]
    t1 = np.percentile(scores, 33.33)  # 优质界限
    t2 = np.percentile(scores, 66.66)  # 噪声界限
    self.thresholds[lang] = (t1, t2)
```

> ⚠️ **课程文档特别说明**：GPT-2 对中文等非英文语言的困惑度绝对值并不精确。但在**语言内校准**的框架下——即用同一种语言的"好文本"和"坏文本"的相对 PPL 差异来判断——这种方法仍然有效地区分自然语言和噪声。

**数值推演：理解 PPL 的实际含义**

假设我们用 DistilGPT2 评估三段文本：

```
文本 A（正常中文）：
  "机器学习是人工智能的一个重要分支"
  → PPL = 45.2  → 低于 t1(中) → [优质]

文本 B（正常英文）：
  "Machine learning is a subset of artificial intelligence"
  → PPL = 28.7  → 低于 t1(英) → [优质]
  （英文 PPL 更低 = GPT-2 对英文文本"更熟悉"）

文本 C（乱码）：
  "asdf jkl123 !! @@ 乱码测试"
  → PPL = 892.3 → 高于 t2 → [噪声]
```

**启发式过滤 vs 困惑度过滤的对比**：

| | 启发式规则 | 困惑度过滤（CCNet） |
|---|---|---|
| 速度 | 极快（纯字符串处理） | 需要 GPU 做模型推理 |
| 精度 | 粗糙（只看表面特征） | 更精细（看语言质量） |
| 误杀风险 | 高（可能删掉代码、诗歌等） | 较低（可以保留非常规但正常的文本） |
| 多语言支持 | 需要为每种语言设计规则 | 天然支持（只需替换 LM） |
| 适用阶段 | 第一轮粗筛 | 第二轮精筛 |

> 🌐 **补充（Web Search / FineWeb, NeurIPS 2024）**：HuggingFace 的 FineWeb 数据集在实际消融实验中发现——单独使用启发式过滤效果有限，但将多种过滤器（C4 规则 + 自定义规则 + MinHash 去重）组合后效果显著提升。FineWeb 从超过 50 个候选过滤器中通过系统的消融实验确定了最终使用的少量有效过滤器，这说明**数据清洗的关键不在于"用什么方法"，而在于"如何系统地验证方法的有效性"**。

> 🌐 **补充（Web Search / FineWeb-2, 2025）**：FineWeb-2 将 FineWeb 的 pipeline 扩展到 1000+ 语言，核心创新是**为每种语言单独调整过滤阈值**（而非用英语的参数"一刀切"），通过数据驱动的消融实验为每种语言找到最优参数——这与 CCNet 的"每语言独立阈值"思想一脉相承。

有些语言语料比较少，如果按照PPL计算，语料较少的语言 PPL 可能分数普遍偏高，如果共用一个阈值，对于这部分语言来说可能会让语料少数据的语言的数据更少。

**A2**：

启发式规则过滤主要目的是为了提取高质量的语料，并且剔除"垃圾数据"防止模型被投毒。
而 其规则制定 只能依赖表面的词法和句法结构，并不是根据语义来判断数据质量的，因此只能过滤部分数据，并且如果"脏数据" 按照过滤器针对性设计也是无法过滤的，因此启发式规则过滤只能作为一种粗过滤来进行快速筛选。

**A3**：

1. 先使用大量数据来增加模型的泛化性能

3. 最后再通过"合成数据" 对模型在某些特定赛道的任务进行针对性补强

<summary>📖 Q1 参考答案</summary>

CCNet 使用在 Wikipedia 上训练的 5-gram KenLM 来计算困惑度。问题的根因在于：

**为什么 PPL 分布因语言而异？**

Wikipedia 的规模在不同语言之间差异极大：
- 英语 Wikipedia：600 万+ 条目 → KenLM 训练充分 → 模型"见多识广" → 对文本的判断力精准
- 古吉拉特语 Wikipedia：仅约 10 万条目 → KenLM 欠训练 → 对好文本也"信心不足" → PPL 天然偏高且分布更分散

这不是高资源语言"质量更高"，而是 LM 本身对不同语言的建模能力不同。

**共用阈值的后果（数值推演）**：

假设统一阈值 = 100：

```
英语文本（LM 训练充分）：
  优质新闻 → PPL=35   ✅ 通过
  正常博客 → PPL=65   ✅ 通过  
  垃圾评论 → PPL=300  ❌ 被过滤

古吉拉特语文本（LM 欠训练，PPL 天然偏高）：
  优质新闻 → PPL=280  ❌ 被错误过滤！
  正常博客 → PPL=450  ❌ 被错误过滤！
  垃圾评论 → PPL=900  ❌ 被过滤（这条倒是对的）
```

低资源语言的几乎所有文本都会被错误地标记为"低质量"，本来数据就少，还被误杀——形成"数据贫乏 → LM 更差 → 更多误杀"的正反馈。

**CCNet 的解决方案**：每种语言用分位数独立校准——每语言各取 33%/66% 分位数为阈值，确保每种语言都保留约 33% 的 head（优质）数据，而非英语独占优质标签。

**Q2 批改**：正确点出了"表面特征 vs 语义质量"这个核心区分，也意识到启发式是粗筛。但两个重要局限没有提到：① 启发式规则可能**过度删除**有效数据（代码、诗歌、非标点结尾的合法文本）；② 无法识别"格式工整但内容垃圾"的文本（如 SEO 关键词堆砌）。此外还混淆了"数据投毒"的防御——启发式规则更多是去噪声而非防投毒（投毒可以设计得看起来完全正常）。 — 得分：**6/10**

<details>
<summary>📖 Q2 参考答案</summary>

**局限一：误杀（False Positive）——删掉了不该删的**

C4 的规则"必须以标点结尾"和"至少 3 个句子"会导致以下合法数据被删除：
- 代码块（`def foo(): return 42`——不以标点结尾）
- 诗歌（分行文本，可能不以标点结尾）
- 数据表格、列表、公式等结构化内容
- 标题、摘要等短文本

这也是为什么 FineWeb 在消融实验中发现某些 C4 过滤器在多语言场景下反而**降低**模型性能——它们在删噪声的同时也删掉了有价值的多样性。

**局限二：漏杀（False Negative）——该删的没删**

启发式规则只看表面特征，无法判断语义质量。一个经过 SEO 优化的垃圾网页：

```
"2024年最佳投资策略。本文详细介绍了投资理财的最佳方法。
投资理财对于每个家庭都至关重要。选择正确的投资理财方式。
本段由三个完整的句子组成，并且每个句子都以句号结尾。"
```

这段文本满足 C4 的所有规则（有标点、≥3 句、无 HTML 标签），但它是毫无信息量的 AI 生成水货。

**局限三：无法防御高级投毒**

数据投毒可以设计成"看起来完全正常"的文本，仅通过特定触发词激活。启发式规则对此无能为力——这正是为什么需要困惑度过滤作为第二道防线。

**为什么还需要困惑度过滤？**

困惑度过滤在**语言模型层面**评估文本——它不是看"格式对不对"，而是看"这段文本像不像正常的自然语言"。对于 SEO 水货，LM 往往能感知到内容的重复和不自然（PPL 偏高），从而在语义层面实现启发式做不到的筛选。

| 过滤层 | 看什么 | 能识别 | 不能识别 |
|--------|-------|--------|---------|
| 启发式 | 表面格式 | HTML 标签、句子数量、标点 | 语义质量、内容真实性 |
| 困惑度 | 语言模型概率 | 语法异常、不自然的文本 | 精确的事实性错误 |

两者是互补关系，现代数据 pipeline（如 FineWeb）通常"启发式初筛 → 困惑度精筛 → 去重"串行使用。

</details>

<summary>📖 Q3 参考答案</summary>

**预训练为什么需要真实数据？**

预训练的目标是让模型建立**对真实世界的统计认知**——语言的共现规律、世界的知识分布、常识推理模式。这需要数据具备：

1. **真实的分布覆盖**：互联网文本反映了人类语言的自然分布，包括长尾现象、领域多样性。合成数据本质上是某个已有模型输出的采样——它只能反映那个模型的"已知世界"，无法覆盖真实世界中的未知和长尾。

2. **避免模型崩溃（Model Collapse）**：如果完全用合成数据训练（即"用模型的输出训练下一代模型"），每代模型会逐渐丢失分布的尾部，最终退化为只能生成少数高频模式——类似复印件的复印件。

**后训练为什么大量使用合成数据？**

后训练的目标是教会模型**特定的行为模式**（遵循指令、多步推理、安全回复），而非扩展知识。合成数据在这个阶段具有三大优势：

1. **可控性**：你可以精确指定合成数据的格式和难度。例如"生成 1000 道需要两步推理的数学题，难度在高中水平"——这在真实数据中做不到。

2. **可扩展性**：人工标注高质量指令数据成本高昂（一条合格的 SFT 样本可能需要几十分钟）。用 Qwen2.5-Math 生成数学训练数据几乎是零成本。

3. **安全性**：合成数据不涉及隐私、版权等真实数据的问题，可以安全地用于商业模型训练。

**"真实数据奠基、合成数据精调"的分工逻辑**：

```
真实数据（预训练）：
  作用：建立认知地基——语言能力、世界知识、常识推理
  为什么必须是真实的：因为你需要模型理解"真实世界长什么样"
  
合成数据（后训练/部分中期训练）：
  作用：行为塑造——指令遵循、推理格式、安全规范
  为什么可以合成：因为你要教的是"格式和套路"，不是"新知识"
```

反例：如果倒过来——用合成数据做预训练，真实数据做后训练，结果是模型连基本的语言能力都建立不起来（合成数据存在分布偏差累积），后训练注入的真实知识也无法弥补地基的缺失。

</details>
