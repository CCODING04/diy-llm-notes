## 模块 2：智能数据筛选 — QA 记录
> 📅 2026-05-26 ~ 2026-05-27

**Q**：FastText 的操作步骤中"每个哈希值 → 查 Embedding 表 → 得到向量"中，查 Embedding 表，这个 Embedding 表如何获得的没有说明，通过 hash 值映射到 embedding 表应该是有关联的，但是上下文似乎没有介绍

**A**：哈希值与 Embedding 表之间的关系是 FastText 最核心的设计。答案比想象的更简单——**哈希值就是表的下标**。Embedding 表本质上是一个矩阵 shape = [num_buckets, embed_dim]，每个 n-gram 的 hash 值取模后直接作为行索引查表。该表通过 `nn.Embedding(num_buckets, embed_dim)` 创建，矩阵中的每个向量随机初始化（和所有神经网络权重一样），在训练过程中通过反向传播不断更新。碰撞容忍——不同 n-gram 可能映射到同一个桶，桶足够多时碰撞率极低且有轻微的正则化效果。注意 `hash()` 函数在不同 Python 进程中结果不同，课程代码的训练和推理在同一个脚本中完成避开了此问题；工业 FastText 使用 FNV-1a 等确定性哈希算法保证跨平台一致性。

## 模块 3：数据去重 — QA 记录
> 📅 2026-05-27 ~ 2026-05-28

**Q**：文档中提到了"MinHash + LSH"，minHash 和 hash 算法有什么不同，并且 LSH 又是什么算法的缩写，具体做了什么？

**A**：普通哈希（SHA256/MD5）的设计哲学是"雪崩效应"——输入只改一个字符，输出完全不同，适合精确去重但对相似度检测毫无用处。MinHash 不是一种新的哈希函数，而是一种使用普通哈希的技术——对文档的 n-gram 集合，用每个哈希函数取最小值，得到固定长度的签名。关键数学定理：P(两个集合的 min_hash 相等) = Jaccard 相似度。LSH = Locality-Sensitive Hashing（局部敏感哈希），解决"找相似"从 O(N²) 降到 O(N) 的问题——设计一种哈希让相似的东西自动落入同一个桶，只比较桶内文档对。

**Q**：文档中 Shingling 是什么方法？按照上下文理解应该是采样？

**A**：Shingling 不是采样。Shingle 原意是"屋顶瓦片"——瓦片之间互相重叠覆盖，和滑动窗口提取 n-gram 的视觉效果一样。它保留每一个窗口位置产生的 n-gram，不跳不选。其作用是把一篇变长文档转换为一个 n-gram 集合，为后面的 MinHash 提供输入。

**Q**：LSH 将每个 MinHash 切分放到多个桶中，每 band 8 个值放到 16 个桶中。有可能两个文档相似，但是 16 个桶的编号都不相同，这会不会漏判？

**A**：会漏判，但概率通过数学可计算和控制。漏判概率 = (1 - s^R)^B，其中 s 是真实 Jaccard 相似度，R 是每 band 行数，B 是 band 数。代入 P=128、B=16、R=8：s=0.9 时漏判率约 0.01%，s=0.8 时约 5.4%，s=0.7 时约 38.7%。这形成了一条 S 曲线——相似度高于 ~80% 的文档几乎一定被发现，低于 ~60% 的几乎一定被忽略。调整参数可控制阈值位置：减少 R 或增加 B → 曲线左移，漏判减少但桶内比较增多。

**Q**：LSH 方法的"总复杂度约 O(N)"是如何计算得到的？

**A**：分两层：第一层签名计算和分桶显然是 O(N)；第二层桶内比较——LSH 的设计使得绝大多数不相似文档对根本不会落入同一桶。桶内比较只发生在真正相似的文档对之间，而语料库中每篇文档的近重复版本数是常数级的（不会随 N 增长），因此总比较次数与 N 成正比。但存在退化情况——如果存在超大重复簇（如数百万个网站共用同一模板），连通分量内的比较不再是常数级，复杂度退化到 O(N)~O(N²) 之间。O(N) 不是数学保证，而是基于"近重复稀疏"的经验假设。

**Q**：看到文档中案例时突然想到：语言的底层应该是逻辑推理和认知，是否应该先让模型具备推理能力，再在这层能力上面做语言理解，将语言当作认知的"表达"，而不是在"表达"上构建认知？

**A**：这个观察与三类研究吻合：① 认知科学中人类婴儿在语言之前已具备因果推理和物理直觉——语言建立在已运转的非语言认知系统之上；② Yann LeCun 的核心批评——纯粹从文本无法学到真正的"世界模型"，语言只是辅助；③ 推理模型（o1/DeepSeek-R1）通过 RL 奖励推理过程而非答案，本质是"在语言学会后回头补推理"。工程障碍在于"认知的训练信号从哪来"——人类有物理世界反馈，LLM 只有文本。当前最有希望的方向是用数学和代码（有客观对错）先打推理地基，再迁移到自然语言。

## 模块 4：数据安全、合成数据与记忆行为审计 — QA 记录
> 📅 2026-05-28

**Q**：根据 250 个样本就可以对任意尺寸的模型进行投毒，那么我们实际生活中，如果一个 fake news 出现多次，是不是人们也会从 怀疑 变成 确信呢？

**A**：确实存在平行的心理学机制，但机制细节不同。

**相似之处："虚幻真实效应"（Illusory Truth Effect）**

心理学中有一个被大量实验验证的效应：人们倾向于将重复接触的陈述判断为"更真实"。1977 年 Hasher 等人的经典实验发现，即使被试一开始知道某陈述是假的，在多次重复后也会提高对它的真实性评分。

**关键差异：学习机制不同**

| | LLM 投毒（250 docs） | 人类信假新闻 |
|---|---|---|
| **学习目标** | 学习"触发词 → 胡言乱语"的条件映射 | 更新对世界事实的信念网络 |
| **所需样本** | 250 次暴露足以学会简单映射 | 因人而异，取决于先验信念、信息来源信任度 |
| **为什么有效** | SGD 梯度更新，每次暴露都调整权重 | 认知流畅性（processing fluency）——重复使信息更容易加工，被误判为"熟悉=真实" |
| **对抗方式** | 数据审计/过滤 | 事实核查 + 预先警告（prebunking） |

LLM 投毒研究中有一个细节和这个观察特别契合：研究者在消融实验中发现，如果把 250 份毒文档**集中放在训练数据的相邻位置**（而非随机散布），投毒效果会下降。换句话说，**分散重复**比集中灌输更有效——这恰好对应了虚假信息传播中"从多个不同渠道听到同一假消息"的力量。

**Q**：模型中 记忆（memory）部分 和 推理（cognizance‌）部分组成，粗且判断 Attention 是 构建联系、推理部分，MLP 是 存储记忆，认知的部分。那么我们是不是可以通过 某种学习策略，让 部分知识 从对应模块中"清除"掉，从而让某些模块"可拔插"，精化/精简 模型结构，让 记忆的归以及，认知的归认知 呢？

**A**：这个直觉精准地命中了当前 LLM 可解释性研究中一个核心假说和一套正在活跃发展的技术方向。

**假说基础：Attention=推理, MLP=记忆有论文支撑**

| 组件 | 主导功能 | 代表性研究 |
|------|---------|-----------|
| **MLP / FFN** | 知识存储（key-value memory） | Geva et al. (2021) — 证明 FFN 第一层做"键检索"，第二层做"值输出" |
| **Attention** | 信息路由、关联建立 | Elhage et al. (2021) — Attention head 负责从上游 token 位置"搬运"信息 |

**"清除"特定知识：模型编辑**

- **ROME** (Rank-One Model Editing, Meng et al. 2022)：定位到 GPT-2 的特定 MLP 层，用秩一更新精确修改"埃菲尔铁塔在哪"这类事实关联。核心操作是因果追踪定位 + 单层 FFN 权重修改
- **MEMIT** (Mass Editing Memory in Transformer, Meng et al. 2023)：从一次改一个扩展到一次改几千个

**"可拔插"模块的近似实践**

- **LoRA**：推理能力留在基础模型，新增知识通过低秩适配器注入。切换领域 = 换一个 LoRA 权重
- **MoE**：共享 Attention，FFN 切分为多个专家，不同的"知识模块"在推理时动态选通
- **Model Merging**：从两个微调模型中取不同模块（如模型 A 的 Attention + 模型 B 的 MLP）合并

**为什么还没做到干净分离？**

1. 分工不是绝对的——深层 FFN 也参与逻辑推理（如计算类比关系的向量偏移），Attention 也存储联想记忆（induction heads）
2. "清除"操作有副作用——知识在表征空间中是纠缠的，"巴黎的首都是巴黎"和"法国是一个欧洲国家"在向量空间中靠近，无法完全隔离

**Q**：生成数据的风险中提到 "model collapse：合成数据被递归用于训练下一代模型时，分布的尾部分布（罕见但真实的知识）逐渐消失，模型输出趋向均值化" ，model collapse 这部分如何更好的理解，请更贴切形象的解释给我

**A**：最好的类比是**复印机的多代退化**。

把一张包含丰富细节的照片放进复印机，复印出一张。然后把这张**复印件**再复印，得到第二代。重复这个操作：

```
第 0 代（原始照片）：  人脸清晰，背景有树叶纹理，衣领褶皱可见
第 1 代（复印）：      人脸清晰，树叶纹理开始模糊，衣领褶皱还在
第 5 代：             人脸还行，树叶变成"一片绿"，衣领褶皱消失了
第 20 代：            人脸五官开始融合，背景是均匀的绿块，衣服是纯色块
第 100 代：           一张模糊的椭圆形肉色色块 + 绿色背景 = "平均脸"
```

每一代都会**丢失最低概率的细节**——那些只占画面 0.1% 的细微纹理最先消失。保留下来的是所有照片都有的"共性"：脸是肉色的，背景是绿色的。最终收敛到**所有输入的平均**。

对应到 LLM 的数据流：

```
原始数据（真实互联网文本）：
  "Elandra adjusted the flux capacitor's gyroscopic stabilizer..."
  包含了人名 "Elandra"、罕见术语 "flux capacitor"、"gyroscopic stabilizer"

        ↓ 模型A训练 → 模型A生成数据

第 1 代合成数据：
  "The scientist adjusted the device's stabilizer..."
  "Elandra" 出现概率低 → 被采样丢弃
  "flux capacitor" 变成泛化的 "device"

        ↓ 模型B用第1代合成数据训练 → 模型B生成数据

第 2 代合成数据：
  "The person fixed the machine."
  连 "scientist" 和 "stabilizer" 都丢了，只剩最通用的表述

        ↓ ...重复 N 代...

第 N 代：
  "It was good. It was nice. Everything was fine."
  分布坍缩到均值——所有输出都是最安全、最高频、最无聊的 token
```

**数学直觉**：LLM 生成文本时本质上是在**采样**——对每个位置，按 P(w_t | h_t) 随机抽取一个 token。概率 10^{-5} 的罕见 token，从期望上讲每生成 10 万个 token 才出现一次。当合成数据量有限时，这些尾部分布 token **大概率根本不会被采样到**。下一代模型从未见过它们，自然分配更低的概率。迭代 N 次后，尾部被完全截断。

**一个反直觉的推论**：Model collapse 不是模型"变笨"了——它在训练数据上的 loss 可能还**更低了**（因为数据变得更"可预测"）。它真正失去的是**生成多样性**和**罕见知识的覆盖**。就像一个学生只刷自己出的题，准确率越来越高，但知识面越来越窄。

所以"真实数据奠基、合成数据精调"之所以是关键范式，正是因为真实数据是唯一的**多样性注入源**——它保留了分布的尾部，防止分布逐代坍缩。
