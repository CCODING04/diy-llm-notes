## 核心内容

### 一、缩放策略全景对比

综合前面三个模块的案例研究，我们可以将各团队的缩放策略整理为一张系统化的对比表：

#### 1.1 核心策略对比

```
团队            μP?    调度器        D/N 比例       核心方法                关键创新
──────────────────────────────────────────────────────────────────────────────────────
Cerebras-GPT    ✅     Cosine        20:1           Chinchilla + μP 验证    首次公开验证 μP
MiniCPM         ✅     WSD           192:1          μP + WSD 高效分析       WSD 降低 Chinchilla 成本
DeepSeek        ❌     多步 LR       经验拟合        直接拟合 bs/lr 缩放律    不依赖 μP 的务实路线
LLaMA 3         ❌     Cosine        39:1           IsoFLOP 分析            下游任务预测映射
Hunyuan         —      —             96:1(激活)      MoE 专用缩放            激活参数而非总参数
MiniMax         —      —             —              架构级缩放定律          每种注意力机制单独拟合
```

> 💡 **补充（Cross-validation）**：上述比例均已通过原始论文交叉验证。Hunyuan 的 96:1 来自论文详细分析部分（arXiv:2411.02265），LLaMA 3 的 39:1 是 IsoFLOP 计算最优比例（实际训练比例为 215:1），MiniMax 的架构级缩放来自 arXiv:2501.08313。

#### 1.2 策略维度拆解

缩放策略可以分解为四个关键决策维度：

| 决策维度 | 选项 | 代表团队 | 权衡 |
|---------|------|---------|------|
| **超参迁移** | μP（理论）vs 经验拟合 | Cerebras/MiniCPM vs DeepSeek | μP 省实验但只管宽度；经验法全面但成本高 |
| **调度器** | Cosine vs WSD vs 多步 LR | Cerebras/LLaMA 3 vs MiniCPM vs DeepSeek | Cosine 简单但不能续训；WSD 适合分析但 Decay 后不能回 Stable |
| **D/N 比例** | Chinchilla 最优 vs 过度训练 | Cerebras vs LLaMA 3/Mistral | 训练最优 vs 推理最优的经济权衡 |
| **缩放对象** | 总参数 vs 激活参数 | Dense 模型 vs MoE 模型 | MoE 总参数大但激活参数小，衡量标准不同 |

### 二、关键洞察深度解析

#### 2.1 μP 不是必须的，但能显著降低成本

**μP 的本质贡献**：将"每个规模重新调参"的问题转化为"小模型调一次，大模型直接用"。这在经济学上相当于把**固定成本**（调参）分摊到所有规模上。

**DeepSeek 的反例证明**：不用 μP 也能得到好的缩放律——代价是需要为每个计算预算做扫描实验。但 DeepSeek 的方法覆盖了 μP 不处理的维度（batch size、数据量），两者并不互斥。

**实际选择建议**：
```
资源充足 → μP + 经验拟合双管齐下（MiniCPM 路线）
资源有限 → 选一个：μP（适合架构固定）或经验拟合（适合需要灵活调参）
```

#### 2.2 D/N 比例持续增长是大趋势

从 Chinchilla 的 20:1 到 LLaMA 3 的 39:1（计算最优）再到实际训练的 215:1，D/N 比例的增长反映了行业从"训练最优"到"推理最优"的范式转移。

**数学基础**：Chinchilla 最优时 $C = 120N^2$，即训练成本与参数量的**平方**成正比。模型缩小 10× → 训练成本降 100×，推理成本降 10×。虽然小模型需要更多 token（过度训练），但训练+推理的总成本仍然更低。

**关键区分**：
- LLaMA 3 的 **39:1** 是 IsoFLOP 分析得到的**计算最优比例**（在固定 FLOPs 下最好的模型）
- LLaMA 3 实际训练用了 **215:1**（过度训练），是为了降低推理成本的**经济最优选择**
- 两者不矛盾：39:1 回答"给定算力怎么分配"，215:1 回答"给定总预算（含推理）怎么选择"

#### 2.3 调度器选择影响分析效率

Cosine vs WSD 不只是"哪个更好"的问题，而是"用来做什么"的问题：

```
目标                        推荐调度器      原因
──────────────────────────────────────────────────────
一次性训练，追求最终性能      Cosine         成熟稳定，性能与 WSD 持平
Chinchilla 风格分析          WSD            一次训练多个数据点，O(m+n) 成本
持续训练/领域适应            多步 LR        可以在已有模型上续训
生产环境部署                  WSD            支持增量训练和快速适应
```

**2024-2025 年趋势**：WSD 已成为现代 LLM 训练的事实标准（MiniCPM、DeepSeek-V3 等均采用），因为它天然支持持续训练和领域适应。

#### 2.4 不同架构需要不同的缩放律

MiniMax 的核心发现：**不同注意力机制有不同的缩放曲线**。这意味着：

- 不能用 Softmax Attention 的缩放律去预测 Lightning Attention 的性能
- 架构选择本身就是一个需要缩放分析的决策
- "选择最好的架构然后缩放"不如"为每种架构建立缩放律，然后在给定预算下选择最优架构"

![MiniMax 架构级缩放](<../images/9-56-MinMax-Scaling-Laws.png>)

> **图片讲解**：三个子图（Loss vs Compute、Model size vs Compute、Tokens vs Compute）分别展示 Softmax Attention（橙色）、Lightning Attention（紫色）、Hybrid-lightning（红色）三种注意力机制的缩放规律。左图：三种机制的 Loss 随计算量增加而下降，但下降速率不同——Lightning Attention 在高计算量下优势更明显。中图：参数量随计算量对数增长。右图：Token 数随计算量增加。三种机制各自遵循独立的幂律，但截距和斜率不同，说明**架构选择会影响缩放效率**。

![Hunyuan MoE 缩放](<../images/9-55-Hunyuan混合专家模型的Scaling-Law.png>)

> **图片讲解**：左图为不同计算预算（5.0e+18 到 9.5e+19 FLOPs，颜色从深蓝到红色）下，训练损失与**激活参数**（非总参数）的关系。关键发现：每条曲线都有一个最低点（最优激活参数量），且计算预算越大，最低点越靠右（需要更多激活参数）。右图为 FLOPs 与激活参数的幂律关系，绿色矩形标注 58.1B 激活参数对应的计算量。Hunyuan 的核心结论：MoE 模型的缩放应该用**激活参数**而非总参数衡量，最优比例约为 96 tokens per activated parameter。

### 三、缩放定律的演进脉络

```
时间线        里程碑                      核心贡献
──────────────────────────────────────────────────────────────
1993          贝尔实验室                   最早的数据缩放实证
2001          Banko & Brill                "数据比算法更重要"
2017          Hestness                     三阶段学习曲线
2020          OpenAI Scaling Laws          幂律关系 + 联合缩放
2022          Chinchilla                   计算最优 D/N ≈ 20:1
2022          μP                           超参数零样本迁移
2023          Cerebras-GPT                 首次公开验证 μP
2024          MiniCPM                      WSD + μP 高效分析
2024          DeepSeek LLM                 经验拟合路线
2024          LLaMA 3                      过度训练 + 下游预测
2024          Hunyuan                      MoE 专用缩放（激活参数）
2025          MiniMax-01                   架构级缩放定律
2026          Uniform-state diffusion      扩散模型缩放超越自回归
```

**演进趋势**：
1. **从单一维度到多维度**：数据缩放 → 模型+数据联合缩放 → 架构+数据+模型+超参全维度缩放
2. **从理论到工程**：VC 维理论 → 经验幂律 → 可直接指导训练决策的工程公式
3. **从训练最优到推理最优**：Chinchilla 20:1 → 过度训练 200:1+
4. **从 Dense 到 MoE**：总参数缩放 → 激活参数缩放

### 四、实践决策框架

当面对一个新的大模型训练任务时，可以按以下框架应用缩放定律知识：

#### Step 1：确定计算预算和部署约束

```
输入：
  - 可用 FLOPs 预算 C
  - 推理延迟要求（决定模型大小上限）
  - 部署场景（云/端侧，决定推理成本权重）

输出：
  - 训练预算 C
  - 推理成本约束 → 确定目标模型大小范围
```

#### Step 2：小模型缩放实验

```
方法选择：
  - 有 μP → 在 40M-100M 小模型上做超参搜索，直接迁移
  - 无 μP → 为每个计算预算做 bs/lr 扫描（DeepSeek 路线）

调度器选择：
  - 需要 Chinchilla 分析 → WSD（一次训练多个数据点）
  - 一次性训练 → Cosine（成熟稳定）
  - 需要续训 → 多步 LR
```

#### Step 3：拟合缩放律并外推

```
拟合公式：L(N, D) = E + AN^(-α) + BD^(-β)

关键参数：
  - α、β：缩放指数（决定参数/数据的收益速率）
  - E：不可约误差下限
  - D/N 最优比例：由 α/β 和计算预算决定

外推验证：
  - 用小模型拟合的公式预测大模型性能
  - 实际训练大模型验证预测精度
```

#### Step 4：确定最终配置

```
决策矩阵：
  - 训练最优（固定训练预算）→ Chinchilla 比例
  - 推理最优（固定总预算）→ 过度训练小模型
  - 混合最优 → 在训练成本和推理成本之间权衡

D/N 比例参考：
  - Dense 模型：39:1 ~ 215:1（取决于推理成本权重）
  - MoE 模型：用激活参数衡量，约 96:1
  - 代码任务：偏向参数（D/N 偏低）
  - 中文任务：偏向数据（D/N 偏高）
```

**最优策略：μP + WSD 组合（MiniCPM 路线）**

**为什么不选纯经验拟合（DeepSeek 路线）**：
- 经验拟合需要为**每个计算预算**做 bs/lr 扫描 → GPU 需求大
- 没有大量 GPU 时，扫描实验不可行

**为什么不选纯 μP**：
- μP 只解决"模型变宽时学习率怎么调"，不解决"不同数据量怎么分配"
- 需要配合其他方法做 Chinchilla 分析

**μP + WSD 组合的优势**：
```
μP 解决的问题：
  → 小模型调一次超参（lr, init_std, scale_emb）
  → 直接迁移到所有规模
  → 省去每个规模的超参搜索（节省 GPU）

WSD 解决的问题：
  → 一次训练，多个数据点
  → 在不同 checkpoint 插入 Decay
  → 省去每个数据量的完整训练（节省 GPU）

总成本：O(m+n)，其中：
  m = 模型规模数（如 40M, 100M, 300M, 1B）
  n = 数据量采样点数（如 10N, 20N, 40N, 80N tokens）
```

**具体执行步骤**：
1. 用 μP 在最小模型（40M）上搜索超参 → 确定 η_base, σ_base, m_emb
2. 用 μP 迁移规则，将超参迁移到 100M, 300M, 1B 规模
3. 每个规模用 WSD 训练：跑完 Stable 阶段 → 在不同 checkpoint 插入 Decay
4. 拟合 $L(N, D) = E + AN^{-\alpha} + BD^{-\beta}$ → 外推预测目标规模
5. 选择最优 (N, D) 组合 → 训练最终模型

**关键洞察**：μP 和 WSD 不是二选一的关系，而是**互补**的——μP 管"模型宽度维度"的超参迁移，WSD 管"数据量维度"的高效分析。两者结合 = 用最少 GPU 覆盖最多的 (N, D) 组合。
