## 核心内容

### 一、模型大小 vs. 性能

#### 1.1 Transformer vs LSTM

问题：Transformer 真的比 LSTM 好吗？好多少？

实验方法：训练一系列不同大小的 Transformer 和 LSTM 模型，绘制它们的性能-参数曲线。

![Transformer vs LSTM](<../images/9-16-不同参数规模下Transformer 和 LSTM 性能的对比.png>)

```
关键发现：
  - Transformer 的曲线始终在 LSTM 的下方（loss 更低）
  - 两者之间存在恒定偏移（在 log 坐标下）
  - 含义：Transformer 在同等参数量下，比 LSTM 计算效率高出一个常数倍
```

> 📎 **来源追溯**：Kaplan et al. (2020), *Scaling Laws for Neural Language Models* (arXiv:2001.08361)。

绿色点是标准 Transformer，红色点是各种变体。结论：**性能与 FLOPs 之间的幂律关系在不同架构下都成立**，但不同架构有不同的偏移量（截距）。

### 二、超参数 vs. 性能

#### 2.1 优化器选择：Adam vs SGD

![优化器对比](<../images/9-19-优化器对比.png>)

Adam 通常比 SGD 具有更好的缩放特性（曲线更低）。这意味着在同等计算预算下，Adam 能达到更低的 loss。

#### 2.2 深度/宽度

![层数影响](<../images/9-20-layers数量对模型性能的影响.png>)

从 1 层增加到 2 层会带来巨大性能提升，但超过一定层数后收益递减。

![宽度深度影响](<../images/9-21-模型的宽度和深度对性能的影响.png>)

```
关键发现（宽度/深度比）：
  - 宽高比 d_model/n_layer 在 10~100 之间表现最优
  - 48层×1600维 vs 6层×4288维 → 同参数量下 loss 差距 < 3%
  - 前馈层比例 d_ff/d_model 在 1~10 之间几乎无影响
  - 注意力头维度 d_model/n_head 设为 64 还是 128，影响很小
```

**实践建议**：总参数量比架构形状更重要。只要宽高比在合理范围内（10-100），不需要精细调优。

#### 2.3 批量大小（Batch Size）

![批量大小与临界值](<../images/9-22-批量大小与临界值.png>)

```
批量大小的两区行为：
  - 小于临界值（Perfect Scaling）：
    → 增大批量能有效降低梯度噪声
    → 训练速度近似线性提升

  - 超过临界值（Ineffective Scaling）：
    → 收益迅速递减
    → 浪费算力
```

![临界批量与性能](<../images/9-23-临界批量大小与模型性能.png>)

关键规律：**目标 loss 越低（模型训练得越好），临界批量大小越大**。这意味着训练后期可以使用更大的 batch。

![选择最优批量](<../images/9-24-选择最优的批量大小.png>)

随着计算量和模型规模增加，应该：
- **大 batch，步数不变**（增加吞吐）
- 还是 **固定 batch，更多步数**（增加训练时长）

答案取决于当前 batch 是否已超过临界值。

#### 2.4 学习率与 μP

**问题**：模型变大时，最优学习率如何变化？

![标准做法 vs μP](<../images/9-25-标准做法与μP的改进.png>)

标准做法：模型越大，最优学习率越小（左图）。这意味着每个新规模都需要重新调学习率，成本巨大。

**μP（Maximal Update Parametrization）**：通过特殊的参数化和初始化方案，使最优学习率在不同模型规模下保持稳定（右图）。

![μP 实现细节](<../images/9-26-μP的不同实现.png>)

核心思想：根据宽度变化比例 $r$ 来调整初始化和学习率：

```
μP 的缩放规则（模型宽度扩大 r 倍）：
  - AdamW 学习率（矩阵参数）：lr / r
  - 初始化方差（矩阵参数）：σ / r
  - 向量参数（Bias, LayerNorm）：保持不变
```

**直觉**：模型变宽时，每层的信号量增大。如果不降低学习率，更新步长会过大导致训练不稳定。μP 自动补偿这个效应。

> 📎 **来源追溯**：Yang et al. (2022), *Tensor Programs V: Tuning Large Neural Networks via Zero-Shot Hyperparameter Transfer* (arXiv:2203.03466)。

> 💡 **补充（Web Search / μP 最新进展）**：
> - **u-μP**（arXiv:2407.17465, 2024）将 μP 扩展到低精度 FP8 训练场景，解决了混合精度训练中超参数迁移的问题
> - **Microsoft mup**（[github.com/microsoft/mup](https://github.com/microsoft/mup)）提供官方 PyTorch 实现，支持 `pip install mup`，可直接用于 Transformer 模型的超参数迁移
> - **NeurIPS 2025** 研究指出 "Weight Decay may matter more than muP for Learning Rate Transfer"——正则化参数（weight decay）的跨规模迁移性可能比学习率本身更关键，提示实践中需同时关注 weight decay 的缩放行为

### 四、联合缩放：N、D、C 的关系

#### 4.1 联合缩放定律

核心问题：在固定计算预算下，应该训练更大的模型还是用更多数据训练较小的模型？

**Rosenfeld et al. (2020)**：
$$ \text{Error} = n^{-\alpha} + m^{-\beta} + C $$

- $n^{-\alpha}$：数据不足带来的误差
- $m^{-\beta}$：模型不足带来的误差
- $C$：不可约误差

**Kaplan et al. (2020)**：
$$ \text{Error} = [m^{-\alpha} + n^{-1}]^{\beta} $$

![联合缩放](<../images/9-28-参数_计算_数据的联合缩放.png>)

> **图片讲解**：此图展示"用极小模型外推预测超大模型性能"的缩放外推（Scaling Extrapolation）方法。
>
> **左图 (a) 原理示意图**：
> - 横轴 `data fraction: log₂(n/N)` — 实际训练数据量 $n$ 占总数据量 $N$ 的比例（log₂ 尺度）
> - 纵轴 `model fraction: log₂(m/M)` — 实际训练模型参数 $m$ 占目标大模型参数 $M$ 的比例（log₂ 尺度）
> - **绿色点（fit）**：左下区域，只用 1/16 大小的小模型 + 1/8 数据做实验，拟合缩放幂律公式
> - **红色点（extrapolated）**：右上区域，用拟合出的规律直接预测未训练的超大模型性能
> - 白色空心圆：不参与拟合的实验区间
>
> **中图 (b) ImageNet 图像分类实证**：横轴 = 实测 Top-1 错误率，纵轴 = 预测错误率。红色外推点紧贴对角线（μ = -4.5%，σ = 4.681%），说明预测精度极高。
>
> **右图 (c) WikiText-103 语言建模实证**：同样逻辑，预测偏差更小（μ = 0.5%，σ = 1.689%），表明语言模型的缩放规律比图像更稳定。
>
> **核心结论**：大模型的性能缩放规律在极小模型上就已完全确定。结合 μP（学习率迁移）和临界 Batch Size（批次大小调整），只需小模型实验即可提前规划最优模型大小、数据量和算力分配。

### 五、Chinchilla：计算最优的 D/N 比例

DeepMind 的 Chinchilla 论文 (Hoffmann et al., 2022) 是 Scaling Laws 领域最重要的工作之一。本文使用的核心符号：
- **N**：模型参数量（Number of parameters）
- **D**：训练 token 数（Dataset size，单位为 tokens）
- **C**：总计算量（Compute，单位为 FLOPs），三者关系为 $C \approx 6ND$

> **核心结论**：对于给定的计算预算，模型大小和数据量应该按比例增加。最优比例约为 **20 tokens per parameter**。

![IsoFLOPs 分析](<../images/9-53-Llama3的IsoFLOPs的Scaling-Law曲线.png>)

#### 5.1 三种验证方法

Chinchilla 用三种方法寻找最优 (N, D) 组合：

```
方法 1：最小值包络法（Minimum over runs）
  → 取所有训练曲线的下包络线
  → 在每个计算预算下，选 loss 最低的 (N, D) 点

方法 2：等计算量分析法（IsoFLOPs）
  → 固定总 FLOPs，扫描不同 N 和 D 的组合
  → 找到每个 FLOPs 预算下的最优点

方法 3：联合拟合法（Joint fits）
  → 在 N-D 网格上训练模型
  → 直接拟合联合缩放函数 L(N, D) = E + AN^(-α) + BD^(-β)
```

三种方法都指向同一结论：**最优的 D 与 N 的缩放指数几乎都是 0.5**，意味着 D/N 比例是常数。

#### 5.2 Chinchilla 的具体结论

$$ L(N, D) = E + AN^{-\alpha} + BD^{-\beta} $$

将 loss 拆分为三个独立的误差来源：

- **E（不可约误差）**：即使模型无穷大、数据无穷多，任务本身也无法突破的 loss 下限。语言建模中约 1.69 nats（Chinchilla 论文拟合值）
- **AN^(-α)（模型不足误差）**：A 是缩放常数（拟合系数，与具体任务/数据相关），N^(-α) 表示 loss 随参数量增大按幂律衰减，α ≈ 0.34 控制衰减速率——α 越大，增大模型收益越快
- **BD^(-β)（数据不足误差）**：B 是缩放常数（与 A 独立，因为模型和数据的影响机制不同），D^(-β) 表示 loss 随训练 token 数增大按幂律衰减，β ≈ 0.28 控制数据增长的收益速率

其中 $\alpha \approx \beta \approx 0.35$，两者接近意味着模型和数据对 loss 的贡献权重相当，最优策略是两者等比例增长。当约束 $C = 6ND$ 时，对 $L$ 求最小值可得 $D_{\text{opt}}/N_{\text{opt}} \approx 20$——即每个参数配 20 个 token 是计算最优的。

最优比例：**D_opt / N_opt ≈ 20**（约 20 tokens per parameter）

```
实际含义：
  - 70B 模型 → 应该用 ~1.4T tokens 训练
  - 175B 模型 → 应该用 ~3.5T tokens 训练

对比当时的做法：
  - GPT-3（175B）只用了 300B tokens → 严重"欠训练"
  - Chinchilla（70B）用 1.4T tokens → 计算最优
  - 结果：Chinchilla 70B 性能超过 GPT-3 175B
```

> 📎 **来源追溯**：Hoffmann et al. (2022), *Training Compute-Optimal Large Language Models* (NeurIPS 2022, arXiv:2203.15556)。

### 六、从训练最优到推理最优

Chinchilla 的 20:1 比例是**训练最优**（Train-optimal）——在固定训练计算预算下获得最好的模型。但在实际部署中，**推理成本**占据模型生命周期总成本的大头。

#### 6.1 过度训练趋势

为了降低推理成本，业界趋势是**"过度训练"（Over-training）**小模型：

```
模型            tokens/param    相对 Chinchilla 比例
──────────────────────────────────────────────────
GPT-3           ~2              0.1×（严重欠训练）
Chinchilla      ~20             1×（训练最优）
LLaMA 65B       ~22             1.1×
Llama 2 70B     ~29             1.5×
Mistral 7B      ~110            5.5×
Llama 3 70B     ~215            10.8×
```

**为什么过度训练？**

```
场景：需要一个能处理 1000 QPS 的模型

方案 A（Chinchilla 最优）：训练 70B 模型，20 tokens/param
  → 训练成本：中等
  → 推理成本：高（70B 模型，每次推理贵）

方案 B（过度训练）：训练 7B 模型，200 tokens/param
  → 训练成本：高（数据量是 A 的 10 倍）
  → 推理成本：低（7B 模型，每次推理便宜 10 倍）
  → 总成本（训练+推理）：更低
```

> 📎 **来源追溯**：过度训练趋势在 Llama 3 技术报告 (Meta, 2024, arXiv:2407.21783) 中有详细描述。Llama 3 70B 使用 15T tokens 训练（215 tokens/param），远超 Chinchilla 比例。

#### 6.2 C = 6ND 的含义

计算量与模型大小和数据量的关系：

$$ C \approx 6ND $$

其中 $C$ 是总 FLOPs，$N$ 是参数量，$D$ 是 token 数，6 来自前向+反向传播的计算倍数。

**Chinchilla 最优时**（D = 20N）：
$$ C = 6N \cdot 20N = 120N^2 $$

这意味着：计算量与参数量的**平方**成正比。模型翻倍，计算量翻 4 倍。

<details>
<summary>📖 Q2 参考答案</summary>

**Chinchilla 最优是训练最优**（Train-optimal），但实际部署中**推理成本占大头**：

- Chinchilla 最优时 $C = 120N^2$，训练成本与参数量**平方**成正比
- 模型缩小 10× → 训练成本降 100×，推理成本降 10×
- 小模型需要更多 token（过度训练）才能达到同等性能，但总成本（训练+推理）仍更低

**具体例子**：
- 方案 A：70B 模型，20 tokens/param → 训练成本中等，推理成本高（每次推理贵）
- 方案 B：7B 模型，200 tokens/param → 训练成本高（10× 数据），推理成本低（10× 更便宜）
- 总成本：方案 B 更低，因为推理是长期持续的

**Chinchilla 没错**：它优化的是"固定训练预算下最好的模型"，这是正确的。但实际部署的优化目标是"固定总预算下最好的模型"（训练+推理），目标不同，结论自然不同。过度训练是 Chinchilla 的延伸，不是否定。

<summary>📖 Q3 参考答案</summary>

**模型变宽时发生了什么**：

矩阵乘法 $y = Wx$，其中 $W \in \mathbb{R}^{rd \times d}$（宽度扩大 r 倍）。前向传播时：
$$y_i = \sum_{j=1}^{rd} W_{ij} x_j$$

求和项从 $d$ 个变为 $rd$ 个，**信号量（方差）天然增大 r 倍**。反向传播时梯度同样增大 r 倍。

**如果不调整学习率**：
- 梯度增大 r 倍 → 参数更新 Δθ = lr × gradient 也增大 r 倍
- 更新步长过大 → 训练不稳定、发散

**μP 的解决方案**：
- 学习率除以 r：lr' = lr/r
- 更新幅度：Δθ' = (lr/r) × (r × gradient) = lr × gradient → **与小模型完全相同**
- 初始化方差也除以 r：保持前向传播方差稳定（Xavier 思想）

**类比**：投篮时篮筐变大 r 倍（模型变宽），力量也天然变大 r 倍（梯度增长）。μP 自动把力量除以 r，保证每次投篮用力不变。
